I2. **A missing `report.tap` aborts the step before the support bundle runs** — `.github/workflows/bats.yaml:498` [Claude Opus 5]

```yaml
        cp "bats/report.tap" logs
```

The `bats/logs` copy two lines above is guarded by `[ -d "bats/logs" ]`; this one is not. Actions runs a `shell: bash` step as `bash --noprofile --norc -eo pipefail`, so a missing `report.tap` ends the step and `collect-logs.sh` at line 504 never runs. That is exactly the case the new script exists for: `bats.yaml:390-397` documents the suite dying "before its first test" when the WSL interop handler is gone, and no `report.tap` is written then. The upload step still runs with `if-no-files-found: error`, so the job fails on a missing directory instead of reporting the real cause.

```bash repro
# Save as probe-consolidate.sh; run: bash probe-consolidate.sh
# Emulates the "Consolidate logs" step of .github/workflows/bats.yaml.
# GitHub runs a `shell: bash` step as `bash --noprofile --norc -eo pipefail {0}`.

step() { # $1 = "with-report" | "without-report"
    local dir
    dir=$(mktemp -d)
    mkdir -p "$dir/bats/logs" "$dir/logs"
    [[ $1 == with-report ]] && echo "1..1" >"$dir/bats/report.tap"

    ( cd "$dir" && bash --noprofile --norc -eo pipefail -c '
        if [ -d "bats/logs" ]; then cp -R "bats/logs/" logs; fi
        cp "bats/report.tap" logs
        echo "REACHED collect-logs.sh"
    ' ) 2>&1 | sed "s/^/  [$1] /"
    echo "  [$1] step exit status: ${PIPESTATUS[0]}"
    rm -rf "$dir"
}

step with-report
step without-report
```

## Suggestions

S1. **A bare `return` propagates a failed `command -v` under `errexit`** — `bats/tests/helpers/utils.bash:420` [Claude Opus 5]

```bash
    else
        return
    fi
```

`load.bash:1` sets `errexit`. A bare `return` inherits the status of the last command, here the failed `command -v lsof`, so `capture_host_sockets` returns 1, `capture_logs` aborts before `capture_kubernetes_state`, and `teardown` never reaches `take_screenshot`. Reaching it needs a host with neither `ss` nor `lsof` and `RD_USE_WINDOWS_EXE=false`, which CI does not produce, so this is latent.

```bash repro
# Save as probe-return.sh; run: bash probe-return.sh
make_capture() { # $1 = "return" (current code) | "return 0" (proposed fix)
    eval "capture_host_sockets() {
        if false; then
            set -- netstat.exe -ano
        elif command -v ss__absent >/dev/null; then
            set -- ss --tcp --udp --processes --numeric
        elif command -v lsof__absent >/dev/null; then
            set -- lsof -i -P
        else
            $1
        fi
        printf 'would run: %s\n' \"\$*\"
    }"
}

capture_logs() {
    capture_host_sockets
    echo "  capture_kubernetes_state REACHED"
}

for variant in "return" "return 0"; do
    echo "with '$variant':"
    make_capture "$variant"
    ( set -o errexit; capture_logs; echo "  teardown continued" )
    echo "  capture_logs exit status: $?"
done
```

```text repro-output
$ bash probe-return.sh
with 'return':
  capture_logs exit status: 1
with 'return 0':
  capture_kubernetes_state REACHED
  teardown continued
  capture_logs exit status: 0
```

Fix: `return 0`.

S2. **The firewall test's success assertions cannot fail** — `bats/tests/containers/published-udp-ports.bats:33` [Claude Opus 5]

```bash
    assert_success
```

`powershell_output` at line 17 ends with `2>&1 || :`, folding stderr into stdout and discarding the status, so `assert_success` always holds and `assert_output` at line 35 is satisfied by an error string such as "No MSFT_NetFirewallRule objects found". If the exception vanished entirely the test would still pass.

S3. **An unguarded `Set-Service` can abort the job before any test runs** — `.github/actions/disable-compat-telemetry/action.yaml:39` [Claude Opus 5]

```powershell
      Set-Service DiagTrack -StartupType Disabled -Status Stopped
```

Actions prepends `$ErrorActionPreference = 'stop'` to `pwsh` steps, which `bats.yaml:276-280` states explicitly, so a missing or locked DiagTrack on a future runner image throws. The two neighbouring calls in the same action already pass `-ErrorAction SilentlyContinue`, and every other Windows diagnostic step in the workflow (`bats.yaml:339,347,355,468,476`) sets `continue-on-error: true`. The caller at `bats.yaml:285-287` sets neither.

Fix: add `-ErrorAction SilentlyContinue`, or `continue-on-error: true` on the calling step.

S4. **The new job timeout skips the log collection it was sized to protect** — `.github/workflows/bats.yaml:492` [orchestrator]

```yaml
      if: ${{ !cancelled() }}
```

The branch adds `timeout-minutes: 150` at the job level. A job that hits its own cap is cancelled, so `!cancelled()` steps are skipped while `if: always()` steps still run — which is why the sampler stop steps at lines 463 and 471 use `always()`. The commit body for `213889f33` reasons about this and picks 150 against the step's 120 so the step fails first, which holds for a hung test. It does not hold when a wedged setup or install step consumes the extra 30 minutes: collection and upload are then both skipped.

Fix: switch lines 492 and 519 to `always()`, matching the sampler steps.

*Unproven:* the cancellation semantics are GitHub's, documented for `timeout-minutes` ("automatically cancels it") and for `always()`; no local test reaches them.

S5. **`assert_traefik_charts_are_gone` drops the sanity check its sibling carries** — `bats/tests/k8s/traefik.bats:47` [Claude Opus 5]

```bash
    charts=$(jq_output 'map(select(.metadata.name | contains("traefik")))')
```

`assert_traefik_pods_are_down` at lines 17-20 first asserts the query returned at least one item before concluding from an empty filter. The new function has no equivalent. `jq length` on empty input exits 0 and prints nothing, so `count` is empty and `[[ "" -gt 0 ]]` is false: a `kubectl` call that succeeds with no output is indistinguishable from "no traefik charts". `assert_success` catches a failed call but not an empty one.

Fix: assert the raw output is non-empty JSON before filtering, mirroring the sibling.

S6. **The typeperf artifact keeps a per-sample summary and the raw TSV** — `.github/actions/windows-typeperf-sampler/action.yaml:30` [Claude Opus 5]

## Design Observations

### Concerns

- **`--scale` is opt-in, so the default stays wrong for slow machines (in-scope).** Every new wait must remember the flag, and I1 is the first cost of that. Scaling by default with an explicit opt-out for the loops the docstring calls "expected to run out" would make the safe choice automatic; those loops appear to be few. [Claude Opus 5]
- **Per-file splitting multiplies fixed setup cost on the slowest runners (future).** Adding `containers` to `SPLIT_PER_FILE_ON_MAC` takes the macOS matrix from 44 jobs to 78 (measured by running `get-tests.py` at both SHAs). Each new job pays a full artifact download, install and VM boot to run one file, and `containers/published-udp-ports.bats` skips everything on macOS via `skip_on_unix`, so two of those jobs only install. Splitting just the files that exceed a time budget, or reusing one instance across a suite, would keep the two-hour cap satisfied for fewer runner minutes. [Claude Opus 5]
- **`NerdctlClient.waitForReady` still retries forever (future).** The branch adds a log line every ten failures but nothing bounds the loop, so an engine that never becomes ready stalls the start. The new comment says so itself. `MobyClient.waitForReady` has the same shape. This is pre-existing: the loop is byte-identical at the merge-base. [Gemini 3.5 Flash]

### Strengths

- **The commit messages carry the evidence.** Each names the run ID, the measurement, and the alternative tried and rejected — `0b54d3644` on the firewall protocol, `1cc855bc1` on `Set-NetConnectionProfile`, `6b7116cee` on the k3s version, `d00838c62` on why the dropped `verify-cached-images` skip never matched. Reviewing 51 commits was possible because of them. [Claude Opus 5]
- **The dangling-symlink change is correct and non-obvious.** Replacing a dangling lima symlink with an empty file made `lima.ts`'s `symlink()` fail, and that failure is swallowed, so the placeholder blanked the lima logs for the rest of the run. Removing the symlink instead fixes it. [Claude Opus 5]
- **`summarize.mjs`'s `'no ok '` → `'not ok '` is a real fix.** The old string never matched TAP output, so failures counted as zero, and the earlier `startsWith('ok ')` arm cannot shadow the corrected one. [Claude Opus 5]
- **`package.yaml`'s `github.event.inputs.sign` → `inputs.sign`.** For a `workflow_dispatch` input declared `type: boolean`, the former is the string `"false"`, which is truthy; the latter is a real boolean. [Claude Opus 5]

## Review Process Notes

### Skill improvements

- Set the per-agent deadline from measured duration history rather than from prompt length or diff size, and record the measurement where the rule lives. Agent wall-clock does not track input size: an agent that verifies claims by running experiments spends its time per file, and one that answers from the diff finishes in a fraction of it regardless of how large that diff is.
- When an agent times out twice with no quota or API error, drop it and say so in the report rather than raising the deadline again. A second identical failure with the agent still working means it is not deadline-aware, and a longer budget buys another full wait for the same nothing.
- Check every agent worktree for files written outside the scratch directory, and read them. A fabricated finding is usually accompanied by the script that produced it, and comparing that script against the file it claims to test settles the finding faster than re-reading the code.
- When a reviewer's finding rests on a language, schema, or platform default, settle it from the implementing source rather than from the reviewer's assertion or your own recollection. Vendored toolchains pin a specific version whose behaviour is readable, and a default that applies only under a sibling condition is the common shape of this error.

### Repo context updates

- `[repo]` Jest run from the repo root collects specs from any worktree under `.claude/worktrees/`, so a stray worktree adds its whole suite to the run and its e2e specs fail under Jest. Pass `--testPathIgnorePatterns '/node_modules/' '/pkg/rancher-desktop/sudo-prompt/' '/[.]claude/worktrees/'` when a run reports failures in paths outside the main tree; overriding the flag drops the config's own `sudo-prompt` exclusion, which must be restated. A worktree marked `locked` belongs to a running session and must not be removed.
- `[repo]` `bats/Makefile`'s `lint` target runs from `bats/`, so its `find scripts` covers only `bats/scripts`. Shell added under `.github/workflows/` is not linted by any target, and `make lint` passing says nothing about it.
- `[repo]` On Windows the BATS suite runs inside the WSL distribution, not Git Bash: `bats.yaml` sets `BATS_COMMAND` to `wsl.exe --distribution <distro> --exec`. A helper that branches on `using_windows_exe` is choosing between the host's view and the distro's namespace, not between two shells.
- `[repo]` The BATS CI lane installs from the zip on Windows by default, and the zip install recreates the product's firewall rules under the MSI's own names. A test that asserts on rules named `Rancher Desktop Networking*` is reading the test harness's rules, not the product's, unless `INSTALL_MODE=installer`.
