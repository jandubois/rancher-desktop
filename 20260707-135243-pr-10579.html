Executive Summary ¶

PR #10579 adds two i18n-report subcommands: translate (missing keys with English values, sliceable into batches) and untranslated (a heuristic scan for hardcoded English). The code is clean, well-tested at the regex level, and carries no critical bugs. Two trivial consistency fixes stand out: an empty untranslated --format=json prints null instead of [], and the scan silently skips unreadable source files. Land both before merge.

All three reviewers agreed on the empty-JSON fix; Gemini and Codex independently flagged the silent skip. Gemini also raised one fabricated critical — a non-existent Split(comment, "n") bug — dropped on verification against the source. The reviewed diff spans the whole stacked branch, so two of the three commits belong to #10107; findings in the scanner (scan.go) are marked as such. The remaining findings are polish: stale known-gaps docs, a scrambled doc comment, misleading empty-batch text, and duplicated file-scan logic.

Design Observations ¶

Concerns

  • untranslated orchestration is untested (in-scope) Claude. The per-pattern regex tests are thorough, but the findUntranslated driver — the <template> tracking state machine, isVue/isTS branching, .spec/.test skipping, cross-line bare-text detection, and the includeDescriptions toggle — has no test over a sample file tree. A small fixture test would lock this behavior without golden-file brittleness.
  • translate errors on a not-yet-created locale file (future) Claude. reportTranslate loads the locale via loadYAMLFlat, so a missing <locale>.yaml returns exit 2 instead of listing every key as missing — awkward for the "add a new locale" workflow, where translate is the first command run. It mirrors stale and may be intentional (create the empty file first).
  • Dynamic key extraction would benefit from structured parsing (future) Codex. The root of S7: a TS/Vue AST pass, or a narrower extractor scoped to t()/exists() contexts, would drop the broad false matches and make unused more trustworthy.

Strengths

  • The []-not-null JSON invariant is deliberate and commented across the package (in-scope) Claude Gemini — I1 is the one place it slipped.
  • Sorting keys before slicing gives parallel translators stable, disjoint batches between runs (in-scope) Gemini Claude.
  • normalizeWhitespace documents its lossiness and points to --format=json for a lossless round-trip (in-scope) Claude Codex.
  • The exit-code split between findings (1) and operational failures (2) is a clean CI contract (in-scope) Codex.

Review Process Notes ¶

Skill improvements

  • When a finding predicts a program's observable output — a report includes or omits a value, a result serializes as [] versus null, a command exits with a specific code — build and run the program against the real tree to observe the actual bytes before assigning severity, instead of tracing the logic statically. Execution is cheaper and more decisive than reasoning through a chain of regexes or branches, and it separates a latent risk from a live defect: a pattern that "could" match a key may match nothing in the actual codebase, which is the difference between an Important bug and a low-priority nit.

Repo context updates

  • [repo] The src/go/i18n-report CLI holds a package-wide output contract: every report's JSON form must serialize an empty result as [], never null, enforced by TestReportDynamicJSONListsAreNeverNull and by nil→empty-slice guards in output.go, report_dynamic.go, and report_translate.go. When reviewing a new or changed report in this package, confirm each JSON-emitting path guards its slice before json.Encode. This is the tool's own output invariant, distinct from the moby/nerdctl T[] | null runtime divergence already in this file.
  • [repo] The same package treats an unreadable source file as an operational failure (exit 2), documented in scan.go and the README exit-code section. A new file-walking report that continues past a read error rather than returning it breaks that contract — flag it.
  • [repo] The i18n-report work ships as a stack of PRs (group 1 = #10107, group 2 = #10579, later groups after), each targeting main. Until a parent merges, a child PR's diff carries the parent's commits, so the reviewed surface is wider than the child's own change. Attribute findings in already-reviewed base files (the scanner, YAML loader, output helpers) to the parent PR, and concentrate severity on the child commit's new files.
