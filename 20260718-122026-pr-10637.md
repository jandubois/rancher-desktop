S3. **Fallback title does not update on locale change** — `pkg/rancher-desktop/pages/containers/ContainerInfo.vue:198` [Gemini 3.1 Pro]

```ts

  store.dispatch('page/setHeader', {
    title:       name || t('containerInfo.fallbackTitle'),

    action:      'ContainerStatusBadge',

```

`setHeader` stores the evaluated string in Vuex, so a `title:` value never re-translates; only `titleKey` recomputes reactively in `TheTitle.displayTitle`. Fix: pass `titleKey: name ? '' : 'containerInfo.fallbackTitle'` alongside `title: name || ''`.

## Design Observations

### Concerns

- **Main-process `t()` does not auto-inject `appName`/`vendor`; the renderer does** `(future)` [Claude Opus 4.8] — `store/i18n.js` merges `{ vendor, appName }` into every format call, so `t('kubernetesError.title')` resolves `{appName}` with no explicit arg. `main/i18n.ts`'s `t()` has no such injection, so a main-process call to a shared `{appName}` key must pass it explicitly or ICU throws and degrades to the literal. Every current main-process caller (`mainmenu.ts`) does pass `{ appName }`, so this is latent — but a future reference to a shared key is a quiet trap. Consider injecting `appName`/`vendor` in `main/i18n.ts` too.

- **Navigation labels have a hand-maintained mirror** `(future)` [Codex GPT 5.6 Sol] — `Nav.vue:123-133` maps paths to translation keys separately from `window/constants.ts` and the router. The mapping is complete today, but a future route can silently display its English `name`. Putting `labelKey` on route metadata would make route registration the single source of truth.

- **HTML links embedded in translation strings** `(future)` [Gemini 3.5 Flash] — keys such as `kubernetesPrefs.options.spinkubeWarning` embed `<a>` tags with `data-navigate`, coupling presentation to translations; translators must keep the markup intact. `validate` enforces tag/`data-*`/`href` parity, and the README documents the coupling. Component-slot interpolation would remove it later.

### Strengths

- `backendHelper.ts:177` replaces the `/field ".*" is locked/` stderr regex with the structured `sv.hasLockedFieldError` flag — the right move now that validator messages are localized [Claude, Codex, Gemini 3.5 Flash].
- `store/page.ts` `setHeader` clears the opposing field on every branch (`titleKey` set ⇒ `title=''` and vice-versa), so a key-based title cannot leak past a navigation to a literal-title page [Claude].
- Each per-window `onLocaleChange` registration (`tray.ts`, `dashboard.ts`, `preferences.ts`) is paired with an unregister on teardown [Claude, Codex, Gemini 3.5 Flash].
- Separate infinitive/gerund/past-tense image-action keys resolve #1481 without assembling sentences from English fragments [Codex, Gemini 3.5 Flash].

## Review Process Notes

### Skill improvements

- When a diff replaces one positional argument of a function call — a string literal becoming a `t()` call, a value becoming a wrapper — diff the call's **entire** argument list against the base revision, not just the replaced token. Mechanical extraction and rename edits frequently drop a trailing positional argument (a boolean flag, an options object) along with the token being rewritten, which silently changes behavior while looking like a pure refactor in review. Flag any call whose argument count or trailing arguments changed without a stated reason.

### Repo context updates

- [repo] In the page-header system (`store/page.ts` + `components/TheTitle.vue`), only `titleKey`/`descriptionKey` produce a locale-reactive header: `setHeader` stores a `title:`/`description:` value as a frozen string in Vuex, so even `title: t('…')` will not re-translate on a locale change, while `TheTitle.displayTitle` resolves `titleKey` reactively. When reviewing a `setHeader` caller, treat a translated `title:` value as a reactivity gap — except where the title is genuinely dynamic data (a resource name), which legitimately uses `title:` with a `titleKey` fallback for the empty case.

- [repo] Translator-controlled HTML must render through the registered `v-clean-html` (DOMPurify) directive, not raw `v-html`; `plugins/i18n.js` documents this as the intended sink, and DOMPurify preserves `data-*` and `href="#"` so `data-navigate`/`data-action` wiring survives sanitization. Flag any new `v-html` bound to a translation lookup, even behind an `eslint-disable vue/no-v-html`, and recommend `v-clean-html` — the strings are app-controlled today but become untrusted once user-supplied translations land.

- [repo] Backend `ProgressTracker.action()`/`numeric()` descriptions are user-facing progress text but are invisible to the `i18n-report` CI gate (first-arg template literals the scanner skips). When reviewing an i18n extraction PR, grep `progressTracker\.(action|numeric)\('` for remaining English literals — the gate will pass regardless, so you must catch these gaps by reading.

#### Suggestions

S1. **Hardcoded Semicolon & Period Punctuation in Dynamic String Concatenation** — `pkg/rancher-desktop/components/UpdateStatus.vue:157-172`

```typescript
      const { info, progress } = this.updateState;
      // Punctuation is hardcoded here (period, semicolon). Some locales use
      // different punctuation; revisit when locale coverage grows.
      const prefix = this.t('updateStatus.available', { version: info.version });

      if (!progress) {
        return `${ prefix }.`;
      }
      // ...
      return `${ prefix }; ${ this.t('updateStatus.downloading', { percent: String(percent), speed }) }`;
```

Hardcoded delimiters (like `.` and `;`) assume Western punctuation conventions, which can lead to awkward or grammatically incorrect rendering in other languages (such as Japanese or Chinese, which use full-width punctuation `。` or `；`).

Fix: Avoid splitting and gluing punctuated clauses in code. Instead, declare separate fully templated messages for both the simple and in-progress states:

```diff
-      const prefix = this.t('updateStatus.available', { version: info.version });
-
-      if (!progress) {
-        return `${ prefix }.`;
-      }
-      const percent = Math.round(progress.percent || 0);
-      const speed = new Intl.NumberFormat(undefined, {
-        style:        'decimal',
-        notation:    'compact',
-      }).format(progress.bytesPerSecond);
-
-      return `${ prefix }; ${ this.t('updateStatus.downloading', { percent: String(percent), speed }) }`;
+      const { info, progress } = this.updateState;
+
+      if (!progress) {
+        return this.t('updateStatus.availableMessage', { version: info.version });
+      }
+      const percent = Math.round(progress.percent || 0);
+      const speed = new Intl.NumberFormat(undefined, {
+        style:        'decimal',
+        notation:    'compact',
+      }).format(progress.bytesPerSecond);
+
+      return this.t('updateStatus.downloadingMessage', {
+        version: info.version,
+        percent: String(percent),
+        speed,
+      });
```

### Design Observations

#### Concerns

1. **HTML Link Extraction Coupling** `(in-scope)`
   Embedding `<a>` tags with `data-navigate` directly in localized strings (e.g. `kubernetesPrefs.options.spinkubeWarning`) creates tight coupling between presentation attributes and translations. Translators must keep the exact link syntax intact.
   *Alternative:* Use slot-based component interpolation or structured split messages (e.g. `{ prefix } <a>{ linkText }</a> { suffix }`) in the future to keep translation files entirely clean of HTML presentation logic.

#### Strengths

1. **Structured Error Classification (`hasLockedFieldError`)**
   Exposing a structured boolean flag `hasLockedFieldError` on `SettingsValidator` instead of matching raw localized error text (such as `field "..." is locked`) is a brilliant and highly professional approach that fully neutralizes localized string parsing hazards in backend validation paths.
2. **Deterministic Locale Change Rebuilding**
   Registering `onLocaleChange` callbacks to rebuild Electron application menus, tray menus, and window titles dynamically on locale changes provides a flawless runtime experience without requiring application restarts.
