Executive Summary ¶

The PR adds two i18n-report subcommands: drift (flags translations whose English @source snapshot has changed) and check (the CI gate over source, registration, and per-locale checks, with --strict for completeness). The code is clean, well-tested, and passes end-to-end on the i18n-workflow-v2 tree it polices. Design Observations ¶

Concerns ¶

  • unused sits in the default gate, against a strings-first workflow (in-scope) Claude. Bare check — the PR-CI form — always runs unused (report_check.go:110), so it fails when an en-us key lands before the code that references it. This project's stack lands strings ahead of their wiring, exactly the case that trips it (the current review SHA reports 2961 unused keys). undefined belongs in the default, since it renders %key% at runtime; consider moving unused behind --strict, where completeness and hygiene already live.

Strengths ¶

  • The gate-vs-lister invariant is real for stale, missing, and drift. check --strict flattens the locale with loadYAMLFlat and drift uses nodeAllLeaves, but both route through flattenNodeWithComments/appendKeyPath, so they produce identical key sets — the two commands report identical drift by construction.
  • The errFindings / operational split (main.go:20-32) is clean, and drift honors it correctly.
  • Drift compares decoded scalars, so re-quoting the English never counts as drift (compute.go:11-13) — a subtle correctness property, well-commented.
  • Keeping missing and drift behind --strict is a sound CI split: PR runs stay structural, release runs enforce completeness.

Review Process Notes ¶

Skill improvements ¶

  • When a tool documents a dual exit-code or error-taxonomy contract (findings vs. operational, retryable vs. fatal, warning vs. error), enumerate every terminal path across all sibling subcommands and confirm the same underlying condition maps to the same code everywhere. Sibling commands that share a contract routinely draw the boundary differently for an edge case — a missing input file, a malformed config, an unknown argument — and the divergence stays invisible until the paths are compared side by side.
  • When a PR adds a CI gate, validator, or check whose inputs are supplied by other changes (sibling PRs in a stack, an integration branch, a later migration), identify the tree the gate is meant to run against and exercise it there before rating findings that it aborts, fails, or cannot run. A gate that is dormant on its own branch, because its inputs are not yet assembled, is expected rather than a defect; run it where the inputs exist before assigning severity.
