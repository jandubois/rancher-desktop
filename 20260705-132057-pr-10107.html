Executive Summary ¶

This PR adds i18n-report, a self-contained Go CLI that scans Vue/TS/JS source and en-us.yaml to report unused, undefined, stale, referenced, and dynamic translation keys. It is the recut first slice of a ten-PR stack — only the scanner and read-only reports — cleanly scoped and fully tested. One output bug matters: references --format=json emits keys absent from en-us.yaml, diverging from text mode. The rest are documentation and scope cleanups.

The three reviewers converged. Claude and Gemini independently caught the JSON leak; Codex and Claude flagged package comments that name subcommands (check, drift, merge, translate) and helpers (loadMetadata) absent from this slice; Gemini and Claude noted override/merge machinery in yaml.go carried from later slices and dead here. No critical issues surfaced. Running every report against the live tree confirmed the heuristic scanner produces zero false positives today — the undefined gate finds exactly seven genuine missing keys — so the several "this heuristic could false-positive" concerns are future hardening, not current bugs.

S3. Unsupported --format values silently render as text Codex¶

Every report accepts --format but compares only against "json", so any other value — including a typo like --format=jsoon — renders as text and exits 0. A shared validator returning an operational error (exit 2) for values other than text or json would catch the mistake. The pattern repeats in report_dynamic.go, report_references.go, report_stale.go, and report_undefined.go.

// mergeEntry holds a translated key-value pair with an optional comment.
type mergeEntry struct {
	key      string
	value    string
	comment  string // may be multi-line (joined with "\n")
	override bool   // true if comment contains @override
}

// loadYAMLWithComments loads a YAML file and returns flattened entries
// that preserve YAML comments (e.g. @reason, @context annotations).
func loadYAMLWithComments(path string) (map[string]mergeEntry, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, err
	}
	var doc yaml.Node
	if err := yaml.Unmarshal(data, &doc); err != nil {
		return nil, fmt.Errorf("parsing %s: %w", path, err)
	}
	result := make(map[string]mergeEntry)
	if doc.Kind == yaml.DocumentNode && len(doc.Content) > 0 {
		flattenNodeWithComments("", doc.Content[0], result)
	}
	return result, nil
}

// flattenNodeWithComments recursively flattens a yaml.Node tree into
// dotted keys, preserving HeadComment from leaf key nodes.
func flattenNodeWithComments(prefix string, node *yaml.Node, result map[string]mergeEntry) {
	if node.Kind != yaml.MappingNode {
		return
	}
	for i := 0; i < len(node.Content)-1; i += 2 {
		keyNode := node.Content[i]
		valNode := node.Content[i+1]
		key := keyNode.Value
		if prefix != "" {
			key = prefix + "." + key
		}
		if valNode.Kind == yaml.MappingNode {
			flattenNodeWithComments(key, valNode, result)
		} else {
			result[key] = mergeEntry{
				key:      key,
				value:    valNode.Value,
				comment:  keyNode.HeadComment,
				override: commentHasOverride(keyNode.HeadComment),
			}
		}
	}
}

// overrideMarker is the comment line that protects a hand-tuned translation.
const overrideMarker = "# @override"

// commentHasOverride returns true if a comment string contains @override.
func commentHasOverride(comment string) bool {

		trimmed := strings.TrimSpace(line)
		if trimmed == overrideMarker || strings.HasPrefix(trimmed, overrideMarker+" ") {
			return true
		}
	}
	return false
}

S8. indirectKeyPattern misses double-quoted object property names Gemini¶

The pattern matches property names only as bare words (\b\w+) or single-quoted strings ('[^']+'). A double-quoted property with a key-shaped value — "my-prop": 'foo.bar' — is missed, so foo.bar is never counted as referenced and unused reports it as dead. This affects unused precision only (not the undefined gate), and no such construct exists in the tree today. Add "[^"]+" to the property-name alternation.

S9. Dead ${ guard in extractDynamicPatterns Gemini¶

The loop skips a template that lacks ${, but dynamicKeyLiteral already requires \$\{[^}]+\} to match, so the guard can never fire. Drop it.

S10. Line-based comment filter misses block comments without leading asterisks Gemini¶

commentLinePattern matches lines starting with //, *, /*, or <!--. Block-comment inner lines lacking a leading *, and multi-line HTML comments, read as live code. A stateful inBlockComment flag in the line loop would close the gap. Theoretical today — the scan produces no false positives on the current tree.

Design Observations ¶

Concerns ¶

  • (future) The undefined gate's heuristics can false-positive once wired to CI — scan.go Claude Gemini. keyAttrPattern captures any *-key="literal" attribute; the keyPropLine→dottedKeyLiteral path captures every dotted lowercase literal on a line containing titleKey/labelKey/descriptionKey; multilineKeyPattern and trailing/block comments bypass the line-based comment filter. All feed directRefs, which drives the exit-1 gate. Today the tree is clean — exactly seven real undefined keys, no false positives. But a future attribute like sort-key="metadata.name", or an unrelated dotted literal on a labelKey line, would be reported as undefined and, once a later slice wires the gate into CI, fail the build on non-translation code. Constrain keyAttrPattern's value to the key shape, or gate undefined on a curated attribute allowlist. (Gemini raised the keyPropLine and multilineKeyPattern cases as important findings; the zero-false-positive result recalibrates them to this forward concern.)
  • (in-scope) unused folds dynamic matches into "used," under-reporting truly dead keys — scan.go:256-263 Codex. A broad pattern like snapshots.dialog.{}.info marks snapshots.dialog.delete.info used even though only the restore branch calls it (SnapshotCard.vue:139). For a deletion tool this is the safe direction — treating a dynamically-matchable key as used avoids proposing deletion of a live key. A "possibly used" tier (or listing dynamic matches separately) would surface those keys without that risk. Assessment: the current behavior is correct by default; the tier is a precision enhancement, not a fix.
  • (future) Regex-heuristic scanning versus a Vue/TS parser — scan.go Claude. Roughly eleven regexes over raw lines: fast (<1s over the tree) and conservative. Residual noise shows in dynamic, which reports a JS object-access literal WSL.integrations["{}"] with zero matches. If the heuristic set keeps growing across the stack, a lightweight parse would remove the trailing-comment and object-access corners wholesale.

Strengths ¶

  • (in-scope) The refs/directRefs split — scan.go:151-161 Claude Codex Gemini. unused uses the permissive set (indirect and dynamic) to avoid false deletions; undefined uses the strict set to avoid false alarms. The rationale is documented at the point of use.
  • (in-scope) Exit-code discipline — main.go:49-55 Claude Codex. errFindings maps to exit 1 for findings and 2 for operational errors — the right primitive for CI gating, explained in both code and README.
  • (in-scope) Complete integration touches Claude. A single dependency (yaml.v3), the module wired into go.work, a package.json test target, .gitignore, and spelling excludes all land together and correctly.

Review Process Notes ¶

Skill improvements ¶

  • When the change adds or modifies a source scanner, linter, code generator, or CI gate, run it against the real repository before rating any finding that alleges a false positive or false negative. Base severity on the observed output: a heuristic that could misfire in theory but produces none on the current tree is a hardening suggestion, not a correctness bug. State the command run and its result in the finding. Reviewers that reason about the regex in isolation systematically inflate the severity of edge cases the real input never hits.
  • When a round-N PR has been recut rather than incrementally updated — the current diff no longer contains the files a prior round's findings referenced — state this in the prompt and skip injecting prior findings whose code is gone. Re-verify only the prior findings whose files survive the recut. Asking agents to re-check findings against deleted code wastes tokens and invites confusion between the old and new scope.
