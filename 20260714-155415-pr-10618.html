Executive Summary ¶

This PR adds runtime i18n: a main-process ICU translator mirroring the renderer store, a shared translation loader, localized validator errors classified through a structured hasLockedFieldError flag, and an experimental language picker. The design is coherent and well tested. Two Important gaps remain: one validator caller still regex-parses the now-localized lock message, and the bundled zh-hans.yaml makes Chinese a selectable, validator-accepted locale that the command-api enum rejects.

All three reviewers converged on both Important issues (Codex and Claude on each; Gemini added a latent lock-path defect downgraded here to S3). No finding contradicted another. The remaining suggestions are cleanup: a dead import, two parallel t() implementations that drift, README references to tooling not on this branch, and dead arguments at ~20 call sites. The escaping-model change (raw output, sinks escape) was audited safe.

Design Observations ¶

Concerns ¶

  • Two parallel ICU translators (future) Codex Claude — the split-source translators behind S2 are also the root of I2's registration drift. One shared translate(map, locale, key, args) core, consumed by the store getter and the main-process t, would remove both the formatting divergence and the locale-set divergence as classes rather than as instances.
  • Unused locale-change callback machinery (future) Claude — onLocaleChange/localeChangeCallbacks (main/i18n.ts:113) is an exported registration API plus a dispatch loop with no consumer anywhere in pkg/. The README frames it as future tray infrastructure; landing it with its first consumer would avoid shipping speculative surface.
  • none repurposed; the %key% debug mode is gone (in-scope) Claude — the old store rendered every string as %key% when selected === 'none' (a coverage-audit aid, toggled by the deleted toggleNone). The new code maps none → en-us. Removal is safe — toggleNone and selectedLocaleLabel are unreferenced (verified) — but the audit aid is lost.

Strengths ¶

  • Shared translationLoader (in-scope) Claude — it unifies webpack, jest, and tsx loading, and its recursive: false, /\.yaml$/ filter fixes the old "any file under translations/ becomes a locale" footgun, so README.md now lives safely in that tree.
  • Coherent escaping model (in-scope) Gemini Claude — raw output with the sink escaping, plus v-clean-html for interpolated external data, is documented and well tested. The audit confirmed the sole v-t usage is plain text and no two-argument t() reaches an unsanitized HTML sink.
  • Structured error classification (in-scope) Codex Claude — hasLockedFieldError is the right replacement for regex-sniffing localized text; its absence at one call site is I1, not a flaw in the approach.

Testing Assessment ¶

Coverage of the pure getters and formatters is strong: the store, main, and plugin specs exercise per-key English fallback, ICU plurals, missing-argument degradation, malformed patterns, and the no-escape contract. The highest-value gaps, in order: backendHelper.checkForLockedVersion under a translated validation.fieldLocked (a test here catches I1); main-process locale switching (initMainI18n, the settings-update handler, loadLocale failure staying put); the store switchTo/init lifecycle (cookie read, settings-read sync, load-failure fallback, cache clearing); the availableLocales display-name logic (relevant to I2); and an ApplicationGeneral.vue picker test. Both Codex and Claude noted jest could not run in the worktree (node_modules absent), so none of the new specs were executed during review.

Acknowledged Limitations ¶

  • Localized validation messages must not be parsed (README §"Validation messages"; settingsValidator.ts:303) — the author states classification uses structured flags. I1 is the one call site inconsistent with that rationale, so it is a finding rather than an accepted limitation.
  • String-based registration cross-validation (README §"i18n-report tool") — settingsValidator.spec.ts hard-codes the English lock string; acknowledged as revisit-when-next-locale-added.
  • HTML coupling in translation strings (README §"HTML in translation strings") — <a data-action> markup couples to app code; acknowledged, deferred to slot restructuring.
  • onLocaleChange unregister discipline (README §"Callback lifecycle") — callers must unregister on teardown to avoid leaks; acknowledged, and orthogonal to the no-consumer observation above.
  • Scanner gaps (README §"Scanner gaps") — showErrorBox and port-forward errors, and __tests__, are not scanned; acknowledged deferred coverage.

Review Process Notes ¶

Skill improvements ¶

  • Localizing a machine-read string breaks its parsers. When a change converts a signal that code elsewhere pattern-matches — an error string, status text, or label — into localized or otherwise user-facing text, search the whole codebase for every consumer that parses or regex-matches that text, not just the files in the diff. Localization silently defeats string-based classification, and the broken consumer usually sits in an untouched file. Flag any parser of a now-localized string and prefer a structured signal (flag, error subclass, status code) over the parse.
  • Runtime-discovered value sets drift from their hand-declared mirrors. When a set of valid values is discovered at runtime from the filesystem (a glob, directory read, or bundler context) yet also declared by hand elsewhere — an API or schema enum, a validator list, a UI menu — treat the pair as a drift risk. Enumerate every hand-maintained mirror and check it against what discovery actually yields; a stray or stale file on disk can widen the runtime set past the declared contract with no code change in the diff.

Repo context updates ¶

  • [repo] The app's pkg/rancher-desktop/assets/translations/ directory is the source for availableLocales via utils/translationLoader.ts, which reads every *.yaml file present. Any locale file in that directory becomes selectable in the Preferences picker and accepted by settingsValidator's checkEnum('none', ...availableLocales), independently of the command-api.yaml locale enum and the Go/rdctl contract generated from it. When reviewing i18n or settings changes, cross-check the on-disk locale files against the command-api enum — the two are maintained separately and drift silently.
