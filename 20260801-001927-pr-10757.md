## Executive Summary

The sentinel is built and wired correctly: real failures win, `publish` skips a rollback that would have been a no-op, and gvisor keying its proxies on `(protocol, local)` makes the delegation safe. One regression survives. The scanner releases a delegated port only when its listener vanishes or changes shape, so `APITracker.RemoveAll` tearing down the owner's expose strands the port. The merge-base recovered on the next tick.

Two reviewers found the regression independently, and a differential probe against both revisions reproduced it. The remaining eight suggestions are optional; four are pre-existing gaps in adjacent code.

## Important Issues

I1. **A delegated port is never re-probed, so `RemoveAll` strands it** — `src/go/guestagent/pkg/procnet/scanner_linux.go:175-184` [Claude Opus 5, Codex GPT 5.6 Sol]

```go
	for port, bindings := range p.delegated {
		if newBindings, ok := scanned[port]; ok && bindingsEqual(bindings, newBindings) {
			continue
		}
```

The scanner reads an unchanged `/proc/net` binding as proof that ownership persists, and lines 208-210 then suppress every future `Add`. But ownership can end while the listener stays. All five subsystems share one `portTracker` (`main.go:139`), and `RemoveAll` unexposes every binding in it on each engine reconnect, via `docker.EventMonitor.Flush()` (`main.go:203`) and `containerd.EventMonitor.Close()` (`main.go:179`). Docker re-registers via `initializeRunningContainers`; the kube watcher and iptables scanner do not. At the merge-base the scanner retried each tick and recovered.

Fix: bound the delegation. Re-pend each delegated port after a fixed interval (~5 min), and keep the re-delegation log at Debug so the log-growth fix stands.

I probed both revisions. Across 100 ticks after the owner loses its expose, HEAD calls `tracker.Add` once and never republishes; the merge-base scanner republishes on the next tick (`Add` twice, "added port" logged). Codex reached the same counts independently.

## Suggestions

S1. **Two `Add` call sites still treat the sentinel as fatal** — `src/go/guestagent/pkg/docker/events.go:164` [Claude Opus 5]

```go
			if err := e.portTracker.Add(container.ID, portMap); err != nil {
				log.Errorf("registering already running containers failed: %v", err)
				continue
			}
```

The PR classifies three of five call sites. This one and `containerd/events_linux.go:124` still log at Error, and the `continue` skips `createLoopbackIPtablesRules` at line 169. That matches the merge-base, so nothing regressed. But the bare sentinel carries less than the old `ErrExposeAPI` wrap, which named the binding.

Fix: classify the sentinel here too, or return `fmt.Errorf("%w: %d binding(s) for %s", ErrPortAlreadyExposed, alreadyExposed, containerID)` so unclassified sites keep their diagnostics.

S2. **The `Tracker` interface contract omits the sentinel** — `src/go/guestagent/pkg/tracker/tracker.go:29` [Claude Opus 5]

```go
	// Add adds a portMap to the storage using the containerID as a Key.
	// It replaces all existing portMappings, without attempting to unbind listeners,
	// so the caller is responsible for calling Remove first if necessary.
	Add(containerID string, portMapping nat.PortMap) error
```

All three updated callers hold a `tracker.Tracker`, not `*APITracker`, so the contract belongs on the interface. Only the concrete method documents it today.

Fix: state on the interface that `Add` returns `ErrPortAlreadyExposed` when every port in the request was already exposed elsewhere and nothing else failed.

S3. **The upstream literal has no provenance note** — `src/go/guestagent/pkg/tracker/apitracker.go:54` [Claude Opus 5]

```go
const portAlreadyExposedSubstring = "proxy already running"
```

Accurate today: `gvisor-tap-vsock@v0.8.9/pkg/services/forwarder/ports.go:74` is `errors.New("proxy already running")`, and the `/expose` handler passes it through verbatim. Upstream exports no sentinel for it, and the three new tests write the string themselves. So an upstream rewording reverts the fix with a green suite and no compile error.

Fix: name the file and version in the comment so a dependency bump prompts a re-check.

S4. **Delegation is logged at three different levels** — `src/go/guestagent/pkg/procnet/scanner_linux.go:244` [Claude Opus 5]

```go
			log.Infof("/proc/net scanner delegating port %s to its existing exposer", port)
```

`iptables.go:128` and `watcher_linux.go:182` log Debug, and debug is off in production (#10737), so those two delegations go unlogged. The asymmetry is defensible, since the kube line fires per watcher event and the other two fire once per port. But nothing in the code says so.

Fix: raise `iptables.go:128` to Info and note on `watcher_linux.go:182` why the kube path stays at Debug.

S5. **Package doc gives half the release rule** — `src/go/guestagent/pkg/procnet/scanner_linux.go:23-26` [Claude Opus 5]

```go
iptables rules. Ports another component already exposes -- e.g.
docker-proxy's persistent per-published-port listeners, which the

```

The field comment and the `Tick` doc both say "vanishes **or changes binding shape**", and `TestDelegatedPortReleasedOnBindingShapeChange` pins the omitted half.

Fix: `... until their listener disappears or changes binding shape.`

S6. **The docstring overstates what `alreadyExposed` counts** — `src/go/guestagent/pkg/tracker/apitracker.go:96-100` [Claude Opus 5]

```go
// If the expose API reports every port in the request as already
// exposed and no other failures occurred, Add returns
// ErrPortAlreadyExposed so callers can treat the call as successful
// delegation rather than a failure to retry.
```

`Add` skips non-IPv4 bindings (lines 114-118) without incrementing `alreadyExposed` or `errs`. A request pairing one already-exposed IPv4 port with a second port bound only on IPv6 returns the sentinel, and the caller reports the whole request as delegated. The merge-base was silent about the IPv6 port too, so this is a precision fix.

Fix: narrow the wording to "every port the API was called for".

S7. **The iptables scanner reuses an accumulating `portMap`** — `src/go/guestagent/pkg/iptables/iptables.go:103` [Gemini 3.1 Pro, Gemini 3.5 Flash, Claude Opus 5]

```go
		portMap := make(nat.PortMap)

		// Add new forwards
		for _, p := range added {
```

Nothing clears `portMap` between iterations, so the i-th `Add` resubmits ports 1..i-1, a quadratic number of expose POSTs per scan. `portStorage` stays correct because the already-exposed rejection keeps duplicates out of `successfullyForwarded`, so `Remove` never over-unexposes. Pre-existing; this PR silences the Error line it used to produce.

Fix: move `make(nat.PortMap)` inside the loop. That keeps `Add`/`Remove` symmetric on `utils.GenerateID(name)`, which one batched `Add` would not.

S8. **A real Expose failure drops the port permanently** — `src/go/guestagent/pkg/iptables/iptables.go:91` [Gemini 3.1 Pro]


A port whose `Add` fails at line 124 stays in `ports`, never reappears in `added`, and never gets retried. Pre-existing and untouched by this PR.

Fix: record only successfully forwarded entries into the slice carried to the next tick.

## Design Observations

### Concerns

- **`RemoveAll` omits `Protocol` on the unexpose request** *(future, pre-existing)* [Claude Opus 5] — `apitracker.go:248-251` builds `types.UnexposeRequest{Local: ...}` with no `Protocol`, while `Remove` (lines 199-203) sets it. gvisor's `/unexpose` handler defaults an empty protocol to TCP and keys on `key(protocol, local)`, so `RemoveAll` never tears down a UDP proxy. Unrelated to this PR, but it sits on the cleanup path I1 depends on.
- **Textual conflict detection has no ownership lifecycle** *(future)* [Codex GPT 5.6 Sol] — `ErrPortAlreadyExposed` says a proxy exists, not who owns it or whether that ownership later ends. A host-switch response carrying an owner or lease identifier would eliminate the whole stale-delegation class.

### Strengths

- **gvisor's proxy key makes the delegation safe** *(in-scope)* [Claude Opus 5] — `Remote` is unconditionally `tapIP:HostPort` (`apitracker.go:125`) and gvisor's proxy key is `(protocol, local)` (`ports.go:261-263`), so "proxy already running" can only mean an identical forward exists. The whole design rests on that property.
- **Real failures are ordered ahead of the sentinel** *(in-scope)* [Claude Opus 5, Gemini 3.1 Pro] — the `errs` check at `apitracker.go:160` precedes the sentinel at line 168, and `TestAddAlreadyExposedPlusRealFailureReturnsRealFailure` pins it in both directions with `ErrorIs`/`NotErrorIs` instead of a bare `assert.Error`.
- **The skipped rollback is correct and asserted** *(in-scope)* [Claude Opus 5, Gemini 3.5 Flash] — `publish` returns early on the sentinel (`scanner_linux.go:239-246`) without calling `tracker.Remove`, because `Add` stored nothing under the scanner's id; the test asserts `len(tr.removed) == 0` instead of trusting the reasoning.

## Review Process Notes

### Skill improvements

- When a change makes a caller stop retrying a failed operation, identify every path that can invalidate the state the caller now trusts, and confirm the caller re-evaluates after each one. Suppressing a retry converts a self-healing loop into a cache, and a cache with no invalidation path strands whatever it holds. Check in particular for a bulk-reset or reconnect handler that clears shared state the non-retrying caller does not observe.
- When a change adds a typed error that some callers classify, enumerate every call site of the function that returns it. A partial rollout leaves the unconverted sites treating the new value as a generic failure, which can skip work in their error branch and drops whatever context the previous wrapped error carried.
- When a fix depends on matching a literal string produced by a dependency, locate that literal in the dependency's source and record the file and version. Report it as unpinned when the dependency exports no sentinel for it and the project's tests construct the string themselves, since a rewording upstream then reverts the fix with a passing suite and no compile error.

### Repo context updates

- [repo] The `rancher-desktop-guestagent` binary ships only inside the WSL distro image, assembled by `WSLDistroImage` in `scripts/dependencies/tar-archives.ts`. It does not run in the Lima VM on macOS or Linux, where Lima's own guest agent handles port forwarding. Treat findings in `src/go/guestagent/` as Windows-only in scope, and read its `_linux.go` suffixes as "the guest OS", not "the host platform".
- [repo] All of `src/go/guestagent`'s port-forwarding subsystems (container-engine event monitors, the Kubernetes service watcher, the iptables scanner, and the `/proc/net` scanner) share one `tracker.Tracker` instance created in `main.go`. Any finding about one subsystem's tracker state must account for the others, and in particular for `RemoveAll`, which any engine event monitor can call on reconnect and which unexposes every port the other subsystems registered.
- [repo] Linux-only Go packages under `src/go/` cannot run their tests on the macOS review host, so a review that reports them as passing has usually only compiled them. Build the test binary with `GOOS=linux GOARCH=arm64 go test -c` and run it inside the Rancher Desktop VM via `rdctl shell`, copying the binary through the user's home directory, which the VM mounts.

# Deep Review — PR #10757: guestagent: treat "proxy already running" as delegation, not failure

### Executive Summary

The change adds `tracker.ErrPortAlreadyExposed`, returned by `APITracker.Add` when every attempted Expose reported the port already bound, and teaches the three scanning callers to treat it as delegation. The classification is sound — gvisor's proxy key is `(protocol, local)` and `Remote` is always `tapIP:HostPort`, so "already running" provably means an identical forward exists. The headline issue is that the `/proc/net` scanner's delegation is permanent and never re-probed, while `APITracker.RemoveAll()` (reached on every container-engine reconnect) can tear the owner's expose down underneath it.

### Findings

#### Critical Issues

None.

#### Important Issues

**I1. Delegated ports are never re-probed, so an engine reconnect can strand them — `src/go/guestagent/pkg/procnet/scanner_linux.go:191-199`** (important, regression)

```go
		if err := p.publish(port, bindings); err != nil {
			// Another component already exposes this port; hand it off
			// and stop retrying until its listener goes away. Any other
			// failure leaves the port in pending for a next-tick retry.
			if errors.Is(err, tracker.ErrPortAlreadyExposed) {
				p.delegated[port] = bindings
			}
			continue
		}
```

A delegated port is released only when its listener vanishes or changes shape (lines 175-184). Nothing re-validates that the delegate still holds the expose. `APITracker.RemoveAll` (`apitracker.go:274`) wipes the entire shared `portStorage` and unexposes everything; it runs on every engine reconnect — `docker.EventMonitor.Flush()` (`docker/events.go:133`, called at `main.go:203` whenever the docker event stream errors, e.g. a dockerd restart) and `containerd.EventMonitor.Close()` (`containerd/events_linux.go:306`). Docker re-adds via `initializeRunningContainers`, but the kube watcher and iptables scanner do not resync — so a port delegated to either stays unforwarded until its listener changes or the guestagent restarts. At the merge-base the per-tick retry recovered these. The field comment at lines 86-93 documents the release rule but not this case.

Fix: bound the delegation. Track a per-port tick count and re-pend after a slow cadence (~5 min at `procNetScanInterval`), keeping the re-delegation log at Debug so the #10737 log-growth fix stands:

```diff
 	for port, bindings := range p.delegated {
 		if newBindings, ok := scanned[port]; ok && bindingsEqual(bindings, newBindings) {
+			p.delegatedTicks[port]++
+			if p.delegatedTicks[port] < delegationRecheckTicks {
+				continue
+			}
+			delete(p.delegatedTicks, port)
+			// Re-probe: the owner may have lost its expose (RemoveAll).
+		} else {
+			delete(p.delegatedTicks, port)
 		}
 		delete(p.delegated, port)
 	}
```

```go
			if err := e.portTracker.Add(container.ID, portMap); err != nil {

			}
```

It also logs at Error, reintroducing the noise the PR removes elsewhere. Reachable whenever the docker event stream restarts and the `/proc/net` scanner (3 s ticker) exposed docker-proxy's listeners first. #### Suggestions

**S1. `Tracker.Add`'s interface contract does not mention the new sentinel — `src/go/guestagent/pkg/tracker/tracker.go:27-30`** (suggestion, gap)

```go
	// Add adds a portMap to the storage using the containerID as a Key.
	// It replaces all existing portMappings, without attempting to unbind listeners,
	// so the caller is responsible for calling Remove first if necessary.
	Add(containerID string, portMapping nat.PortMap) error
```

All three updated callers hold a `tracker.Tracker`, not `*APITracker`, so the interface is where the contract lives. The sentinel is documented only on the concrete method (`apitracker.go:96-100`). A future `Tracker` implementation has no signal that it must return `ErrPortAlreadyExposed` for the delegation logic to work.

Fix: add to the interface comment — "Add returns ErrPortAlreadyExposed when every port in the request was already exposed by another component and nothing else failed; callers should treat that as delegation, not failure."
