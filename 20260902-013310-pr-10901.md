## Executive Summary

This PR is a workaround for a moby regression: `LoadImage` keeps a `moby-dangling@` record for every re-imported image whose tag already points at the same target, and every later inspect logs it. The helper's digest comparison and its fallbacks behave as documented against the real k3s archive under busybox awk. The one Important finding: the new BATS assertion reads a Lima-only log path, so the test fails on Windows. The awk parser's format assumptions are the main design risk.

Four reviewers ran on the same prompt. All three tool-using reviewers found the Windows log path; Codex, Gemini 3.1 Pro, and Claude each found a different shape of `index.json` that the awk parser mishandles, and the consolidator probed eight shapes with busybox awk in the running VM to settle them. The author reports the change as verified end to end in another session, and treats it as a stopgap: the upstream moby report is in progress. Findings below are limited to the script, the test, and the deployment glue.

## Important Issues

I1. **The dangling-record assertion reads a log path that exists only on Lima** — `bats/tests/k8s/airgap-image-load.bats:41` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro]

```bash
    run rdsudo grep 'still dangling' /var/log/docker.log
    refute_output
```

On Lima the docker conf carries no `LOG_DIR` (`pkg/rancher-desktop/backend/lima.ts:2014`), so the init script's default of `/var/log/docker.log` applies, and the file exists in the running VM.

On WSL, `pkg/rancher-desktop/backend/wsl.ts:1356-1359` writes `LOG_DIR` into the docker conf, and `pkg/rancher-desktop/assets/scripts/service-wsl-dockerd.initd:18` derives the log path from it, so dockerd logs to `docker.log` in the host log directory and the VM path is absent. bats `run` folds grep's stderr into `$output`, so `refute_output` fails on the error text. `local_setup` skips only the containerd engine, so the Windows moby arm reaches this test. Gemini rated this Critical; a test that cannot pass on one platform is Important.

```bash repro

load '/Users/jan/git/rancher-desktop/bats/bats-assert/load'

# WSL: dockerd logs to $LOG_DIR/docker.log on the host, so this path is absent

    run grep 'still dangling' /var/log/docker.log
    refute_output
}

# Lima: the file exists; no warnings means grep exits 1 with empty output

    run grep 'still dangling' empty-docker.log
    refute_output
}
```

```text repro-output

Fix: branch on the platform. `is_windows` (`bats/tests/helpers/os.bash:42`) and `refute_file_contains` (`bats/tests/helpers/utils.bash:83`) already exist. A single `refute_file_contains "$PATH_LOGS/docker.log"` would fail on Lima, where the host log directory has no `docker.log`.

```

**Outcome:** fixed, and the finding was larger than stated. The assertion could not pass on Lima either, because `rdctl shell` writes `Error: exit status 1` to stderr for a grep that matched nothing. The test now runs `grep -c` and asserts `0`.

## Suggestions

S1. **The awk fast path trusts three properties of `index.json` that no producer promises** — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:57` [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Claude Opus 5]

```awk
function split_manifests(line,   body) {
    body = line
    sub(/^.*"manifests":\[/, "", body)
    sub(/\][^]]*$/, "", body)
    return split(body, ENTRIES, /\},\{"mediaType"/)
}
```

The parser assumes one record, `"mediaType"` first in every entry, and `]}` after the array. Reordered keys under-count silently: with the first image present, nothing else loads. One entry per line, or a `]` in a value after the array, passes the census and hands `docker load` invalid JSON, which fails the k3s `start_pre`. Other shapes (pretty-printed, `urls`, `platform`, index-level annotations) parse or fall back; an unnamed entry is dropped [Claude Opus 5], costing only a dangling image. Every producer in use marshals from Go structs, so none trips these today, which caps this at Suggestion; Gemini rated the trailing-value case Important.

```sh repro
# index.json is the real one from the k3s v1.36.4 arm64 airgap archive (8 manifests).
sed -n "/^cat >\"\$WORK\/index.awk\" <<'AWK'\$/,/^AWK\$/p" docker-load-airgap-images | sed '1d;$d' > index.awk
python3 - <<'PY'
import json, collections
d = json.load(open('index.json'), object_pairs_hook=collections.OrderedDict)
def compact(o): return json.dumps(o, separators=(',', ':'))
r = collections.OrderedDict(d)   # entry keys reordered: digest before mediaType
r['manifests'] = [collections.OrderedDict([('digest', m['digest'])] + list(m.items())) for m in d['manifests']]
open('reordered.json', 'w').write(compact(r))
m = '{"schemaVersion":2,"mediaType":"%s","manifests":[\n' % d['mediaType']   # one entry per line
open('multiline.json', 'w').write(m + ',\n'.join(compact(e) for e in d['manifests']) + '\n]}\n')
t = collections.OrderedDict(d); t['annotations'] = {'note': 'built [ci]'}   # a ] after the array
open('trailing.json', 'w').write(compact(t))
PY
printf 'docker.io/rancher/mirrored-pause:3.10.2\n' > wanted
for f in index reordered multiline trailing; do
    printf '%-10s list=%s ' $f "$(awk -v mode=list -f index.awk $f.json | wc -l | tr -d ' ')"
    awk -v mode=filter -f index.awk wanted $f.json |
        python3 -c 'import json,sys; print("filter=valid(%d)" % len(json.load(sys.stdin)["manifests"]))' 2>/dev/null || echo filter=INVALID
done
```

```text repro-output
index      list=8 filter=valid(1)
reordered  list=1 filter=valid(0)
multiline  list=8 filter=INVALID
trailing   list=8 filter=INVALID
# identical under busybox awk 1.37.0 in the VM and BWK awk 20200816 on macOS,
# and for five more shapes (pretty-printed, urls/platform, dup name, ] in an entry, trailing keys)
```

Fix: fail closed, with `|| load_everything` on both awk calls (lines 94, 121) so `set -e` does not fail the k3s start. All nine shapes tested: the real index and three benign variants pass, five bad ones fall back.

```diff
 {
+    if (FNR > 1 || $0 !~ /\]\}$/) exit 1
     n = split_manifests($0)
+    if (gsub(/"io\.containerd\.image\.name":/, "&") != n) exit 1
```

**Outcome:** declined for now. The guard was written, then reverted after two verification rounds each found fresh holes in it. Parser hardening is deferred to its own change.

S2. **`set -eu` diverges from the sibling script and leaves pipefail off** — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:10` [Claude Opus 5, Gemini 3.5 Flash]

```sh
set -eu
```

`pkg/rancher-desktop/assets/scripts/install-k3s:3`, the other `#!/bin/sh` helper deployed to the same VM, uses `set -o errexit -o nounset -o pipefail`, and the repo prefers long options in checked-in scripts. With pipefail, a `zstd` failure sets the status of `decompress | docker load` (line 25) and of the repack at line 123 directly, instead of relying on `docker load` rejecting truncated input, which it does. Line 32 already guards its pipeline with `|| true`. Busybox ash accepts the option, and `install-k3s` proves it in production.

Fix:

```diff
-set -eu
+set -o errexit -o nounset -o pipefail
```

**Outcome:** fixed as proposed.

S3. **The comment overstates what the filtered archive saves** — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:116-117` [Claude Opus 5]

```sh
# Load only the missing images by dropping the rest from index.json; the
# blobs all stay, since docker ignores any that no kept manifest references.
```

containerd's importer ingests every `blobs/` member through `onUntarBlob` (`core/images/archive/importer.go`, the `default:` arm of the member switch) before it reads the index; blobs no manifest references end up unnamed and eligible for garbage collection. Here the dropped entries belong to images already in the store, so their blobs deduplicate on ingest, and the partial path still streams the whole archive through `docker load`. What it saves is the re-tag that creates the dangling record, and the comment should say so.

Fix: "the blobs all stay; docker ingests them and leaves any that no kept manifest references unnamed."

**Outcome:** fixed, with the wording adjusted. The blob claim was verified against containerd's `core/images/archive/importer.go`, whose member switch special-cases only `oci-layout` and `manifest.json`.

S4. **A daemon warning on stderr silently skips the only regression assertion** — `bats/tests/k8s/airgap-image-load.bats:37` [Claude Opus 5]

```bash
    run -0 ctrctl info --format '{{.Driver}}'
    if [[ ${output} != "overlayfs" ]]; then
```

`run` merges stderr into `$output`, and `docker info` prints daemon warnings such as `No swap limit support` there on kernels without that cgroup controller. Any such line makes the comparison fail and the test skips, which a green run never shows. The VM here printed a bare `overlayfs`, so this is defensive. `bats/tests/containers/platform.bats:27` already uses `run --separate-stderr` for the same reason.

Fix:

```diff
-    run -0 ctrctl info --format '{{.Driver}}'
+    run -0 --separate-stderr ctrctl info --format '{{.Driver}}'
```

**Outcome:** fixed, folded into the shared `assert_no_dangling_records` helper.

S5. **The BATS workflow's default Kubernetes version ships a legacy archive, so a dispatched run exercises only the fallback** — `bats/tests/k8s/airgap-image-load.bats:3` [Claude Opus 5]

```bash
local_setup() {
    if ! using_docker; then
        skip "dangling image records only occur in the moby containerd image store"
    fi
}
```

`.github/workflows/bats.yaml:96` defaults `KUBERNETES_VERSION` to 1.22.7, and `.github/workflows/bats/get-tests.py` hands that version to the moby arm. Range requests today show the k3s v1.22.7 and v1.32.5 archives in the docker-save layout (`<id>/json`, `<id>/layer.tar`) and v1.32.7 as the first OCI layout. With a legacy archive the script loads everything, moby recreates the dangling records, and the last assertion fails. The local default is 1.32.7 (`bats/tests/helpers/defaults.bash:193`), so manual runs pass. The workflow is `workflow_dispatch` only in this repo, so the exposure is a dispatched run with the default input; Claude rated it Important. Later patch releases of older minors may also carry the new layout; only the 1.32 boundary was checked.

Fix: skip when the archive predates the layout, or raise the workflow default.

```bash

        skip "k3s airgap archives before v1.32.7 have no index.json"
    fi
```

**Outcome:** fixed, but not as proposed. No version predicate can express this, since k3s backported the layout switch across branches on one date (v1.30.14+k3s1 is docker-save, v1.30.14+k3s2 is OCI). The test detects the layout by reading the archive in the VM.

## Design Observations

### Concerns

- **The partial-load path is most of the script and is where every parser assumption applies** `(in-scope)` [Claude Opus 5]. `split_manifests`, `restore`, filter mode, and the extract-and-repack at lines 118-123 (about 60 of 123 lines) run only when some images are present. Dropping them (census, compare, load everything when anything is missing) keeps the two common cases identical and returns the partial case to today's behaviour, at the cost of recreating dangling records for unchanged images on every k3s upgrade. How long this workaround has to outlive the upstream fix decides the trade.
- **A real JSON parser is one binary away on Lima and two on WSL** `(future)` [Consolidator]. `lima-guestagent yq` is mikefarah yq v4.53.2 and handles every shape in S1; the census and the filter are one expression each. WSL has no equivalent: `wsl-helper` embeds no yq, and neither guest image ships jq or python3 (the Lima VM has 141 apk packages, busybox only; Alpine's jq package is 151 KB and would need releases of alpine-lima and the WSL distro). Embedding yq in `wsl-helper` the way Lima's guest agent does would let one parser-free script serve both backends.
- **Records from earlier sessions outlive the fix** `(future)` [Consolidator]. `docker image prune` keeps a dangling record whose digest belongs to any container (`daemon/containerd/image_prune.go`, `filterImagesUsedByContainers`), so a user upgrading with records already present keeps the warnings for the images their pods use until a reset with image deletion or the upstream fix. The author treats the change as a stopgap with an upstream report in progress.

### Strengths

- **Every parse failure funnels into `load_everything`** `(in-scope)` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]. Lines 33, 97, and 114 catch a missing index, an empty census, and an all-missing store; pretty-printed JSON, an un-annotated index, and a legacy archive all take the fallback.
- **The digest comparison distinguishes a present image from a tag whose content changed** `(in-scope)` [Codex GPT 5.6 Sol]. A tag that moved gets re-imported; only a tag at the same target is skipped.
- **Both backends write the helper in the same action as the k3s init script** `(in-scope)` [Codex GPT 5.6 Sol, Claude Opus 5]. The pair cannot drift, and `/usr/local/bin` is on the init script's PATH, as the existing unqualified `nerdctl` call shows.
- **The header comment states the mechanism as moby implements it** `(in-scope)` [Claude Opus 5, Consolidator]. `LoadImage` runs `ensureDanglingImage` for every archive image whose name exists (`daemon/containerd/image_exporter.go:273-277`), and `collectRepoTagsAndDigests` logs the warning on every inspect (`daemon/containerd/image_inspect.go:156`).

## Review Process Notes

### Skill improvements

- Where a test finding's severity turns on a CI workflow's default input, read the workflow's `on:` block before rating it: a defect reached only through a dispatch-only workflow's default is latent, while the same defect in a scheduled or pull-request workflow breaks every run.

### Repo context updates

- [repo] dockerd logs to `/var/log/docker.log` inside the Lima VM but to `docker.log` in the host log directory on WSL: `service-wsl-dockerd.initd` derives its log path from the `LOG_DIR` that `wsl.ts` writes into the docker conf, and `lima.ts` writes no `LOG_DIR`. A BATS assertion on the docker log needs a platform split: `is_windows` reads `$PATH_LOGS/docker.log` on the host, other platforms grep inside the VM.
- [repo] The guest images ship busybox only: the Lima VM has no jq, python3, or gawk, and `lima-guestagent yq` (mikefarah yq v4) is its only JSON parser; WSL has none, since `wsl-helper` embeds no yq. A guest-side script that parses JSON must use busybox awk or sed and fall back to the full operation on any shape it does not recognise.
- [repo] The BATS workflow is `workflow_dispatch` only and defaults `KUBERNETES_VERSION` to 1.22.7 for the moby arm, while the local BATS default is 1.32.7. k3s airgap archives switched from the docker-save layout to the OCI layout (`index.json`, `oci-layout`, `blobs/`) at v1.32.7, so a test that depends on the archive format needs a version guard.
- [repo] With moby's containerd image store, `docker load` of an image whose tag already exists creates a `moby-dangling@<digest>` record (`LoadImage` calls `ensureDanglingImage`); when the target is unchanged the record stays, and every inspect logs "multiple images have the same target, but one of them is still dangling". `docker image prune` keeps such a record while any container uses that digest.

# Deep Review — PR #10901: Skip loading airgap images that are already present

### Executive Summary

The change replaces the unconditional `docker load` of the k3s airgap archive with a shell helper that parses the archive's `index.json`, compares each entry's digest against `docker image inspect`, and loads only what is missing. The core script is sound — I ran it end to end under both busybox and GNU/BWK toolchains and against the real k3s v1.36.4 archive. The headline problem is the new BATS suite: its log-path assertion is Lima-only, and the CI configuration it runs under never reaches the new code path.

#### Important Issues

**I1. The dangling-record assertion reads a log path that only exists on Lima** — `bats/tests/k8s/airgap-image-load.bats:41-42` (important, regression)

```bash
    run rdsudo grep 'still dangling' /var/log/docker.log
    refute_output
```

On macOS/Linux the Lima VM runs Alpine's `docker` service, which defaults to `/var/log/docker.log` — I confirmed the file exists in the live VM and already holds 60 `still dangling` lines on an unfixed build. On Windows, `wsl.ts:1355-1359` writes its own `/etc/init.d/docker` from `service-wsl-dockerd.initd` and passes `LOG_DIR: logPath` (the wslified `paths.logs`); `service-wsl-dockerd.initd:18` then resolves the log to `${logPath}/docker.log`. `/var/log/docker.log` does not exist there, so `grep` writes `No such file or directory` to stderr, which bats `run` folds into `$output`, and `refute_output` (line 42) fails. The suite is not skipped on Windows — `local_setup` (lines 4-6) skips only the containerd engine.

Unproven: no Windows host available; the path divergence is established from `wsl.ts:1313`/`service-wsl-dockerd.initd:18` and from the absence of `docker.log` under `$PATH_LOGS` on this macOS install.

Fix:

```diff
-    run rdsudo grep 'still dangling' /var/log/docker.log
-    refute_output
+    if is_windows; then
+        # WSL writes dockerd's log into the host log directory (LOG_DIR).
+        refute_file_contains "$PATH_LOGS/docker.log" 'still dangling'
+    else
+        run rdsudo grep 'still dangling' /var/log/docker.log
+        refute_output
+    fi
```

`refute_file_contains` already exists (`bats/tests/helpers/utils.bash:83`), as does `is_windows` (`bats/tests/helpers/os.bash:42`).
