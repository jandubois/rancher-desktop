Review Process Notes ¶

Skill improvements

  • When a review's changed files are build or bundler configuration, verify findings by running the build and inspecting the emitted artifact rather than reasoning from the config alone. Bundler semantics depend on the interaction of target, output type, and externals in ways that are not legible from the diff, and the resulting defects ship silently because the build still succeeds. Where a finding claims a package is or is not correctly handled, build once and read the artifact — a single build settles claims that would otherwise need a clarification round.
  • Treat an agent's report of its own verification run as a claim to check, not evidence, whenever the same report also states an environment limitation that would prevent that run. Reviewers routinely describe a reproduction they could not have executed; reconcile against your own run or label it unverified before repeating it.
  • When a review agent's output describes work it performed on the codebase ("we added tests", "I fixed"), check whether it modified its worktree. A review agent that writes code has stopped reviewing the change and begun reviewing its own edit, and its coverage claims no longer describe the PR. Verify with git status in the agent's worktree before accepting its Coverage Summary.

Repo context updates

  • [repo] The webpack main-process config externalizes packages by testing the request's package name against one package.json section. package.json also declares optionalDependencies (native or platform-specific packages), which electron-builder ships as production dependencies and which app code loads at runtime. When reviewing changes to the externals predicate, check every runtime manifest section, not just dependencies — a native package omitted from the predicate is bundled, its binding fails to load, and packages that wrap the load in try/catch degrade to an empty module with no error.
  • [repo] webpackPreloadConfig is derived from webpackConfig through _.merge, so any change to the main config's externals, experiments, or output is inherited by the preload build, which targets electron-preload with a CommonJS library type. When reviewing a change to the main webpack config, check what it does to the preload build — the two targets disagree on module format, and the preload graph is small enough that an incompatibility stays latent until someone adds an import.
