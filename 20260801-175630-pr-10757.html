Executive Summary ¶

Round 1's recheck fix works: delegations age out, published ports get re-asserted, and four of five mutations I applied to the new code were caught. The gap sits in reassert's error handling. It cannot finish a repair it starts: when the wsl-proxy notification fails after a successful expose, every later recheck gets the sentinel and never resends, so the port stays unreachable from Windows.

Two reviewers found different failure modes in the same six-line function, and I reproduced both against a model of gvisor-tap-vsock v0.8.9's mux. The other two reviewers returned clean. Eight suggestions follow, most of them test gaps around the new recheck path.

I1. A failed wsl-proxy notification during a re-assert can never be retried Codex GPT 5.6 Sol¶

// logAddFailure emits the first publish-failure message for port at
// Error level and subsequent messages at Debug. addErrorLogged
// resets when publish succeeds or when the sweep at the end of Tick

APITracker.Add exposes the port, writes portStorage, then notifies wsl-proxy, so a Send failure returns an error with the first two steps already done. reassert logs it and keeps the port in published. Every later recheck finds the proxy standing, so Add returns the sentinel and skips the notification block. wsl-proxy never learns the port, and portproxy applies each message as a delta with no resync, so the port stays unreachable from Windows.

It triggers when a lost expose (a host-switch restart, or RemoveAll on an engine reconnect) coincides with a wsl-proxy hiccup, and those restarts correlate. This is a gap in the new recovery path; the merge-base failed the same way.

Fix: let Add resend for an expose already in portStorage, and hold the recheck due until both sinks succeed.

I reproduced it: the second Add returns the sentinel and sends nothing.

Documented. A rollback in reassert was drafted and probed; it unexposed a live port on any Expose blip and reached the same stuck state, so it was reverted. reassert's doc comment now marks the re-assert best-effort and gives the reason.

Design Observations ¶

Concerns ¶

  • RemoveAll unexposes every port as TCP (future, pre-existing) Claude Opus 5 — apitracker.go:248-251 builds types.UnexposeRequest without Protocol, while Remove sets it, and gvisor-tap-vsock v0.8.9 defaults an empty protocol to TCP on /unexpose (ports.go:336-338). Every engine reconnect therefore logs an unexpose error per UDP port, leaves the UDP proxy running, and clears portStorage regardless. Round 1 recorded this; this round supplies the consequence, since it is the mechanism behind S1. Fixing it here closes the class instead of patching reassert.
  • The sentinel is a whole-request aggregate (in-scope) Claude Opus 5 — Add returns it only when no binding was forwarded, so a port with one delegated and one fresh binding returns nil and lands in published with a partial record. The conservative choice is right and unpublish stays consistent, but nothing records the partial delegation.
  • Textual conflict detection carries no ownership lifecycle (future) Codex GPT 5.6 Sol — Tracker.Add folds expose, storage, and notification into one error value. A result describing each postcondition would let callers reconcile state instead of inferring it, and would close I1 at the contract rather than at the call site.

Strengths ¶

  • The state machine holds under tracing (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.1 Pro — published and delegated stay disjoint, every exit from either loop deletes the matching recheckTicks entry, and an expired delegation that then hits a real publish error re-enters pending through the end-of-Tick rebuild, so it retries per tick as before.
  • The recheck interval derives from the scan interval (in-scope) Claude Opus 5 Gemini 3.5 Flash — main.go:48's 3 s yields exactly 100 ticks, and TestOwnershipRecheckDerivedFromScanInterval pins the derivation rather than the number, so changing the cadence cannot silently turn the re-probe back into a per-tick retry.
  • All six engine conversions preserve their prior control flow (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.1 Pro Gemini 3.5 Flash — each switch keeps its continue on the real-error arm, and docker's initializeRunningContainers falls through to the loopback DNAT rules on the sentinel, which is the deliberate change its comment documents.

Review Process Notes ¶

Skill improvements ¶

  • When a change adds a periodic repair or reconciliation path, check whether the repair can tell "nothing needed doing" apart from "I could not finish". Repair paths commonly probe a remote system and treat one benign-looking reply as success, when that same reply is also what a half-applied repair returns. Where the two are indistinguishable, a transient fault becomes permanent, because every later pass reads the damaged state as healthy. Ask what the repair would log and retry if it ran a second time against the state its own partial failure left behind.
  • When a test asserts on a call count, check whether it also pins the call's arguments. A count-only assertion passes when the code calls the right function the right number of times with the wrong key, which is the standing failure mode for identifier-derivation helpers shared by several call sites: the derivation drifts in one site and the object is created under a name the cleanup path never looks for. Flag a count-only assertion on any call whose key is computed rather than passed in.

  • [repo] UPDATE the APITracker partial-failure entry. Its parenthetical — "portAlreadyExposedSubstring exists only on the unmerged procnet-* branches; at HEAD the raw error text is all there is" — goes stale when this work merges. APITracker.Add then classifies the host-switch "proxy already running" reply into the typed sentinel tracker.ErrPortAlreadyExposed, returned when every expose the call attempted reported the port already bound and nothing else failed. Both facts produce the same state — the gvisor proxy alive with no tracker record — which nothing can rebuild, since a re-Add for that port answers with the already-exposed sentinel and stores nothing.
