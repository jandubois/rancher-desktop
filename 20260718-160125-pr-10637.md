## Suggestions

S1. **Tray "None found" context label keeps the prior locale on a live switch** — `pkg/rancher-desktop/main/tray.ts:204` [Codex GPT 5.6 Sol]

```ts
    this.offLocaleChange = onLocaleChange(() => this.updateMenu());
```

The new locale callback calls only `updateMenu()`, which rebuilds the top-level labels but refreshes the contexts submenu solely through `updateContexts()` — reached only in the `STARTED`/`DISABLED` branch (`tray.ts:346`). Switching locale while Kubernetes is stopped, starting, stopping, or in error leaves the empty-submenu label `t('tray.noneFound')` (`tray.ts:435`) in the previous language until a state or kubeconfig event refreshes it. Context names are user data, so only the "None found" empty-state label is affected, and it self-heals on the next state change. This is a gap in the PR's new tray live-switch wiring, not a regression (the callback is added here). No impact until a non-English locale ships.

Fix:
```diff
-    this.offLocaleChange = onLocaleChange(() => this.updateMenu());
+    this.offLocaleChange = onLocaleChange(() => {
+      this.updateContexts();
+      this.updateMenu();
+    });
```

S2. **Extraction left visible English literals in files it edited** — `background.ts:432` [Codex GPT 5.6 Sol]

```ts
    applicationVersion: `Version ${ process.env.RD_VERSION }`,
```

The macOS About panel still hardcodes "Version" though `t` is imported (`background.ts:34`) and a `product.version` key exists. The same pass left the debug-mode tooltip in `pages/Troubleshooting.vue:107` ("Cannot be modified because the RD_DEBUG_ENABLED environment variable is set."), the file breadcrumb "root" in `pages/volumes/files/_name.vue:16`, and the `'(Never)'` placeholder in `components/DiagnosticsButtonRun.vue:25`. Each sits in a file this PR edited for extraction, and `i18n-report check` cannot flag them (they are literals, not referenced keys), so they stay English once other locales land. The commit message's "every hardcoded English string" overstates the coverage.

Fix: route each through a component-namespaced `t()` key, or narrow the commit claim.
```diff
-    applicationVersion: `Version ${ process.env.RD_VERSION }`,
+    applicationVersion: `${ t('product.version') } ${ process.env.RD_VERSION }`,
```

S3. **Diagnostics "Last run" timestamps ignore the selected locale** — `pkg/rancher-desktop/components/DiagnosticsButtonRun.vue:28` [Codex GPT 5.6 Sol]

```ts
        return this.currentTime.to(dayjs(this.timeLastRun));
```

The component extends Day.js with `relativeTime` but sets no locale, so the relative string ("2 hours ago") always renders in Day.js's default English. The tooltip (`timeLastRunTooltip`, line 34) calls `toLocaleString()`, which follows the OS locale rather than the app's selected locale. Both diverge from the language picker once non-English locales ship. Unlike S2's plain literals, this needs Day.js locale wiring — import the locale and call `dayjs.locale(...)` off `i18n/current` — rather than a `t()` call, so it is a larger, separate follow-up.

Fix: subscribe to `i18n/current` and drive both the Day.js locale and the tooltip formatting from it.

S4. **`data-navigate` split does not trim, so a translator's space drops the tab** — `pkg/rancher-desktop/components/Preferences/navigateClick.ts:16` [Claude Opus 4.8]

```ts
    const [navItem, tab] = nav.split(',');
```

Every current `data-navigate` value splits cleanly (`"Container Engine,general"`, `"Kubernetes"` — no spaces), but a translated `"Container Engine, general"` yields `tab = ' general'`, which opens the page yet fails to select the tab. That is a partial navigation, not the clean no-op the file's comment describes. Risk is low — the YAML comments tell translators to preserve the attribute verbatim — but a defensive trim removes the trap.

Fix:
```ts
    const [navItem, tab] = nav.split(',').map(s => s.trim());
```

## Review Process Notes

### Skill improvements

- When a finding argues that code should adopt a pattern used elsewhere — "sibling component X does it this way, so Y is wrong" — check whether the repository documents the pattern the finding wants to change as intentional before flagging it. A README section, design doc, or in-code comment that blesses the current pattern outranks an inferred "the other file shows the right way," and a single divergent sibling is as likely to be the exception as the rule. Grep the project's own docs for the pattern before recommending a rewrite.

### Repo context updates

- [repo] The `assets/translations/README.md` "Locale switching" section documents the intended pattern: labels captured in a component's `data()` — table headers and row actions — refresh only when navigation remounts the page, and `data()` capture is the accepted, preferred pattern over reactive `computed` plumbing for new tables. Do not flag a SortableTable whose `headers` or row-action arrays live in `data()` with `this.t()` labels as a live-locale-switch defect; it follows the documented convention. `DiagnosticsBody.vue` uses `computed` headers, but that is the exception, not the rule.

- [repo] UPDATE the i18n context line "The app ships en-us and zh-hans …": the inherited partial `zh-hans.yaml` (cluster-explorer keys only, never selectable) is deleted in this work, so after it merges only `en-us` ships. A real `zh-hans` returns in a later per-locale slice. Keep the plural-parity observation, but drop the present-tense claim that zh-hans ships today.
