## Executive Summary

Both round-1 Critical findings are fixed. The unit suite runs again, and group deselect targets the right containers. But the watcher change that keeps a group selection through a refresh reaches every table, and the two that rebuild their row objects each recompute now hold a selection whose checkboxes read unchecked. A bulk Delete there removes rows the user cannot see are selected. All four round-1 Important findings are untouched.

Findings group into the shared selection model (C1, I3), the group checkbox's three-state contract (I1, I3), presentation (I2), scope (I4), and cleanup (S1 through S7).

## Critical Issues

C1. **Key-based pruning strands stale row objects, so Images and Volumes delete invisible rows** — `pkg/rancher-desktop/components/SortableTable/selection.js:134` [Claude Opus 5, Codex GPT 5.6 Sol]

```js
      const toRemove = this.selectedRows.filter((node) => !contentKeys.has(get(node, this.keyField)));
```

At the merge-base this watcher compared object identity, and `for…of` over a reactive array yields proxies while `pagedRows` holds raw rows. The comparison was therefore always false, and the whole selection cleared on every recompute. Keying it fixes that for `Containers.vue`, which now also caches row objects. But `Images.vue:230` and `Volumes.vue:143` build a fresh wrapper per row on each recompute and have no such cache, so their selection keeps dead objects. The row checkbox renders from identity (`index.vue:1327`), so it reads unchecked while the header still counts the row and `applyTableAction` still deletes it.

```ts repro
// Volumes.vue-shaped rows through the real update()/watcher at both SHAs.
t.update([t.pagedRows[0]], []);      // user ticks vol-a
t.pagedRows = rebuild();             // a volume event rebuilds the rows
t.onPagedRowsChanged();
const afterRefresh = boxes(t);       // index.vue:1327: selectedRows.includes(row.row)
t.update([t.pagedRows[1]], []);      // user ticks vol-b
```

```text repro-output
merge-base | boxes after refresh: vol-a=false vol-b=false | header: "1 selected" | docker volume rm vol-b
review SHA | boxes after refresh: vol-a=false vol-b=false | header: "2 selected" | docker volume rm vol-a,vol-b
```

Fix: re-bind the selection to the current row objects instead of only pruning it. Identity then stays valid for every `includes()` in the module, and `_rowCache` becomes optional.

```diff
-      const contentKeys = new Set(content.map((row) => get(row, this.keyField)));
-      const toRemove = this.selectedRows.filter((node) => !contentKeys.has(get(node, this.keyField)));
-
-      this.update([], toRemove);
+      const byKey = new Map(content.map((row) => [get(row, this.keyField), row]));
+      const rekeyed = this.selectedRows.map((node) => byKey.get(get(node, this.keyField))).filter(r => r);
+
+      this.selectedRows.splice(0, this.selectedRows.length, ...rekeyed);
+      this.$nextTick(() => this.$emit('selection', this.selectedRows));
```

## Important Issues

I1. **The indeterminate group state can never render** — `pkg/rancher-desktop/pages/Containers.vue:123` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash] (round 1 I1, unaddressed)


Re-verified against the shipped `@rancher/components@0.3.0-alpha.1`, unchanged by the merge that moved it to `devDependencies`. ## Design Observations

### Concerns

- **The selection module now mixes key-based and identity-based comparison (in-scope)** [Claude Opus 5, Codex GPT 5.6 Sol] — removal and pruning moved to `keyField`, but `toggle` (`selection.js:433`), `nodesBetween` (line 405), `onRowClick` (lines 282, 286), the row checkbox (`index.vue:1327`) and the page's `isGroupSelected`/`isGroupIndeterminate` all still compare object identity. `_rowCache` restores identity for exactly one of the three selection-enabled tables. Re-keying the selection in the watcher (C1) makes the two representations agree everywhere and forecloses the whole class.
- **Bulk Delete over a mixed group silently skips running containers (in-scope)** [Codex GPT 5.6 Sol, Gemini 3.5 Flash] — a bulk action is enabled when *any* selected row supports it (`selection.js:100`), then `applyTableAction` filters to the enabled subset (`selection.js:518`). Delete is enabled only for stopped containers, so selecting a running compose project deletes only its already-stopped members with no message. Codex rated this Important. It is pre-existing behaviour that this diff does not touch, and the fix is a product decision, so it stays an observation. The new e2e suite encodes the workaround: test 2 stops the project before test 3 deletes it.
- **`clearSelection()` splices the array it iterates (future)** [Claude Opus 5] — `selection.js:531` passes `this.selectedRows` as `toRemove`, and `update()`'s `forEach` walks that same array while splicing it, so roughly half the entries stay. No caller exists today, but it is the obvious helper a future bulk feature reaches for. Delete it or pass a copy.

### Strengths

- **`fullColspan - 1` corrects a latent off-by-one (in-scope)** [Claude Opus 5] — the merge-base group row used `headers.length + 1` = 6 against a 7-cell main row, because `fullColspan` (`index.vue:514`) also counts the row-actions column. The new `1 + (fullColspan - 1)` matches.
- **The padding exception sits in SortableTable's own stylesheet (in-scope)** [Claude Opus 5, Gemini 3.1 Pro] — `td:not(.row-check)` keeps the values in one place instead of duplicating them in the page, and its commit message says why. `DiagnosticsBody.vue` sets `table-actions="false"`, so it has no `.row-check` cell and is unaffected.
- **The `pagedRows` comment states a real and non-obvious fact (in-scope)** [Claude Opus 5, Codex GPT 5.6 Sol] — `for…of` over a reactive array does yield proxies, so the identity comparison it replaced could never match. Verified directly.
- **Reuses the whole bulk-action machinery (in-scope)** [Codex GPT 5.6 Sol] — a selection checkbox composes across groups, allows excluding individual containers, and applies to compose projects, Kubernetes pod groups and standalone containers alike.

## Review Process Notes

### Skill improvements

- When a change to a shared component is justified by one consumer's needs, enumerate the component's other consumers and check whether the change assumes something only the motivating consumer provides. A fix paired with a compensating change in one caller, such as a cache, a wrapper, or a normalisation step, is the signature. The callers that did not get the compensating change now run the new behaviour without its precondition.
- When a diff both changes a shared helper and adds a page-local workaround, ask which one is the real fix. If the workaround exists to restore an invariant the helper change broke, the fix usually belongs in the helper, and reviewing the two hunks separately hides that.
- Before rating a data-staleness finding, check whether the layer feeding the reviewed code already has the same staleness. A caching or merging bug that duplicates one already present upstream changes nothing a user can observe, and one probe against the upstream layer settles the severity.
- When a component already implements a three-state control (checked, unchecked, indeterminate) somewhere in the codebase, compare a new instance against that one before analysing the component's internals. A divergence from the established call pattern usually explains the defect faster than reading the component, and it supplies a fix the codebase already endorses.

### Repo context updates

- [repo] `pkg/rancher-desktop/store/container-engine.ts` updates its container map in place with `lodash/merge` (`containers[id] = merge(containers[id] ?? {}, info)`) so UI state survives a refresh. `merge` skips `undefined` sources and merges arrays element-wise, so `started`, `ports` and `labels` never shrink: a container that stops keeps its published ports and its start time in the store. Treat stale values in those three fields as pre-existing, not as a defect of whatever renders them.
- [repo] `SortableTable`'s selection is stored as row *objects* and rendered by object identity (`selectedRows.includes(row.row)`), while removal and pruning match by the table's `keyField`. ## Design Observations

### Concerns

**The selection module now mixes key-based and identity-based comparison, and this PR papers over the mismatch per-page** *(in-scope)*. Items 1 and 2 moved removal and pruning to `keyField`, but `toggle` (`selection.js:433`), `nodesBetween` (line 405), `groupIdx` (line 417), `onRowClick` (lines 282, 286), the row checkbox (`index.vue:1327`) and `Containers.vue`'s `isGroupSelected`/`isGroupIndeterminate` (lines 594, 599) all still compare object identity. `_rowCache` (item 6) restores that identity for exactly one of the three selection-enabled tables. The C1 fix — re-binding the selection to the current row objects in the watcher — makes the two representations agree for every consumer and removes the need for a per-page cache. It is a smaller change than three row caches and forecloses the whole class.

**`clearSelection()` splices the array it is iterating** *(future)*. `selection.js:531` passes `this.selectedRows` as `toRemove`, and `update()`'s `forEach` walks that same array while `splice`ing it, so roughly half the entries survive. `grep clearSelection` finds no caller today, so it is dormant — but it is the obvious helper a future group/bulk feature reaches for. Either delete it or pass `this.selectedRows.slice()`.

### Strengths

- `:colspan="fullColspan - 1"` (`Containers.vue:129`) silently corrects a pre-existing off-by-one: the merge-base `headers.length + 1` was 6 against a 7-td main row, because `fullColspan` also counts the row-actions column (`index.vue:531-533`).
- The `actions.js` change fixes a genuine null dereference rather than suppressing it, and keeps the guard at the level where the element can actually be missing.
- `6e3c1b8c6`'s decision to put the padding exception in `SortableTable`'s own stylesheet rather than duplicating the values in `Containers.vue` is the right call, and its commit message says why.
