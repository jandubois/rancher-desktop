## Suggestions

S1. **About-panel "Version" label is captured once at startup** — `background.ts:432` [Codex GPT 5.6 Sol]

```ts
    applicationVersion: `${ t('product.version') } ${ process.env.RD_VERSION }`,
```

`setAboutPanelOptions` runs once inside `initUI()` (`background.ts:427`), and `showAboutPanel()` (`mainmenu.ts:95`) only displays the stored options. The app menu's "About" label refreshes through `onLocaleChange(() => buildApplicationMenu())` (`mainmenu.ts:15`), but the panel body does not, so a live locale switch leaves "Version" in the startup language until restart. This is a gap in the PR's own live-switch wiring, not a regression: the pre-PR line was the literal `'Version ${…}'`, equally frozen at startup. It affects macOS only and carries zero impact until a non-English locale ships.

Fix: extract the options into a callback and register it with `onLocaleChange`.
```diff
-  Electron.app.setAboutPanelOptions({
+  const updateAboutPanel = () => Electron.app.setAboutPanelOptions({
     ...
   });
+  updateAboutPanel();
+  onLocaleChange(updateAboutPanel);
```

S2. **`openPreferences` re-registers the locale listener on every call** — `pkg/rancher-desktop/window/preferences.ts:95` [Claude Opus 4.8]

```ts
  const offLocaleChange = onLocaleChange(() => {
    window.setTitle(t('preferencesWindow.title'));
  });

  window.on('closed', offLocaleChange);
```

`createWindow` returns the existing window when preferences is already open (`window/index.ts:69`), yet `openPreferences` runs its tail again. The shortcut block above sits under `if (!Shortcuts.isRegistered(window))` (line 36); this `onLocaleChange` block does not, and `onLocaleChange` pushes without dedup (`main/i18n.ts:116`). Each re-open — from the tray or the app menu — adds another listener plus another `closed` handler. The impact is minor and self-healing: the extra `setTitle` calls are idempotent, and every listener is removed on `closed`. Not a regression: the merge-base already registered the sibling `ipc-message` and `close` handlers the same unguarded way; this PR adds one more.

Fix: move the registration under the existing one-time guard.
```diff
   if (!Shortcuts.isRegistered(window)) {
     Shortcuts.register(/* … */);
+    const offLocaleChange = onLocaleChange(() => {
+      window.setTitle(t('preferencesWindow.title'));
+    });
+    window.on('closed', offLocaleChange);
   }
```

##### S1. Safely handle empty string tabs in navigation utility — `pkg/rancher-desktop/components/Preferences/navigateClick.ts:15`

```typescript
    const [navItem, tab] = nav.split(',').map(s => s.trim());
```

If the translation has a trailing comma (e.g. `"Container Engine, "` or `"Kubernetes,"`), `tab` will resolve to an empty string (`""`) after splitting and mapping. Passing an empty string as a tab name to the internal `navigate` function might fail to match any tabs, whereas passing `undefined` correctly defaults to the page's primary tab.

Fix: Map empty string values to `undefined` during split and trim mapping.

```diff
-    const [navItem, tab] = nav.split(',').map(s => s.trim());
+    const [navItem, tab] = nav.split(',').map(s => s.trim() || undefined);
```
