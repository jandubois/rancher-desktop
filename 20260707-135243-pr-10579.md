## Important Issues

I1. **`untranslated --format=json` emits `null` for an empty result** — `report_untranslated.go:73-77` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

```go
if format == formatJSON {
    enc := json.NewEncoder(w)
    enc.SetIndent("", "  ")
    return enc.Encode(hits)   // hits is nil when empty → "null"
}
```

`findUntranslated` returns a nil slice when it finds nothing (`var hits []untranslatedHit`, appended only inside the loop), so an empty report serializes as the literal `null`. Every other report converts nil to an empty slice on purpose — `output.go:31`, `report_dynamic.go:69` (commented "output contains [] instead of null"), and this PR's own `report_translate.go:124`. `TestReportDynamicJSONListsAreNeverNull` locks that contract, yet this path breaks it with no equivalent test, so a downstream `jq length` or array iteration fails on `null`. Building the tool confirmed the `null` output.

Fix — guard before encoding, and add a test mirroring `TestReportDynamicJSONListsAreNeverNull`:

```go
if hits == nil {
    hits = []untranslatedHit{}
}
```

I2. **`untranslated` silently skips unreadable source files** — `report_untranslated.go:133-135` [Codex GPT 5.5, Gemini 3.1 Pro]

```go
data, err := os.ReadFile(file)
if err != nil {
    continue
}
```

A read error drops the file and the scan continues, so `untranslated` can exit 0 while omitting hardcoded strings from a file it never read. The shared scanner treats the identical condition as an operational failure: `scan.go:210` returns an error with the comment "An unreadable file could hide key references, so it is an operational failure (exit 2), not a partial result," and the README documents that exit-code split. This report should honor the same contract.

Fix — return the error instead of continuing:

```go
if err != nil {
    return nil, fmt.Errorf("reading %s: %w", file, err)
}
```

## Review Process Notes

**Skill improvements**

- When a finding predicts a program's observable output — a report includes or omits a value, a result serializes as `[]` versus `null`, a command exits with a specific code — build and run the program against the real tree to observe the actual bytes before assigning severity, instead of tracing the logic statically. Execution is cheaper and more decisive than reasoning through a chain of regexes or branches, and it separates a latent risk from a live defect: a pattern that "could" match a key may match nothing in the actual codebase, which is the difference between an Important bug and a low-priority nit.

**Repo context updates**

- [repo] The `src/go/i18n-report` CLI holds a package-wide output contract: every report's JSON form must serialize an empty result as `[]`, never `null`, enforced by `TestReportDynamicJSONListsAreNeverNull` and by nil→empty-slice guards in `output.go`, `report_dynamic.go`, and `report_translate.go`. When reviewing a new or changed report in this package, confirm each JSON-emitting path guards its slice before `json.Encode`. This is the tool's own output invariant, distinct from the moby/nerdctl `T[] | null` runtime divergence already in this file.
- [repo] The same package treats an unreadable source file as an operational failure (exit 2), documented in `scan.go` and the README exit-code section. A new file-walking report that `continue`s past a read error rather than returning it breaks that contract — flag it.
- [repo] The i18n-report work ships as a stack of PRs (group 1 = #10107, group 2 = #10579, later groups after), each targeting `main`. Until a parent merges, a child PR's diff carries the parent's commits, so the reviewed surface is wider than the child's own change. Attribute findings in already-reviewed base files (the scanner, YAML loader, output helpers) to the parent PR, and concentrate severity on the child commit's new files.

**C1. Comment parser incorrectly splits on the letter "n" instead of a newline** — `src/go/i18n-report/yaml.go:88`

**S1. `boundLiteralPattern` misses double-quoted bound literals** — `src/go/i18n-report/report_untranslated.go:34`
