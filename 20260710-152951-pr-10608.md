## Executive Summary

This well-contained PR adds `merge` and `remove` commands plus `translate` improve/drift modes to the i18n-report CLI, with strong test coverage. All three reviewers independently found one Important bug: the text-merge and `remove`-pipe input gate (`isValidDottedKey`) rejects the quoted dotted-segment key form the tool itself emits, silently dropping the ~24 `kubernetes.io/*` secret-type keys the PR's own dot-quoting fix was meant to protect. The JSON path is unaffected.

All three agents converged on that single bug (I1) from independent angles — Codex and Claude via the merge/remove call chains, Gemini via the validator's charset — and I reproduced it end-to-end against a built binary. The remaining items are one small robustness gap and three test/coverage suggestions. No security, concurrency, or data-corruption issues in the write path itself, which is carefully guarded.

## Important Issues

I1. **`isValidDottedKey` rejects the quoted dotted-segment key form → text-merge and `remove`-pipe silently drop secret-type keys** — `src/go/i18n-report/yaml.go:192-208` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

```go
func isValidDottedKey(s string) bool {
    parts := strings.Split(s, ".")   // naive split; no quoted-segment awareness
    ...
        if (c < 'a'...) && ... && c != '_' && c != '-' {  // forbids '/', '.', '"'
            return false
```

`en-us.yaml` nests ~24 secret-type labels under keys whose own segment holds a dot (`kubernetes.io/service-account-token`, `bootstrap.kubernetes.io/token`, lines 3121-3144). `translate`, `stale`, and `unused` all emit the canonical quoted form `secret.types."kubernetes.io/service-account-token"` via `appendKeyPath`. But this validator splits on every `.` and allows only `[A-Za-z0-9_-]`, so `parseMergeInput` (`report_merge.go:409,417`) and `readKeysFromStdin` (`report_remove.go:118`) reject that form. `looksLikeEntry` (`report_merge.go:25`) also misses it, so no warning fires.

I reproduced end-to-end against a built binary: a text-format `merge` of `translate`'s own output wrote 1 of 3 keys, exit 0, no warning — the two secret-type keys vanished. Gemini rated this Critical; consolidated to Important because this is a maintainer-only CLI and the JSON path (`--format=json`) plus `remove --stale` work, but it is the must-fix item: silent, and it defeats the PR's own dot-quoting fix.

Fix: validate through the same tokenizer the write path uses.

```diff
-	parts := strings.Split(s, ".")
+	parts := splitKeyPath(s)
 	...
-		if ... && c != '_' && c != '-' {
+		if ... && c != '_' && c != '-' && c != '.' && c != '/' {
```

## Suggestions

S1. **`parseInputData` hard-fails when text input begins with `[`** — `src/go/i18n-report/report_merge.go:240-248` [Gemini 3.1 Pro]

```go
if len(trimmed) > 0 && trimmed[0] == '[' {
    if err := json.Unmarshal(trimmed, &pairs); err != nil {
        return nil, fmt.Errorf("parsing JSON array input: %w", err)

```

Any input whose first non-whitespace byte is `[` is committed to the JSON path; a raw text batch that opens with a note like `[WIP] ...` aborts with `parsing JSON array input: invalid character`. I reproduced this (exit 2). Impact is low — the failure is loud and writes nothing, and `translate` text output never starts with `[`. Gemini proposed falling back to text extraction on a JSON error; that has a downside (a genuinely-intended JSON array with a typo would then be silently mis-parsed as text and mostly dropped), so if changed, keep the failure loud. Downgraded from Gemini's Important on that basis.

S2. **`stripYAMLQuotes` decodes only `\"` and `\\` in double-quoted values** — `src/go/i18n-report/yaml.go:229-234` [Claude Opus 4.8]

## Design Observations

### Concerns

- **Two divergent key representations** (in-scope) [Claude Opus 4.8] — The write path (`splitKeyPath`/`appendKeyPath`, `yaml.go:23-46`) faithfully mirrors the renderer's `splitObjectPath`/`joinObjectPath`: quoted dotted segments, both quote styles stripped. The input-validation path (`isValidDottedKey`) uses a stricter, incompatible `[A-Za-z0-9_-]` charset with a naive `.`-split, and the JSON merge path bypasses validation entirely — which is exactly why JSON round-trips while text/stdin drop. Routing every key-shaped gate (`isValidDottedKey`, and ideally `looksLikeEntry`) through `splitKeyPath` collapses the two representations into one and forecloses the whole I1 class rather than patching one call site.

### Strengths

- **Serialize-then-atomic-write** (in-scope) [Codex GPT 5.5, Claude Opus 4.8] — `reportMerge` builds the full document in a buffer before `writeFileAtomic` (`report_merge.go:212-218`), so a serialization failure leaves the file untouched; co-located `@source` means one atomic write keeps a translation and its snapshot in sync.
- **`validateNoAliases` guardrail** (in-scope) [Codex GPT 5.5, Claude Opus 4.8, Gemini 3.1 Pro] — anchors, aliases, and sequences the custom serializer cannot round-trip are rejected before any mutation (`yaml.go:377-393`).
- **Minimal key quoting** (in-scope) [Claude Opus 4.8] — `keyRoundTripsPlain`/`yamlKey` quote a key only when the plain form would not survive a parse, so benign scalars like `yes` stay unquoted and checked-in locale files do not churn.
- **`applied`-only `@source` refresh** (in-scope) [Codex GPT 5.5, Claude Opus 4.8] — the refresh loop touches only keys this merge wrote, preserving drift markers on untouched translations (`report_merge.go:195-207`).
- **Mapping-overwrite refusal** (in-scope) [Gemini 3.1 Pro, Claude Opus 4.8] — `nodeSetLeaf` refuses to replace a populated mapping with a scalar, preventing accidental subtree erasure.
- **Graceful markdown-fence extraction** (in-scope) [Gemini 3.1 Pro] — `extractTranslationText` drops LLM prose around ```yaml fences, matching the agent-driven translation workflow.

## Review Process Notes

### Skill improvements

- When a change adds or modifies a tool that both **produces** a serialized identifier (a key path, ID, slug, or name) and **consumes** it back — including consuming its own output in a documented round-trip — verify the consumer accepts every form the producer emits. Read the producer's formatting/escaping/quoting routine and the consumer's parsing/validation routine side by side and confirm they share one grammar. A stricter validator on the read side silently drops or rejects values the write side emits, and such round-trip breaks are invisible in tests that exercise only one direction. Flag any validation gate that re-implements identifier parsing (naive `strings.Split`, a hand-rolled charset check) instead of reusing the canonical tokenizer the write path uses.

### Repo context updates

- [repo] The `i18n-report` tool (`src/go/i18n-report/`) carries two key-path representations that must stay in sync: the quote-aware write path (`splitKeyPath`/`appendKeyPath` in `yaml.go`, mirroring the renderer's `splitObjectPath`/`joinObjectPath`) and looser text-input validators (`isValidDottedKey`, `looksLikeEntry`) that split naively on `.` and restrict the charset. The JSON merge path bypasses validation entirely. When reviewing a change to any key-path gate, confirm it routes through `splitKeyPath` rather than a fresh `.`-split, and check the text and JSON input paths behave identically.
- [repo] `en-us.yaml` nests ~24 secret-type labels (lines ~3121-3144) under keys whose own segment contains a literal dot and a slash — `kubernetes.io/service-account-token`, `kubernetes.io/dockercfg`, `bootstrap.kubernetes.io/token`. These are the canonical stress-test keys for any i18n-report key-handling change; a round-trip that does not exercise them (text `translate`→`merge`, `stale`/`unused`→`remove`) leaves the highest-risk path uncovered.
