Executive Summary ¶

The DOWNLOADING → CHECKED transition correctly unwedges the updater, and its regression test drives a real timer through the scheduler. The staged-update half is incomplete: checking-for-update clears available before an error arrives, and only downloaded is restored, so the renderer receives {available: false, downloaded: true} and still hides Restart Now. That is the symptom the author reproduced in issue 7516.

Three of four reviewers found that gap independently. Two probe tests run against the PR's own harness confirmed it, plus a second symptom: a failed Retry hides the whole card.

Review Process Notes ¶

Skill improvements ¶

  • When a finding claims a UI element disappears, is disabled, or otherwise becomes unreachable, trace how it comes back before assigning severity. A state that a scheduled retry, a timer, or the next successful poll restores is a temporary defect; one that persists until the process restarts is a dead end. Reviewers routinely report the first as permanent, which inflates severity by a full level.
  • When an agent reports a concrete run result (a test count, a green suite, a built binary), reproduce it before repeating it, and use the project's own documented test command rather than invoking the runner directly. Test harnesses frequently require flags that the package script supplies, so a direct invocation can fail for reasons that have nothing to do with the code under review, and reporting that failure as a defect is worse than reporting nothing.

Repo context updates ¶

  • [repo] The updateState object that main/update/index.ts broadcasts to the renderer is mutated by several handlers in sequence, and only some of them call window.send. checking-for-update clears available, downloaded, and progress without sending, so the next handler that does send inherits those cleared fields. When reviewing a change to any single updater event handler, trace which earlier handler last mutated each field of updateState and whether it sent; a fix that repairs one field in the error handler can leave a sibling field cleared by checking-for-update, and the renderer gates on the sibling.
  • [repo] pkg/rancher-desktop/components/UpdateStatus.vue renders its card on updateState.available, not on downloaded or error. Any main-process change intended to keep part of the update UI visible has to keep available true as well, or the whole card unmounts and the change has no visible effect.
  • [repo] Jest suites in this repo must run through yarn test:unit:jest, which sets NODE_OPTIONS=--experimental-vm-modules. Invoking yarn jest or npx jest directly fails with "Cannot use import statement outside a module" or an internal paths-module error, neither of which indicates a problem with the code under review.
