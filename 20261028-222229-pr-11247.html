Executive Summary ¶

This PR ports three Windows diagnostic actions from rancher-desktop-2 into the BATS workflow and adds firewall and WSL capture. The wiring is sound, and the fork run produced every _diag file. The one fix needed before merge is in prose. Two ported comments describe rancher-desktop-2's Lima and gzip workload and its 2-vCPU runner, which this repo's Windows job does not have. The suggestions cover truncated tables, an exit status, and a minute of go run per Windows job.

Design Observations ¶

Concerns ¶

  • (in-scope) This repo has no evidence yet that the telemetry step does anything. Claude Opus 5.5 Gemini 3.5 Flash The PR body says Compatibility Telemetry "otherwise competes with the tests for CPU", which is rancher-desktop-2's measurement. On the fork's runner, both scheduled tasks that reference CompatTel were already Disabled, and the step logs only the state after its changes. Logging Get-Service DiagTrack and Get-Process CompatTelRunner before the changes would show whether the step acts. It also runs after the six-minute install of the CI build, while rancher-desktop-2 runs it before its job builds rdd. Outcome: fixed in c0bb399c2, a first step that logs CompatTelRunner and DiagTrack before the changes; the step stays where it is. The PR body now credits rancher-desktop-2's measurement. Fork run 40835438574 found no CompatTelRunner process, and DiagTrack already Stopped and Disabled, before the action ran.

Strengths ¶

  • (in-scope) The samplers write to diag/, and the consolidate step copies it into the artifact. Claude Opus 5.5 That keeps logs/ empty for --gather-test-outputs-in, which bats-core requires.
  • (in-scope) The BLG-then-relog capture records processes that start mid-run, at little cost. Claude Opus 5.5 Gemini 3.5 Flash typeperf's own counter averaged 0.43% of one core over the 108 samples in the fork run's TSV that have a value for it.
  • (in-scope) The history keeps the verbatim port apart from each change that this repo made. Each change can go back to rancher-desktop-2 as its own cherry-pick.

Testing Assessment ¶

These are CI-only scripts, so a test is optional, and none is missing. The BATS workflow does not run on pull requests. Fork run 40795379655 ran every new step at the head SHA on one Windows job: $/ resolved to the fork at that SHA, the WSL section filled, all three firewall rules printed, DiagTrack ended Stopped and Disabled, and the summary was written. Every check on the head commit passed except the two signing tests, which were skipped, and none of them runs the changed files.

The consolidator ran these: gofmt -l and go vet on the summarizer, clean; the summarizer on the staged TSV, matching the artifact's summary apart from its CRLF line endings; the I1 probe from the report, and the I1 patch, which applies and leaves the action parseable by yq; the S3 short-row and intact-row inputs; cold- and warm-cache timings for S4; and typeperf's CPU average from the TSV. PowerShell, typeperf and relog did not run, because the review host has no Windows.

No user-facing document describes the BATS artifact, so _diag/ needs none. I1 covers the two ported comments, S1 the firewall commit's body, and the telemetry concern the PR body's CPU claim.

Review Process Notes ¶

Skill improvements ¶

  • When a PR ports code from another project, check every ported comment, description and filter pattern against the destination repo's own architecture and runners, and put the facts that differ in the prompt. Prose that is true at the source passes a diff review, because nothing in the diff contradicts it.

Repo context updates ¶

  • [repo] UPDATE: the entry saying the Windows WSL distro "is provisioned with only curl and util-linux" is stale. bats.yaml's "Windows: Install prerequisites in WSL" step installs curl netcat-openbsd openssl util-linux.
  • [repo] rancher-desktop-2 shares this repo's GitHub-hosted runners and several CI composite actions, but its Windows CI code assumes Lima, MSYS2 and the RDD_ variable prefix. This repo runs a WSL distro under %LOCALAPPDATA%\rancher-desktop and uses RD_. When a PR ports an action or script from rancher-desktop-2, check each comment, environment filter and path against this repo's Windows backend.
  • [repo] Only macOS splits a suite into one job per file (SPLIT_PER_FILE_ON_MAC in .github/workflows/bats/get-tests.py). Linux and Windows run one job per suite directory and engine, 24 each in a full run; use that count when sizing a per-job cost.
