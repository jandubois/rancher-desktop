## Executive Summary

The PR closes the sudoers injection from #11137 by requiring IPv4 addresses in `networks.yaml`. It refuses shell syntax in the TMPDIR and HOME paths of the root command, and makes sudo-prompt escape `$`, backticks and backslashes. RD's root commands behave as before. This round converged; the three suggestions are optional, and the most useful one validates exactly the two networks that `sudoersFile` reads. A same-user attacker can still swap the temporary sudoers file before root copies it.

## Suggestions

S1. **The address check mishandles a missing or null network entry** — `pkg/rancher-desktop/backend/lima.ts:209` [Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```ts
    if (network.mode !== 'host' && network.mode !== 'shared') {
```

A null entry such as `extra:` throws a TypeError here. The outer `catch` logs "not yaml-parsable", skips the `.orig.yaml` backup, and the defaults overwrite the file, so a custom subnet that the merge-base kept is lost. A missing `host` or `rancher-desktop-shared` entry, or one with the wrong mode, passes the check and then throws in `sudoersFile`, as it did at the merge-base.

Checking exactly the two networks that `sudoersFile` reads fixes both. With the change below, a missing, null or bridged-mode `host` resets to the defaults with a backup, a null `extra:` entry keeps the custom subnet, all 10 tests in `lima.spec.ts` pass, and `tsc -p tsconfig.jest.json` passes. Other host or shared networks never reach the sudoers file. The docstring's "every host and shared network" needs the same narrowing.

Fix: return false unless both networks exist with the expected mode.

```ts
  const host = config.networks?.['host'];
  const shared = config.networks?.['rancher-desktop-shared'];

  if (host?.mode !== 'host' || shared?.mode !== 'shared') {
    return false;
  }

  return [host, shared].every(network => [network.gateway, network.dhcpEnd, network.netmask].every(addr => typeof addr === 'string' && net.isIPv4(addr)));
```

S2. **The tests corrupt only the host netmask** — `pkg/rancher-desktop/backend/__tests__/lima.spec.ts:38` [Claude Opus 5.5]

```ts
    netmask: "255.255.255.0\\nALL ALL=(ALL) NOPASSWD: ALL, \\\\\\n/private/var/run/socket_vmnet.host,"
```

I narrowed `hasValidNetworkAddresses` two ways in the lead worktree: to check only `netmask`, and to check only `host`-mode networks. All 10 tests in `lima.spec.ts` passed both times. A later edit could therefore drop `gateway`, `dhcpEnd` or the shared network from the check and reopen the injection with CI green.

Fix: run the rename test over every network and field, for example an `it.each` over `host` and `rancher-desktop-shared` crossed with `gateway`, `dhcpEnd` and `netmask`. Each case writes a value with an embedded newline and expects the `.orig.yaml` rename.

S3. **A refused TMPDIR leaves the new temporary directory behind** — `pkg/rancher-desktop/backend/lima.ts:1225` [Claude Opus 5.5]

```ts
    const workdir = await fs.promises.mkdtemp(path.join(os.tmpdir(), 'rd-vmnet-install-'));
    const quotedWorkdir = quotePathForShell(workdir);
```

`quotePathForShell` throws after `mkdtemp` has created the directory and before the `finally` that queues `rm -fr`, so each refused start leaves an empty `rd-vmnet-install-*` directory. This happens only with a TMPDIR that the start refuses anyway, so the cost is clutter.

Fix: call `quotePathForShell(os.tmpdir())` before `mkdtemp`. The random suffix that `mkdtemp` appends is alphanumeric.

## Design Observations

### Concerns

- **A same-user process can still replace the sudoers content after validation** (future) [Claude Opus 5.5]. `createLimaSudoersFile` writes the rendered file to `$TMPDIR/rd-sudoers<tag>.txt` with mode 0644 (`lima.ts:1395`), and root copies it only after the user answers the password dialog. A process running as the user can rewrite the file in that window and install any sudoers rules, which bypasses the IPv4 check. The `vmnet.tar` that root extracts into `/opt/rancher-desktop` has the same window. Such a process can already raise the same dialog with its own command, so this does not cross a new boundary, but it means the PR is hardening against one reported vector. The `visudo -cf` check that the issue proposes would not close it, because the swap comes after rendering. Closing it needs root to verify a hash before installing, or to write the file itself.

### Strengths

- **Invalid files take the existing recovery path** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]. A file with a non-IPv4 address is renamed to `networks.orig.yaml` like any other unexpected `networks.yaml`, so users see one behaviour.
- **The escaping now covers sudo-prompt's outer Linux shell** (in-scope) [Claude Opus 5.5]. On Linux, the shell that `child.exec` starts used to expand `$` and backticks in the command before `pkexec` ran `bash -c`. The new `EscapeDoubleQuotes` hands them to `bash` unexpanded.
- **The escaping test runs a real shell** (in-scope) [Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. `index.spec.ts` feeds each escaped string to `/bin/sh -c` and compares the output with the input, so the test checks what the shell does with it.
- **`net.isIPv4` accepts only plain dotted quads** (in-scope) [Claude Opus 5.5]. It rejects leading-zero octets, IPv4-mapped IPv6 addresses and surrounding whitespace, so any value that passes is one that Lima's `net.IP` fields can parse.

## Acknowledged Limitations

- **`quotePathForShell` refuses a single quote instead of escaping it.** `installToolsWithSudo` already refuses any `'` in the whole command (`lima.ts:1141`, unchanged from the merge-base), so a HOME containing `'` failed the same way before this PR, and escaping `'` inside `quotePathForShell` would still trip that check. On macOS, TMPDIR is under `/var/folders` and does not contain the user name. Do not re-suggest escaping `'` here.
- **sudo-prompt's `package.json` does not set `"type": "module"`.** Webpack bundles the module into the main process and jest loads it as ESM. sudo-prompt's manual `test.js` and `test-concurrent.js` import it as `./`, a directory import that Node refuses with or without the field. A direct Node import of `index.js` only prints a `MODULE_TYPELESS_PACKAGE_JSON` warning, and the merge-base file already used ESM `export`. Do not re-suggest adding the field.
- **`quotePathForShell` accepts newlines.** A newline is literal inside both the double quotes around the path and the single quotes around the command. Do not re-suggest refusing it.

## Review Process Notes

### Skill improvements

- When a PR validates an input on its way to a privileged operation, trace the validated value to the point where the privileged side reads it. Flag any intermediate artifact (a temporary file, an archive, an environment variable) that the same attacker can modify after validation, and say whether the PR then closes the attack or only the reported input. A fix that leaves an equivalent path open is hardening, and the report should say so, because the author may answer the reporter differently.

### Repo context updates

- `[repo]` UPDATE: the jest tip about excluding `.claude/worktrees/` hardcodes the sudo-prompt exclusion. Tell the reader to copy every entry of `jest.config.js`'s `testPathIgnorePatterns` into the flag, because the flag replaces that list, and the sudo-prompt entry must stay narrow enough to keep sudo-prompt's own specs under `__tests__/`.
- `[repo]` A command passed to sudo-prompt's `exec` crosses different shell layers on each platform. On macOS it goes verbatim into a script that the bundled applet runs as root, and only the `cd` and `export` lines are escaped. On Linux the whole command is inside a double-quoted `bash -c` argument that a `/bin/sh` running as the user parses before `pkexec`. Review any value that reaches a root command against both layers.
- `[repo]` Any process running as the user can raise Rancher Desktop's administrator dialog with its own command, by running the bundled sudo-prompt applet with its own `sudo-prompt-command` file. A finding that a same-user attacker gains root once the user approves a prompt therefore does not cross a privilege boundary; rate it as hardening.


`quotePathForShell` checks `/["$`\\']/` (line 251) to block characters with special shell meaning inside double quotes.
