Executive Summary ¶

The PR adds an i18n-report validate subcommand and a hand-written ICU MessageFormat parser mirroring intl-messageformat 11, gating each translation on placeholder, plural/select, tag, href/data-*, @override, and @source parity. The parser is faithful: it parses the entire en-us corpus and already caught a latent runtime crash in zh-hans. Two regex checks misfire on the shipping corpus — literal angle-bracket prose reads as HTML tags, and repeated href attributes collapse to the last.

All three reviewers converged on the attribute-collapse bug (I1); Claude and Codex also caught the tag-prose bug (I2). Both were confirmed by running validate --locale=zh-hans against the live corpus. Gemini raised plural-branch rigidity as Critical; the tool produced zero branch-parity errors on the current locales, so this review reframes it as an in-scope design decision (see Design Observations) with one live manifestation. One Gemini finding — a claimed search-and-replace corruption of @override/@source strings — did not survive verification and was dropped as a false positive.

compareConstructs keys constructs by variable,keyword, so a message with two {count, plural, ...} blocks keeps only the last; a missing branch in the earlier block goes unreported. No current corpus string trips this, so the risk is latent. Fix: group into map[string][]icuConstruct and compare positionally, or consume matched constructs from the slices.

S2. checkICU re-parses each value three times Claude¶

checkICU parses en and locale for the syntax check, then checkPlaceholders and checkICUStructure each parse both again — six parseICU calls per key. Parse once and pass []icuNode down: performance is irrelevant for a CLI, but a single parse keeps the three call sites from drifting.

S3. The locale file is read three times per run Claude¶

validateLocale loads the locale through loadYAMLFlat, loadYAMLDocument, and loadSources — three reads and parses of one file. A single yaml.Node parse yields the flat values, the @source comments, and the override placement together.

S4. skipArgStyle ignores apostrophe quoting Gemini¶

skipArgStyle counts braces to find a typed argument's closing brace but, unlike parseText, does not skip apostrophe-quoted regions. A style with a quoted literal brace (e.g. {n, number, '{'}) would miscount depth. No corpus string exercises this and simple number/date styles rarely contain braces, so the gap is theoretical; align it with parseText's quote handling if typed styles grow.

Design Observations ¶

Concerns ¶

  • Exact ICU structural parity may reject valid locale-specific plurals (in-scope) Gemini — checkICUStructure requires a translation's plural/select constructs and branch labels to match English exactly. Exact parity is right for select (gender, boolean), but plural uses locale-specific CLDR categories: Chinese needs only other, Polish needs few/many. On the current en + zh-hans locales the tool reports zero branch mismatches because zh-hans mirrors English's branches. It does already flag one case: sortableTable.paging.generic, where the Chinese dropped the nested {count, plural} (Chinese does not inflect) and validate reports missing {count, plural, ...} construct. The sibling resource key kept the structure, so today the drop reads as an inconsistency worth surfacing — but adding a few/many language would turn exact parity into blocked correct translations. Decide whether plural structure should be exact or relaxed to exact-match labels (=N) plus other. Gemini rated this Critical; the live impact is a single construct, hence the reframe.
  • Tag and attribute checks bypass the parser they ship beside (future) Codex Claude — Placeholder and plural/select checks use the intl-messageformat-mirroring parser, but the tag and attribute checks use a separate regex tokenizer. That tokenizer cannot tell HTML from literal prose (I2), ignores ICU apostrophe quoting (a '<b>' literal counts as a <b> tag), and collapses repeats (I1). Routing tag detection through the ICU grammar, which already models <tag>…</tag> rich text, would fold three defects into one path. The I2 allowlist is the cheap step; the parser-integrated model is the direction.
  • @source errors bury the structural findings (future) Claude — On zh-hans today, validate prints 2373 errors, 2348 of them [source]; the 16 placeholder, 7 tag, and 2 ICU findings — including the runtime crash — are lost in the noise. A --check=<category> filter or per-category counts would surface the high-value findings during locale migration.

Strengths ¶

  • The parser faithfully mirrors intl-messageformat (in-scope) Claude Gemini — apostrophe quoting, '' collapse, and #-scoping (significant only inside the nearest plural/selectordinal, literal inside a nested select) all match formatjs.
  • The gate already earns its keep (in-scope) Claude — it flagged workload.validation.containerImage in zh-hans (容器{{name}, a doubled brace) that would crash intl-messageformat at runtime.
  • TestParseICURealCorpus pins the parser to the whole en-us corpus (in-scope) Codex Claude — a strong guard on the fidelity claim.
  • Co-located @source keeps provenance on the key (in-scope) Codex — no parallel metadata file to drift.

Testing Assessment ¶

The unit tests cover each check* helper well, and TestParseICURealCorpus guards parser fidelity. Gaps, highest-risk first:

  1. Multiple links / repeated href in one value (I1) — coverage stops at single-link changed href/dropped href, which is exactly why the collapse slipped through.
  2. Literal angle-bracket prose vs. real tags (I2) — no test feeds <Binary Data: {n} bytes> or <ip …> to checkTags.
  3. validateLocale/reportValidate end-to-end — aggregation, the @source check, override integration, error sorting, output format, and exit code are unexercised; only the individual helpers are tested.
  4. selectordinal and non-plural select structure — the parser supports both, but no test or corpus string covers them.
  5. extractDataAttrs and data-* preservation — no direct test, and the corpus carries no data-* attribute, so that whole path is untested against real data.

Documentation Assessment ¶

The README updates are accurate: the check list, the file-map row, and the exit-code paragraph all include validate. One gap: validate depends on the @source snapshots that i18n-report source writes, so a first run on an unmigrated locale (zh-hans today) reports thousands of [source] errors. Document the source-before-validate order, or ship the initial annotations with the feature. Codex

Acknowledged Limitations ¶

  • Parser handles a subset of ICU — icu.go:13-17 scopes out offset:N on plurals and typed-argument skeletons (style is parsed, then ignored). A string using offset: would fail the syntax check, but none exist in the corpus and TestParseICURealCorpus guards the en side. Consistent with the stated scope. Codex Claude
  • @source required on every translated key — report_validate.go:104-105 documents that the snapshot lives on the key, so the zh-hans flood reflects unmigrated locales, not a checker defect. Claude

Review Process Notes ¶

Skill improvements ¶

  • When a change adds a regex that extracts or classifies a token type (HTML tags, placeholders, identifiers, attributes) from free-form text, run it against the project's real data before trusting it. Two failure modes stay hidden until real data hits them: the pattern over-matches literal text shaped like the token, and a result map keyed by token name silently drops duplicate occurrences. Flag both.
  • When a change adds a check that enforces exact structural parity between a source artifact and a derived one, verify the derived form is allowed to match exactly. Derived forms often diverge legitimately along their varying dimension — locale (CLDR plural categories differ by language), platform, or version — so an exact-parity check rejects valid variants. Flag parity checks that assume the derived form must structurally mirror the source.

Repo context updates ¶

  • [repo] Rancher Desktop's translation corpus (pkg/rancher-desktop/assets/translations) uses angle brackets for literal display text (<Binary Data: N bytes>, <ingress-name>), not only HTML. Real HTML tag names in the corpus are limited to a, b, br, code, li, p, pre, span. A tool that treats every <word> as an HTML tag produces false positives.
  • [repo] The app ships two locales, en-us and zh-hans; zh-hans mirrors English's ICU plural branch structure (keeping never-selected branches) rather than using native CLDR categories. Exact plural-structure parity passes on the current corpus but would block correct translations once a few/many language is added.
  • [repo] The i18n-report validate subcommand depends on @source snapshots that i18n-report source writes onto each translated key; running validate on a locale not yet processed by source floods the output with [source] errors.
