This PR replaces the manifest's per-dependency `checksums` map with an `assets` list, where each artifact carries its own platform, arch, url, and checksum, so the install path selects and verifies an asset without reconstructing URLs. It adds `rddepman --regenerate`. The refactor is thorough, correct, and well unit-tested; every dependency class was converted and selectors resolve to exactly the manifest's assets. The one notable issue is a dropped commit-SHA validation for the Moby spec.

## Important Issues

I1. **Dropped commit-SHA validation for the Moby spec** — `scripts/dependencies/moby-openapi.ts:99-106` [Codex GPT 5.5, Claude Opus 4.8]

```ts
async getAssets(version: MobyOpenAPISpecVersion): Promise<DependencyAsset[]> {
  const fileName = `v${ version.apiVersion }.yaml`;
  const url = `https://raw.githubusercontent.com/${ this.githubOwner }/${ this.githubRepo }/${ version.commit }/api/docs/${ fileName }`;
  return [{ platform: 'linux', url, checksum: await downloadAndHash(url) }];
}
```

The old `download()` rejected a `mobyOpenAPISpec` entry whose `commit` was not a 40-char SHA (merge-base `moby-openapi.ts:32`). The new `download()` reads `asset.url` directly and never inspects `commit`, and `parseVersion` (`dependencies.ts:206-222`) only checks that `commit` is a string. So `--regenerate` builds the URL from `version.commit` and pins a checksum to it: a hand-edited mutable ref (`commit: main`) records a digest against a moving target, and later upstream drift becomes an install-time checksum failure. The class documents manual commit edits as a supported path ("To adopt a new commit, edit dependencies.yaml manually"), so the misuse is reachable. Codex rated this important; Claude rated it a suggestion, noting the URL is authoritative at install and the commit is otherwise decorative.

Fix: restore the 40-hex check in `parseVersion` so every read — install and regenerate — rejects a non-SHA commit.

## Suggestions

S1. **Credential-helper guard checks count, not identity** — `scripts/dependencies/tools.ts:368-389` [Codex GPT 5.5]

```ts
const assets = selectAssets(context, this.name, { platform: context.goPlatform, arch });
const expected = DockerProvidedCredHelpers.helperNames[context.goPlatform];
if (assets.length !== expected.length) {
  throw new Error(`Expected ${ expected.length } ${ this.name } assets ... found ${ assets.length }.`);
}
```

The guard checks only the matching-asset count, then derives each destination name from the asset URL (`tools.ts:381-386`). A manifest carrying two `docker-credential-pass` assets and no `docker-credential-secretservice` passes the count check and installs `pass` twice, silently omitting `secretservice`. The old installer iterated each expected helper name and fetched that exact artifact (merge-base `tools.ts:375-385`), so it could not miss one — this PR weakens it to a count-only check. The trigger requires a corrupted manifest: `getAssets` always emits the correct distinct set, and this machine-generated file has no documented manual-edit path, so Claude traced the same code and judged the count-check adequate. Hence a suggestion, not important.

Fix: map assets by derived helper name and reject unless the set of names equals `expected`.

S2. **Speculative multi-config / manifestPath scaffolding (YAGNI)** — `scripts/rddepman.ts:42-44,355-367`, `scripts/lib/dependencies.ts:671` [Claude Opus 4.8]

```ts
const configs: Record<string, DependencyConfig> = {
  host: { manifest: globalDependencies, extras: getExtensions(true) },
};
```

`configs` holds a single `host` entry, yet `parseArgs` parses a positional argument to select among configs and throws on any other name (`rddepman.ts:355-367`), and `GlobalDependency.manifestPath` (`dependencies.ts:671`) is settable but never overridden. The docstrings point at a future guest `rdd/dependencies.yaml` that this PR does not add. The `manifest`/`extras` split earns its place (regenerate skips `extras`); the config registry, positional selection, and `manifestPath` override do not yet. Verified: `manifestPath` has no override, and the guest manifest appears only in a docstring.

Fix: keep the split; inline the single config and drop the positional lookup and `manifestPath` override until a second manifest lands.

S3. **Misleading `regenerateAssets` precheck comment** — `scripts/rddepman.ts:330-339` [Claude Opus 4.8]

```ts
// Every write rewrites the whole manifest, so the first regenerated sibling
// would drop the assets of a dependency skipped below.
for (const dependency of dependencies.filter(d => !d.regenerable)) {
  if ((await dependency.currentAssets).length === 0) { throw ... }
}
```

`updateManifest` reads the full manifest, replaces only its own entry, and writes it back (`dependencies.ts:681-688`), so a skipped dependency's assets are never dropped by a sibling's write — the stated mechanism does not occur. The guard's actual purpose: a non-regenerable dependency is skipped during regeneration, so if it already has empty assets (migrated from the old schema) the run emits a manifest that leaves it broken. The comment misstates why the check exists.

Fix: reword to state that a skipped dependency is never re-resolved, so empty assets here would survive into the output manifest; fail fast instead.

## Design Observations

**Strengths**

- **(in-scope)** The `AssetSelector` / `selectAsset` / `selectAssets` abstraction separates "which artifact" from "how to install it," and the exactly-one contract turns a silently-missing asset into a hard error at install time. [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]
- **(in-scope)** Every resolved URL is version- or commit-pinned (GitHub release assets, `raw.githubusercontent.com/<commit>`, versioned S3/chart paths) — no mutable refs, so upstream drift is caught by checksum rather than swapped in silently. [Claude Opus 4.8]
- **(in-scope)** `serializeAsset` fixes key order so the emitted YAML is deterministic regardless of how the asset object was built; the round-trip and structured-version tests lock this in. [Claude Opus 4.8]
- **(in-scope)** The extracted `cartesian` helper replaces several near-duplicate nested platform/arch loops with one matrix. [Gemini 3.1 Pro]

**Concerns**

- **(future)** The migration path is asymmetric: new code tolerates an old `checksums` entry by parsing it to `assets: []`, but `--regenerate` cannot fully migrate an all-old manifest — non-regenerable `electron` trips the precheck with empty assets and aborts before any dependency is rewritten. Moot post-merge (the committed manifest is already new-format and the tolerance is marked temporary), but relevant if the tool is ever pointed at a stale branch. [Claude Opus 4.8]

## Review Process Notes

**Skill improvements**

- When reviewing a refactor that relocates or restructures validation, enumerate the guards (format checks, required-field assertions, exact-identity lookups) present on the touched code paths at the merge-base and confirm each still fires after the change. A guard that existed before and is absent afterward is a regression even when no test fails and the happy path is unchanged — the check most often disappears when a value that was validated at its point of use becomes a pre-resolved field that later code reads blindly from a manifest or config. (Check whether the dimensions already ask for this before adding.)

**Repo context updates**

- [repo] `pkg/rancher-desktop/assets/dependencies.yaml` is machine-generated by `rddepman` and marked DO-NOT-EDIT. When a finding's only trigger is a malformed or inconsistent manifest, calibrate severity by whether a manual-edit path is documented: most dependency classes generate their entries correct-by-construction, so treat corruption-only findings as low severity — but a class that documents hand-editing a field (e.g. `mobyOpenAPISpec.version.commit`, "edit dependencies.yaml manually") makes weak validation of that field a genuine, higher-severity gap.

### Gemini 3.1 Pro

**Executive Summary**

This PR fundamentally improves how `rddepman` manages dependency downloads. By shifting from a brittle mapping of artifact filenames to checksums toward a fully-resolved asset model (URL, checksum, platform, arch, and format), the manifest itself becomes the source of truth for the download. This safely eliminates the need for every downloader function to hold package-specific knowledge about upstream naming conventions, URL layouts, and OS-specific extensions. The implementation is structurally sound and effectively handles backward-compatibility with older manifests.

### Design Observations

**Strengths**
- **Explicit URL resolution**: Pushing the full upstream URL and platform/architecture metadata into `dependencies.yaml` is a fantastic design choice. It cleanly decouples the artifact selection from the physical download phase, meaning the individual dependency `download()` functions no longer have to construct platform-specific filenames or handle OS exceptions.
- **Robust Migration Strategy**: The `--regenerate` loop in `rddepman.ts` combined with the `regenerable: false` safeguard on `Electron` flawlessly manages the state transition from the old `checksums` object to the new `assets` list without risking silent data loss for packages pinned to `package.json`. 
- **Array Cartesian Helper**: Extracting the `cartesian` platform/arch loop replaces a sprawling mess of implicit and slightly different multi-level `for` loops with simple matrix processing.
