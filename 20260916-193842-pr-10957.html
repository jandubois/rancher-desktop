/**
 * Remove an access key written in parentheses after the label, as Chinese,
 * Japanese and Korean translations write it. "削除(&D)" becomes "削除".

export function removeParenthesizedAccessKey(label: string): string {
  return label.replace(/\(&[^&]\)/g, '');
}

Design Observations ¶

Concerns ¶

  • A bulk action that skips ineligible rows still says nothing about them (future) Gemini 3.5 Flash Claude Opus 5. applyTableAction filters the selection to rows where the action is enabled, and delete is enabled only for stopped containers. Select five containers with two stopped and the dialog reads "Delete 2 containers?" and names them. That is accurate, and better than the merge-base, which deleted the two with no word at all. But nothing says the other three were dropped, and Stop, Start and Restart still skip silently with no dialog. A "N of M selected rows support this action" line in the table's action bar would cover all four actions. Only delete asks anything today.

Strengths ¶

  • Deleting by container id while displaying containerName (Containers.vue:462) means the confirmation cannot drift from what is removed if the store refreshes while the dialog is open. Claude Opus 5
  • Normalising containerCommandTarget to always return a list let execCommand drop its Array.isArray branch, so this safety feature removes a shape check instead of adding one. Claude Opus 5 Codex GPT 5.6 Sol
  • Placing labels by named index keeps the buttons correct when the object literal is reordered; the positional arrays used elsewhere in the app do not. Codex GPT 5.6 Sol Gemini 3.5 Flash
  • The macOS CJK access-key strip is in the main-process wrapper once, instead of repeated per page. Gemini 3.5 Flash Codex GPT 5.6 Sol

Review Process Notes ¶

I3 is about a commit message, so it cites the short SHA and has no leading code block. The citation lint reports it as "1 without a leading block"; that is deliberate, since inventing a file reference would point the reader at code the finding is not about.

Skill improvements ¶

  • When a finding asserts that a language, compiler, or framework rejects a syntax the code under review uses, run that syntax through the toolchain before recording it. A tool that accepts two spellings of the same annotation makes the unfamiliar one look like a defect, and citing a rule instead of an observation makes the claim hard to doubt. The check costs one file and one invocation, and it separates an ineffective annotation from an effective one whose surrounding configuration is broken.
  • Treat generated or annotated metadata that ships in the repo (translation comments, rationale notes, provenance headers) as reviewable prose, not as context for the code. Where such a note states a reason, check that reason against the artifact it annotates, not against its own plausibility. The claim is often true in isolation and inapplicable to the one string, path, or value it is attached to. These notes propagate, because the next contributor treats an existing one as precedent.

Repo context updates ¶

  • [repo] Delete confirmations built on show-message-box pass the full list of target names as detail, joined with newlines, with no cap; components/Images.vue established this and the container and volume confirmations follow it. Do not flag an unbounded name list as a defect; macOS renders message as the heading with detail beneath and scrolls it. Raise a finding here only when a caller departs from the join-everything pattern.
  • [repo] Only the main/preload bundle is type-checked in CI. Renderer .vue and renderer-only .ts files are not, so a type error there fails nothing, and pages/Containers.vue is plain JavaScript whose JSDoc is consumed by editors alone. Calibrate type-correctness findings in renderer code accordingly, and check whether a JSDoc @import actually resolves before crediting the annotations that depend on it.
  • [repo] src/go/i18n-report's checkICUStructure requires every locale to have exactly the ICU plural branches en-us has, including languages with no singular/plural distinction, where both branches are necessarily identical. check --locale=all runs validate, so collapsing such a branch turns the CI gate red. Identical branches with an @reason above them are the intended shape, not duplication to flag.
  • [repo] Running jest from a scratch worktree outside the repo needs both node_modules and resources/darwin/bin/rdctl linked from the main checkout; without the latter, 26 suites fail at load with "attempting to load the paths module from a undefined process". With both linked, exactly two suites (utils/__tests__/paths.spec.ts, integrations/__tests__/unixIntegrationManager.spec.ts, 17 tests) fail environmentally and pass in a real checkout. Treat those two as expected noise and anything else as real.
