## Executive Summary

This PR adds a workflow-side collector that writes a support bundle for every BATS job and lets a job that fails early upload its artifact; the fork artifacts show it working on all three platforms. The main problem is on Windows, where the bundle runs `rc-status` outside the PID namespace that Rancher Desktop's OpenRC uses. A probe that times out also prints nothing, and the first commit message credits the wrong change for the uploaded artifact.

I2. **The WSL `rc-status` probe runs outside the PID namespace where OpenRC runs** — `.github/workflows/bats/collect-logs.sh:219` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]

```bash
    echo "=== Guest: rc-status ==="
    with_timeout 20 wsl.exe --distribution rancher-desktop -- rc-status --all
```

On WSL, network-setup starts the distro's init under `unshare --pid --mount-proc --fork` (`src/go/networking/cmd/network/setup_linux.go:338-339`), so OpenRC's pidfiles name PIDs in that child namespace. The distro's own `wsl-service` (rancher-desktop-wsl-distro v0.101, lines 3-5) gives the consequence: "using rc-service directly will not return correct results." So Rancher Desktop never runs OpenRC commands directly.

`execService` (`pkg/rancher-desktop/backend/wsl.ts:1208`) goes through `wsl-service`, and `rdctl shell` goes through `wsl-exec` (`src/go/rdctl/pkg/shell/shell.go:67`); both nsenter init's namespaces. Line 219 runs `rc-status` in the distro's root namespace, so on a running distro, the case that this section exists for, it reports the wrong service state. `ps -ef` on line 223 can stay, because the parent PID namespace sees every process.

Unproven: this host has no WSL, and the fork runs captured only a stopped distro (booted cold by the probe in run 40809252951, skipped in run 40819479405).

Fix: run `rc-status` through `wsl-exec`, which Rancher Desktop writes during startup (`wsl.ts:1405`).

```diff
-    with_timeout 20 wsl.exe --distribution rancher-desktop -- rc-status --all
+    with_timeout 20 wsl.exe --distribution rancher-desktop --exec /usr/local/bin/wsl-exec rc-status --all
```

I3. **A probe that times out prints nothing, so the bundle reports a hung `wsl.exe` as a stopped distro** — `.github/workflows/bats/collect-logs.sh:213-214` [Claude Opus 5.5]

```bash
    if ! with_timeout 20 wsl.exe --list --running --quiet | tr -d '\r' | grep -qx rancher-desktop; then
        echo "=== Guest: skipped because wsl --list --running does not list rancher-desktop ==="
```

GNU `timeout` prints nothing when it kills a command, and `with_timeout` (lines 69-76) returns the 124, but its callers ignore it. So a hung probe leaves a section that a reader cannot tell from an empty answer, though lines 159-162 say that a stuck rdctl request is when the capture is most useful. The probe runs the real script on a simulated Git Bash host with a stub `wsl.exe`. A hung WSL service gets the same skip line as a stopped distro (line 214), under an empty `wsl --list --verbose` section.

S1. **The macOS jetsam query looks back one hour, but Run BATS runs for up to two** — `.github/workflows/bats/collect-logs.sh:127` [Claude Opus 5.5, Codex GPT 6 Astra]

```bash
        log show --style compact --last 1h --predicate \
            '(sender == "kernel") AND ((eventMessage CONTAINS[c] "jetsam") OR (eventMessage CONTAINS[c] "memorystatus") OR (eventMessage CONTAINS[c] "low swap"))' \
            2>&1 | tail -100
```

Line 127 keeps the window from RD2's `bats-with-timeout.sh:193-194`, which justifies it as covering "any single bats target (30-min timeout + slack)". Here Run BATS has `timeout-minutes: 120` (`bats.yaml:411`), and the script runs right after it. In the hang-until-timeout case that the script header names, a jetsam kill in the step's first hour, the likely trigger of the hang, falls outside the window. The port also dropped RD2's `lowmem` term from the predicate. This is a Suggestion because the merge-base did not collect any memory evidence, so the gap loses nothing that shipped.

```bash repro
#!/usr/bin/env bash
# Save as probe-log-window.sh; run on macOS from the repo root: bash probe-log-window.sh
# Compares the jetsam query's window in collect-logs.sh with the Run BATS
# step timeout, then counts the kernel lines that query loses on this Mac.
set -o nounset
cap=$(awk '/- name: Run BATS/ { f = 1 } f && /timeout-minutes:/ { print $2; exit }' .github/workflows/bats.yaml)
last=$(grep -o -- '--last [0-9]*[hm]' .github/workflows/bats/collect-logs.sh | awk '{ print $2 }')
case $last in
*h) window=$((${last%h} * 60)) ;;
*m) window=${last%m} ;;
*) echo "unrecognised window: $last" >&2; exit 2 ;;
esac
echo "Run BATS timeout-minutes: ${cap}; jetsam query window: ${window} min"
predicate='(sender == "kernel") AND ((eventMessage CONTAINS[c] "jetsam") OR (eventMessage CONTAINS[c] "memorystatus") OR (eventMessage CONTAINS[c] "low swap"))'
in_window=$(log show --style compact --last "${window}m" --predicate "$predicate" | grep -c ' kernel\[')
in_cap=$(log show --style compact --last "${cap}m" --predicate "$predicate" | grep -c ' kernel\[')
echo "kernel lines in the last ${window} min: $in_window; in the last ${cap} min: $in_cap"
if ((window < cap && in_cap > in_window)); then
    echo "FAIL: $((in_cap - in_window)) lines from the start of a ${cap}-minute Run BATS fall outside the query window"
    exit 1
fi
echo "PASS: the window covers the whole Run BATS step"
```

## Review Process Notes

### Skill improvements

- When a PR ports code from another project, have agents list every constant whose rationale came from the source project's environment (a timeout, a time window, a retry count, a size limit) and check it against the target's own configuration. A port copies the value and often drops the comment that tied it to the source's setup.
- In diagnostic and collection code, check that each section separates an empty answer from a probe that failed, timed out or was skipped, and that every skip message's stated reason holds in each case that reaches it.

### Repo context updates

- [repo] On WSL, Rancher Desktop's OpenRC runs in a child PID and mount namespace that network-setup creates (`unshare --pid --mount-proc --fork`). An OpenRC command (`rc-status`, `rc-service`) run through plain `wsl.exe --distribution rancher-desktop` sees the distro's root namespace and does not report the services correctly; Rancher Desktop routes such commands through the distro's `/usr/local/bin/wsl-service` or `/usr/local/bin/wsl-exec`, which nsenter init's namespaces. A process listing works from the root namespace, which sees every child process. Flag any WSL-side diagnostic or test helper that runs OpenRC commands without them.
- [repo] On the macOS runners, a script with `#!/bin/bash` runs bash 3.2 even after the workflow installs Homebrew bash, and so does a `shell: bash` step that runs before "macOS: Install prerequisites". Under `set -o nounset`, bash 3.2 rejects an empty array expansion (`"${arr[@]}"`), so check such scripts against an empty input.

### Report notes

- I1 cites a commit SHA, not a file, so it draws a beautify lint warning on purpose.
