Executive Summary ¶

This well-contained PR adds merge and remove commands plus translate improve/drift modes to the i18n-report CLI, with strong test coverage. All three reviewers independently found one Important bug: the text-merge and remove-pipe input gate (isValidDottedKey) rejects the quoted dotted-segment key form the tool itself emits, silently dropping the ~24 kubernetes.io/* secret-type keys the PR's own dot-quoting fix was meant to protect. The JSON path is unaffected.

All three agents converged on that single bug (I1) from independent angles — Codex and Claude via the merge/remove call chains, Gemini via the validator's charset — and I reproduced it end-to-end against a built binary. The remaining items are one small robustness gap and three test/coverage suggestions. No security, concurrency, or data-corruption issues in the write path itself, which is carefully guarded.

// stripYAMLQuotes removes outer YAML quotes from a value string.
func stripYAMLQuotes(s string) string {
	if len(s) >= 2 && s[0] == '\'' && s[len(s)-1] == '\'' {
		inner := s[1 : len(s)-1]
		return strings.ReplaceAll(inner, "''", "'")
	}
	if len(s) >= 2 && s[0] == '"' && s[len(s)-1] == '"' {
		inner := s[1 : len(s)-1]
		inner = strings.ReplaceAll(inner, `\"`, `"`)
		inner = strings.ReplaceAll(inner, `\\`, `\`)
		return inner
	}
	return s
}

Any input whose first non-whitespace byte is [ is committed to the JSON path; a raw text batch that opens with a note like [WIP] ... aborts with parsing JSON array input: invalid character. Design Observations ¶

Concerns ¶

  • Two divergent key representations (in-scope) Claude — The write path (splitKeyPath/appendKeyPath, yaml.go:23-46) faithfully mirrors the renderer's splitObjectPath/joinObjectPath: quoted dotted segments, both quote styles stripped. The input-validation path (isValidDottedKey) uses a stricter, incompatible [A-Za-z0-9_-] charset with a naive .-split, and the JSON merge path bypasses validation entirely — which is exactly why JSON round-trips while text/stdin drop. Routing every key-shaped gate (isValidDottedKey, and ideally looksLikeEntry) through splitKeyPath collapses the two representations into one and forecloses the whole I1 class rather than patching one call site.

Strengths ¶

  • Serialize-then-atomic-write (in-scope) Codex Claude — reportMerge builds the full document in a buffer before writeFileAtomic (report_merge.go:212-218), so a serialization failure leaves the file untouched; co-located @source means one atomic write keeps a translation and its snapshot in sync.
  • validateNoAliases guardrail (in-scope) Codex Claude Gemini — anchors, aliases, and sequences the custom serializer cannot round-trip are rejected before any mutation (yaml.go:377-393).
  • Minimal key quoting (in-scope) Claude — keyRoundTripsPlain/yamlKey quote a key only when the plain form would not survive a parse, so benign scalars like yes stay unquoted and checked-in locale files do not churn.
  • applied-only @source refresh (in-scope) Codex Claude — the refresh loop touches only keys this merge wrote, preserving drift markers on untouched translations (report_merge.go:195-207).
  • Mapping-overwrite refusal (in-scope) Gemini Claude — nodeSetLeaf refuses to replace a populated mapping with a scalar, preventing accidental subtree erasure.
  • Graceful markdown-fence extraction (in-scope) Gemini — extractTranslationText drops LLM prose around `yaml fences, matching the agent-driven translation workflow.

Testing Assessment ¶

Coverage is thorough: the mode matrix (normal/drift/improve, --include-overrides, dry-run), duplicate/unknown-key rejection, comment preservation, mapping-vs-leaf refusal, and BOM/JSONL/markdown-fence extraction are all exercised, and the suite passes (go test ./src/go/i18n-report/... -count=1). Gaps, ranked by risk:

  1. Text-format merge of a dotted-segment key — untested and broken (I1). The dotted-key round-trip is covered only through the JSON array path (TestMergeReadsTranslateJSONArray) and the tree path (TestNodeRoundTripPreservesDottedSegmentKey), never the text/key=value path.
  2. remove stdin/pipe with a slash/quoted key — untested and broken (I1); see S4.
  3. TestRemoveKeyFromNode structural assertion — wantYAML never compared (S3).
  4. stripYAMLQuotes with \n/\t/unicode escapes — untested (S2).
  5. validateNoAliases sequence rejection — anchors/aliases are covered (TestMergeRejectsAliases); a bare SequenceNode in a locale file is not directly exercised.

Documentation Assessment ¶

The README documents --format=json as lossless and the text format as lossy for multiline values, but nowhere warns that the text-batch merge and the unused|remove / stale|remove pipe workflows silently drop dotted-segment (secret-type) keys — a distinct, non-multiline limitation. If I1 is fixed, no doc change is needed; if deferred, the "Translate missing keys" and "Clean up dead keys" workflow sections should state that dotted-segment keys require --format=json / remove --stale. The new annotation and subcommand docs otherwise match the code.

Review Process Notes ¶

Skill improvements ¶

  • When a change adds or modifies a tool that both produces a serialized identifier (a key path, ID, slug, or name) and consumes it back — including consuming its own output in a documented round-trip — verify the consumer accepts every form the producer emits. Read the producer's formatting/escaping/quoting routine and the consumer's parsing/validation routine side by side and confirm they share one grammar. A stricter validator on the read side silently drops or rejects values the write side emits, and such round-trip breaks are invisible in tests that exercise only one direction. Flag any validation gate that re-implements identifier parsing (naive strings.Split, a hand-rolled charset check) instead of reusing the canonical tokenizer the write path uses.

Repo context updates ¶

  • [repo] The i18n-report tool (src/go/i18n-report/) carries two key-path representations that must stay in sync: the quote-aware write path (splitKeyPath/appendKeyPath in yaml.go, mirroring the renderer's splitObjectPath/joinObjectPath) and looser text-input validators (isValidDottedKey, looksLikeEntry) that split naively on . and restrict the charset. The JSON merge path bypasses validation entirely. When reviewing a change to any key-path gate, confirm it routes through splitKeyPath rather than a fresh .-split, and check the text and JSON input paths behave identically.
  • [repo] en-us.yaml nests ~24 secret-type labels (lines ~3121-3144) under keys whose own segment contains a literal dot and a slash — kubernetes.io/service-account-token, kubernetes.io/dockercfg, bootstrap.kubernetes.io/token. These are the canonical stress-test keys for any i18n-report key-handling change; a round-trip that does not exercise them (text translate→merge, stale/unused→remove) leaves the highest-risk path uncovered.
