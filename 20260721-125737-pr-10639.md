## Review Process Notes

**Skill improvements**

- When a change rewrites a user-facing string that already has translations, compare the old and new values byte for byte, not as rendered text. Locale files carry typography that a diff view renders identically to its plain-ASCII counterpart: non-breaking spaces, narrow no-break spaces, directional quotes, and locale-specific punctuation. A rewrite that retypes the string silently drops them, and placeholder- and tag-based validation does not inspect whitespace. Check the surrounding file for the convention before deciding whether a difference is a regression.
- When a change adds a skip, exemption, or early return that delegates a case to another check, verify that the named check actually runs in CI. Read the workflow files for the invocation and its flags. A comment naming another report as the owner is a claim about process, not code, and the delegated case disappears when that report is optional, manual, or gated behind a flag nothing sets.
- When a prior round's resolution records a finding as fixed by a new test, verify the test fails without the fix. Delete or invert the code the test claims to pin and run the suite. A fixture added for a branch frequently exercises a different branch that shares its outcome, and the resolution table then records coverage the suite does not have.
- When reviewing documentation that cites a specific code identifier, string, or symbol as evidence for a rule, check that the cited item has the history the prose claims. A rule generalized from one incident often ends up quoting a neighbouring item that was changed in the same commit, which leaves a maintainer unable to find the evidence.

**Repo context updates**

- [repo] REMOVE the note that the `check` and `drift` subcommands "remain in flight on the `i18n-workflow-v2` integration tree", and REMOVE the bullet directing reviewers to validate i18n-report gate changes inside an `i18n-workflow-v2` worktree. Both subcommands are on the default branch and `check --locale=all` runs clean from an ordinary worktree. This was raised in the previous round and has not been applied; the stale text reached every agent again this round.
- [repo] Translation files carry per-language typography that must survive an edit: French uses U+00A0 inside `« »` guillemets and before `: ; ! ?`, and Japanese and Chinese use full-width parentheses and punctuation. When a PR rewrites a translated value, diff the bytes rather than the rendered text, since `validate` checks placeholders, tags, and ICU structure but never whitespace.
- [repo] The i18n CI gate is `go run ./src/go/i18n-report check --locale=all` in `.github/workflows/test.yaml`, with no `--strict`. Completeness checks, missing keys, and drifted keys therefore never run in CI, even though the translations README states that periodic and pre-release runs add `--strict`. When reviewing a change that defers a case to `drift` or to a completeness check, treat that case as ungated.

#### Strengths

- **Symmetrical Key Parsing**: `isValidDottedKey` tokenizes key paths using `splitKeyPath`, ensuring that dotted segments enclosed in quotes (e.g., `secret.types."kubernetes.io/basic-auth"`) are parsed symmetrically on both reading and writing paths.
