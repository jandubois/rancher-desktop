## Executive Summary

The PR edits `/containers/create` bodies as raw JSON, so the docker proxy forwards fields it does not model and passes dockerd's `API-Version` through. It also removes the moby spec download and go-swagger. The JSON editing is correct for the bodies that real clients send, and CI passed. But existing checkouts keep go-swagger's generated `models/` package, which then breaks `go test ./...` and golangci-lint in wsl-helper. The PR body should tell developers to delete it.

dockerd decodes the body with `encoding/json`, which accepts any capitalization of a field name and keeps the last match in document order. `findKey` picks the exact spelling instead, and `writeTo` re-encodes each edited object from a map, which sorts its keys. So for `{"Binds": [...], "binds": [...]}` the proxy rewrites `Binds` while dockerd reads the untouched `binds`, and an unrelated pair such as `env` and `Env` swaps which value wins. The merge-base's struct round trip forwarded the effective values in both cases. Real clients never send both spellings, so this stays a Suggestion.

## Design Observations

### Concerns

- (in-scope) The `containersCreateBody` comment (`containers_create_body.go:21-26`) presents forwarding unknown fields only as a benefit. #11358 accepted the cost of dropping the `API-Version` cap, which is that a future API change to how requests describe bind mounts reaches the mungers unchecked. If a later API version adds a field that carries a host path, the Windows proxy forwards it untranslated, the Linux proxy does not rebind it, and the proxy logs neither. A sentence in that comment naming the risk keeps it in front of the next reader. Today's spec is not affected. `v1.57-swagger.yaml` changes neither `Mount` nor `HostConfig.Binds` against `v1.56.yaml`, and moby's 1.57 changelog does not mention `POST /containers/create` at all. [Claude Opus 5.5, Gemini 3.5 Flash]

### Strengths

- `readContainersCreateBody` puts the original bytes back before decoding, and the `Director` in `serve.go` only logs munger errors. So any decode failure forwards the client's request untouched. [Claude Opus 5.5, Gemini 3.5 Flash]
- Keeping every unedited value as `json.RawMessage` preserves unknown fields and integers past float64 precision, and `TestContainersCreateBody` pins both. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]
- The Linux and Windows mungers share one reader and writer, so both platforms serialize the body the same way. [Codex GPT 6 Astra]
- No reference to the spec, go-swagger or the generated models remains anywhere in the tree. [Codex GPT 6 Astra, Gemini 3.5 Flash]

When a body contains both `Binds` and `binds`, `findKey` (line 61) picks the exact-case key. dockerd's `encoding/json` struct decode (`runconfig/config.go` `loadJSON`) takes the last matching key in document order instead. `writeTo` (line 187) also re-sorts the keys, so `binds` ends up after `Binds`. ##### Design Observations

**Concerns**

- (future) #11358's Option 3 named one risk: without the `API-Version` cap, a future API change to how requests describe bind mounts reaches the mungers unchecked. The code does not record this. C1. **JSON smuggling in proxy allows path translation bypass** — `src/go/wsl-helper/pkg/dockerproxy/mungers/containers_create_body.go:59-75`

```go repro
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"strings"
)

func findKey(object map[string]json.RawMessage, name string) string {
	key := ""
	if _, ok := object[name]; ok {
		key = name
	} else {
		for candidate := range object {
			if strings.EqualFold(candidate, name) {
				key = candidate
				break
			}
		}
	}
	if key == "" || string(bytes.TrimSpace(object[key])) == "null" {
		return ""
	}
	return key
}

func marshalJSON(value any) (json.RawMessage, error) {
	var buf bytes.Buffer
	encoder := json.NewEncoder(&buf)
	encoder.SetEscapeHTML(false)
	encoder.Encode(value)
	return bytes.TrimSuffix(buf.Bytes(), []byte("\n")), nil
}

type Request struct {
	HostConfig *HostConfig
}

type HostConfig struct {
	Binds []string
}

func main() {
	input := []byte(`{
		"hostconfig": {"Binds": ["/malicious:/host"]},
		"HostConfig": {"Binds": ["/exact:/host"]}
	}`)

	var top map[string]json.RawMessage
	json.Unmarshal(input, &top)

	hostConfigKey := findKey(top, "HostConfig")

	var hcMap map[string]json.RawMessage
	json.Unmarshal(top[hostConfigKey], &hcMap)
	hcMap["Binds"] = json.RawMessage(`["/translated_exact:/host"]`)

	top[hostConfigKey], _ = marshalJSON(hcMap)
	output, _ := marshalJSON(top)

	var dockerdReq Request
	json.Unmarshal(output, &dockerdReq)
	fmt.Printf("Dockerd uses Binds: %v\n", dockerdReq.HostConfig.Binds)
}
```

```text repro-output
Dockerd uses Binds: [/malicious:/host]
```

When multiple case-insensitive keys exist in the JSON request (e.g., `"HostConfig"` and `"hostconfig"`), `findKey` prefers the exact match `"HostConfig"` and rewrites its contents. However, `writeTo` re-marshals the body using `json.Marshal` on a map, which sorts keys alphabetically. Since `"HostConfig"` sorts before `"hostconfig"`, the un-rewritten `"hostconfig"` appears *last* in the payload sent to dockerd.

Go's `json.Unmarshal` in dockerd processes fields sequentially and takes the last matching key, causing it to use the un-rewritten `"hostconfig"` and completely ignore the proxy's rewrites. An attacker can use this to bypass path translation and mount arbitrary VM directories (like `/etc` or `/var/run/docker.sock`) into the container. This affects `HostConfig`, `Binds`, `Mounts`, `Type`, and `Source`.

Fix: Modify `findKey` to delete duplicate case-insensitive matches from the map before returning.

```go
	// Delete duplicates to prevent JSON smuggling
	for candidate := range object {
		if candidate != key && strings.EqualFold(candidate, name) {
			delete(object, candidate)
		}
	}

	if key == "" || string(bytes.TrimSpace(object[key])) == "null" {
		return ""
	}
	return key
```
