## Design Observations

### Concerns

- **A bulk action that skips ineligible rows still says nothing about them** `(future)` [Claude Opus 5]. `applyTableAction` filters the selection to rows where the action is enabled, and delete is enabled only for stopped containers. Select ten rows of which three are stopped and the dialog reads "Delete 3 containers?" while ten checkboxes stay ticked. The name list discloses which three, so the dialog is accurate. This has now run two rounds as an observation; closing it means a tenth translation key, and Stop, Start and Restart would still skip silently.
- **Three main-process dialog paths bypass the shared wrapper** `(future)` [Claude Opus 5]. `window/index.ts:706` applies the macOS access-key strip to every caller that passes `normalizeAccessKeys`, which is the right place. But `main/imageEvents.ts` calls `Electron.dialog.showMessageBox` directly and `window/preferences.ts:114` uses `showMessageBoxSync`. None sets `normalizeAccessKeys` today, so nothing is broken; a future dialog added on one of those paths would lose the strip silently.

### Strengths

- Both pages capture the target list before prompting and reuse it for the confirmation and the execution, so the count and the action cannot drift apart. [Codex GPT 5.6 Sol, Claude Opus 5]
- Placing labels by named index keeps `buttons`, `defaultId` and `cancelId` synchronized against reordering. [Codex GPT 5.6 Sol, Gemini 3.1 Pro]
- One wrapper keyed on `normalizeAccessKeys` applies the macOS CJK strip for every call site, so translators follow the README and no dialog needs its own workaround. [Claude Opus 5, Gemini 3.5 Flash, Gemini 3.1 Pro]
- The e2e stub intercepts the main-process dialog instead of driving a native window, which lets the bulk cancel case assert what the user saw. [Gemini 3.1 Pro]

## Review Process Notes

I1 is about a commit body, so it cites the short SHA and has no leading code block. The citation lint reports it; that is deliberate, since inventing a file reference would point the reader at code the finding is not about.

### Skill improvements

- Before consolidating a round on a pull request, fetch the hosting platform's check results for the head commit and read the log of any failing job. A merge gate that arrived on the base branch after the branch diverged does not exist in the reviewed tree, so no agent worktree and no local test run can reach it, and every agent will report the suite green while the pull request is red. This is invisible to any amount of reading and costs one API call.

- When the round's verdict rests on whether commit messages describe their changes, require the check to be a comparison against the artifact the message makes a claim about, not against the commit's own diff. Confirming that a diff matches its subject line is a scope check; a body that states a fact about files elsewhere in the tree is only verified by counting or reading those files. Several agents performing the weaker check look like convergence.

- When a prior round's finding rests on a count, re-derive the count and the inference separately in the next round.
