## Important Issues

I1. **The recheck comment says `RemoveAll` unexposes every port, but UDP proxies keep running** — `src/go/guestagent/pkg/procnet/scanner_linux.go:65-69` [Claude Opus 5.5, Codex GPT 6 Astra]

```go
	// components exposed. The listeners stay, so /proc/net does not
	// change, and the monitor exposes only its own ports again. Without

```

`RemoveAll` builds its `UnexposeRequest` without `Protocol` (`tracker/apitracker.go:246-248`), and gvisor-tap-vsock v0.8.9's `/unexpose` handler defaults an empty protocol to TCP. So a UDP proxy keeps running, while `RemoveAll` still clears the port's tracker record and tells wsl-proxy to close its listener. At the next recheck `Add` gets "proxy already running" and returns the sentinel, so `reassert` restores neither. A reader would expect the recheck to repair UDP ports after a reconnect.

The UDP leak predates this PR, and round 2 declined it as S1. This round adds a sentence stating the opposite. The first commit's "clears every expose" had the same flaw, and round 2 missed it.

The probe runs the real `APITracker` against upstream's handlers; TCP is the control.

## Suggestions

S1. **The sentinel now tells callers not to retry, which the scanner does on purpose** — `src/go/guestagent/pkg/tracker/apitracker.go:41-43` [Claude Opus 5.5]

```go
	// ErrPortAlreadyExposed signals that Add was a no-op because
	// host-switch already runs a proxy for every port in the request,
	// usually one another component asked for. Callers should not retry.
```

The rewrite replaced "should treat this as successful delegation rather than a failure to retry" with "Callers should not retry." But the /proc/net scanner calls `Add` again for every delegated port once `ownershipRecheckInterval` passes (`scanner_linux.go:214-225`), and `reassert` calls it for every published port expecting this sentinel (`scanner_linux.go:356-357`). The kube watcher calls it on every Service event. None of those retries a failure, but someone adding a caller could take the sentence as ruling the recheck out, and the instruction every caller follows, treating the sentinel as success, is gone.

Fix: `Callers should treat it as success.`

S2. **A test can pin the upstream wire string against the real handler** — `src/go/guestagent/pkg/tracker/apitracker.go:54` [orchestrator]

```go
const portAlreadyExposedSubstring = "proxy already running"
```

Round 1 declined this pin because "a real pin needs a gvisor netstack in a guest-agent unit test". An empty netstack is enough. `NewPortsForwarder(stack.New(stack.Options{}))` behind an `httptest` server runs the real `/expose` handler, as the I1 probe shows, and both modules are already in `go.mod`. Re-raised because the decline's cost estimate was wrong. Every sentinel arm in this PR rests on the substring. If a gvisor-tap-vsock bump rewords it, the kube and iptables callers go back to the Error lines of #10337 and #10338, docker again skips the loopback DNAT rules, and the tracker tests stay green because a fake feeds them the string. Dependabot bumps this module (`c5cae3605`), so nothing prompts the manual re-check the comment asks for.

Fix: a tracker test that calls `Add` twice for one port against the real mux and asserts `errors.Is(err, tracker.ErrPortAlreadyExposed)`.

## Design Observations

### Concerns

- **Sending `Protocol` from `RemoveAll` fixes UDP cleanup, but leaves kube UDP ports unexposed for up to an hour** *(future)* [orchestrator] — With the protocol set, `RemoveAll` would close UDP proxies on an engine reconnect, which makes I1's original sentence true and closes the UDP path to round 2's S1. Today those UDP proxies keep running across a reconnect because of the bug. Kube TCP ports already wait for that event. I reasoned this from the code and did not run it, so it belongs in its own change with a test.

### Strengths

- **The rewrite corrects two things round 2 got wrong** *(in-scope)* [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash] — The kube watcher does expose its ports again. `handleUpdate` re-adds every port of an unchanged Service (`kube/servicewatcher_linux.go:131-180`), and the informer resyncs hourly. And a failed wsl-proxy notification cuts off other WSL distributions, not Windows. wsl-proxy listens on localhost in the distro's default namespace, while Windows reaches the port through host-switch.

When the recheck runs `reassert` for that port, `Add` gets the sentinel (`scanner_linux.go:365-366`), so it neither restores the tracker record nor re-notifies wsl-proxy.

A reader of the comment would conclude that the recheck restores every port after a reconnect. For UDP it restores nothing. This is not a re-raise of the declined round-2 S1; it concerns only whether the new sentence is true.

Unproven: the evidence is upstream handler source. The fake tracker in the procnet tests never goes through `RemoveAll`.

Fix:
```diff
-	// docker or containerd event monitor reconnects, APITracker.RemoveAll
-	// unexposes every port in the shared tracker, including ports other
-	// components exposed. The listeners stay, so /proc/net does not
+	// docker or containerd event monitor reconnects, APITracker.RemoveAll
+	// unexposes every TCP port in the shared tracker, including ports
+	// other components exposed. It sends no protocol and host-switch
+	// defaults to TCP, so UDP proxies keep running and this recheck
+	// cannot restore their tracker or wsl-proxy state. The listeners stay, so /proc/net does not
```

I2. **The sentinel comment promises coverage of skipped bindings** — `src/go/guestagent/pkg/tracker/apitracker.go:41-43` (important, regression)

```go
	// ErrPortAlreadyExposed signals that Add was a no-op because

	// usually one another component asked for. Callers should not retry.
```

The guarantee at line 42 exceeds the implementation. IPv6 bindings are logged and skipped before calling Expose (`apitracker.go:112-116`). A request containing an already-exposed IPv4 binding and an unexposed IPv6 binding can therefore return the sentinel through `apitracker.go:165-166`.

Fix: Say that every **Expose call made** reported an existing proxy, no call succeeded, and no other returned failure occurred. Avoid promising coverage of skipped bindings.
