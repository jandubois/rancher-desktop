Commit 1 (`d26440463`) writes `dump_sockets` with `ss --tcp --udp --processes --numeric` and plain `lsof -i -P -n`. Commit 2 (`df8a51541`) adds `--all`, the `sudo --non-interactive` and the skip line for a host with neither tool, but its message describes only the Windows netstat table and `ps --windows`. So commit 1 on its own still does not list Linux listeners, and a reader looking for when `ss` gained `--all` would not think to open a commit titled "List Windows sockets and processes".

S2. **Linux `ss` names the owning process only for the runner user's sockets** — `.github/workflows/bats/collect-logs.sh:161`

```bash
            with_timeout 30 ss --all --tcp --udp --processes --numeric
```

Found during consolidation. Round 1's S2 fix moved macOS `lsof` under sudo because "lsof lists other users' sockets only as root", and Linux `ss --processes` has the same limit, because only root can read another user's `/proc/<pid>/fd`. Run 40937460339's Linux bundle shows it. Its `Runner.Worker` connections show `users:((...))`, while sshd's listener on port 22 and systemd-resolved's on port 53 do not show an owner. So a port that a root process holds, such as one the runner's dockerd publishes, would appear with no program name. This is a Suggestion because the merge-base did not collect a socket table. #11246's `capture_host_sockets` runs `ss` the same way.

Fix: run `ss` under `sudo --non-interactive`, as line 165 does for `lsof`.

Outcome: fixed in commit 1 (`7340e368a`), which runs `ss` under `sudo --non-interactive`. #11246's copy is left for that PR.

S3. **A `wsl --list --running` answer that lists the distro and then hangs loses its timeout line** — `.github/workflows/bats/collect-logs.sh:234-238` [Codex GPT 6 Astra]

```bash
    running=$(with_timeout 20 wsl.exe --list --running --quiet | tr -d '\r')
    if ! grep --quiet --line-regexp rancher-desktop <<<"$running"; then
        echo "=== Guest: skipped because wsl --list --running did not list rancher-desktop ==="
        echo "$running"
        return
```

The round-1 I3 fix prints the captured listing only under the skip line. When `wsl.exe` prints `rancher-desktop` and then hangs, `grep` matches, the guest probes run, and the `timeout: sending signal TERM` line in `$running` never reaches the bundle. A stub `wsl.exe` that prints the distro name and then sleeps reproduces it. The bundle shows both guest sections and no timeout line. The guest probes run under their own timeouts, so a wedged WSL would still show up in their sections.

Fix: print `$running` under its own `=== wsl --list --running ===` header before the check, whichever branch follows.

Outcome: fixed in commit 1 (`7340e368a`). The listing prints under its own header before the check, so a hang after the distro name keeps its `timeout:` line.

### Skill improvements

- The preamble forbids commits but lets agents run git commands that write in a `.scratch/` clone. An agent read that allowance as covering `git commit`, and a host hook that turns every commit into a permission prompt then blocked it until the stall watchdog fired. Say in the preamble that the commit ban covers clones too, and name `git merge-tree --write-tree` and `git merge-file` for merge experiments.
- When a PR body gives conflict or merge-order guidance about sibling PRs, check it against each sibling as it will be after its own rebase onto the current default branch. Conflicts that a sibling has with the base exist whatever the PR does, and counting them against the PR overstates how the two interact.

### Repo context updates

- [repo] On the GitHub-hosted Linux runners, `ss --processes` names the owning process only for the runner user's own sockets; listeners that root or a system user owns, such as sshd and systemd-resolved, appear without a process name, and a port that a root dockerd publishes would too. Flag diagnostic code that needs the owner and runs `ss` without `sudo --non-interactive`, which is passwordless on the runners.
