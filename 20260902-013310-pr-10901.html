Executive Summary ¶

This PR is a workaround for a moby regression: LoadImage keeps a moby-dangling@ record for every re-imported image whose tag already points at the same target, and every later inspect logs it. The helper's digest comparison and its fallbacks behave as documented against the real k3s archive under busybox awk. The one Important finding: the new BATS assertion reads a Lima-only log path, so the test fails on Windows. The awk parser's format assumptions are the main design risk.

Four reviewers ran on the same prompt. All three tool-using reviewers found the Windows log path; Codex, Gemini 3.1 Pro, and Claude each found a different shape of index.json that the awk parser mishandles, and the consolidator probed eight shapes with busybox awk in the running VM to settle them. The author reports the change as verified end to end in another session, and treats it as a stopgap: the upstream moby report is in progress. Findings below are limited to the script, the test, and the deployment glue.

S1. The awk fast path trusts three properties of index.json that no producer promises Codex GPT 5.6 Sol Gemini 3.1 Pro Claude Opus 5¶
pkg/rancher-desktop/assets/scripts/docker-load-airgap-images
function entry_digest(entry) {
    return value_of(entry, "\"digest\":\"[^\"]*\"")
}
# Split the manifests array into ENTRIES, dropping the delimiters between
# them; restore() puts them back.
function split_manifests(line,   body) {
    body = line
    sub(/^.*"manifests":\[/, "", body)
    sub(/\][^]]*$/, "", body)
    return split(body, ENTRIES, /\},\{"mediaType"/)
}
function restore(i, n,   entry) {
    entry = ENTRIES[i]
    if (i > 1) entry = "{\"mediaType\"" entry
    if (i < n) entry = entry "}"
    return entry

The parser assumes one record, "mediaType" first in every entry, and ]} after the array. Reordered keys under-count silently: with the first image present, nothing else loads. One entry per line, or a ] in a value after the array, passes the census and hands docker load invalid JSON, which fails the k3s start_pre. Other shapes (pretty-printed, urls, platform, index-level annotations) parse or fall back; an unnamed entry is dropped Claude Opus 5, costing only a dangling image. Every producer in use marshals from Go structs, so none trips these today, which caps this at Suggestion; Gemini rated the trailing-value case Important.

Design Observations ¶

Concerns ¶

  • The partial-load path is most of the script and is where every parser assumption applies (in-scope) Claude Opus 5. split_manifests, restore, filter mode, and the extract-and-repack at lines 118-123 (about 60 of 123 lines) run only when some images are present. Dropping them (census, compare, load everything when anything is missing) keeps the two common cases identical and returns the partial case to today's behaviour, at the cost of recreating dangling records for unchanged images on every k3s upgrade. How long this workaround has to outlive the upstream fix decides the trade.
  • A real JSON parser is one binary away on Lima and two on WSL (future) [Consolidator]. lima-guestagent yq is mikefarah yq v4.53.2 and handles every shape in S1; the census and the filter are one expression each. WSL has no equivalent: wsl-helper embeds no yq, and neither guest image ships jq or python3 (the Lima VM has 141 apk packages, busybox only; Alpine's jq package is 151 KB and would need releases of alpine-lima and the WSL distro). Embedding yq in wsl-helper the way Lima's guest agent does would let one parser-free script serve both backends.
  • Records from earlier sessions outlive the fix (future) [Consolidator]. docker image prune keeps a dangling record whose digest belongs to any container (daemon/containerd/image_prune.go, filterImagesUsedByContainers), so a user upgrading with records already present keeps the warnings for the images their pods use until a reset with image deletion or the upstream fix. The author treats the change as a stopgap with an upstream report in progress.

Strengths ¶

  • Every parse failure funnels into load_everything (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.5 Flash. Lines 33, 97, and 114 catch a missing index, an empty census, and an all-missing store; pretty-printed JSON, an un-annotated index, and a legacy archive all take the fallback.
  • The digest comparison distinguishes a present image from a tag whose content changed (in-scope) Codex GPT 5.6 Sol. A tag that moved gets re-imported; only a tag at the same target is skipped.
  • Both backends write the helper in the same action as the k3s init script (in-scope) Codex GPT 5.6 Sol Claude Opus 5. The pair cannot drift, and /usr/local/bin is on the init script's PATH, as the existing unqualified nerdctl call shows.
  • The header comment states the mechanism as moby implements it (in-scope) [Claude Opus 5, Consolidator]. LoadImage runs ensureDanglingImage for every archive image whose name exists (daemon/containerd/image_exporter.go:273-277), and collectRepoTagsAndDigests logs the warning on every inspect (daemon/containerd/image_inspect.go:156).

  • Where a test finding's severity turns on a CI workflow's default input, read the workflow's on: block before rating it: a defect reached only through a dispatch-only workflow's default is latent, while the same defect in a scheduled or pull-request workflow breaks every run.
