## Design Observations

### Concerns

- **The feed's trust boundary spans two processes** `(future)` [Claude Opus 4.8] — `background.ts:810` returns raw XML across IPC and `BlogFeed.vue:21` parses it in a window running `nodeIntegration: true, contextIsolation: false`. Today's code holds the line: `safeLink` rejects non-http(s) schemes before any `href` binding, all text flows through `{{ }}`, and no `v-html` touches feed content. But the invariant lives in one component, and whoever adds an author avatar or a rendered excerpt inherits a Node-integrated renderer holding remote markup. Parsing in main and returning a typed `{title, link, summary, date}[]` would move the boundary to the IPC edge and let `electron-ipc.d.ts` carry the guarantee. Main has no `DOMParser`, so that trade buys a new XML dependency.
- **Two components drive the same IPC handshake** `(in-scope)` [Claude Opus 4.8] — `General.vue:52-56` and `AutoUpdateCheckbox.vue:24-32` both register `settings-update`/`settings-read`/`update-state` and both re-request two of them, so each page load runs the handshake twice. Harmless, since both converge on the same broadcast state, and it is the price of the action slot passing no props (`TheTitle.vue:98` renders `<component :is>` bare). A third action-slot consumer would multiply it again.
- **Secondary and disabled text share one token** `(future)` [Codex GPT 5.6 Sol] — S4 is the local symptom. A dedicated accessible secondary-text token would end the recurring choice between low-contrast `--muted` and form-specific `--input-label`.

### Strengths

- **Feed content cannot inject** `(in-scope)` [Claude Opus 4.8, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash] — `safeLink` validates by parsing with `URL` and allowlisting `url.protocol` rather than prefix-matching, the spec drives a real `javascript:` payload through it, and every text field reaches the DOM through interpolation.
- **The new locale surface is clean** `(in-scope)` [Claude Opus 4.8] — all nine locales carry both keys with correct `@source` annotations, and `i18n-report check`, per-locale `check`, `validate`, and `drift` all pass. The `telemetryOptIn.fineprint` removal leaves no dangling reference anywhere, and `excludes.txt:99` (`/translations/(?!en)`) keeps the non-English values out of the spell checker, so dropping `fineprint` from `expect.txt` orphans nothing.
- **Layout decisions carry their rationale** `(in-scope)` [Claude Opus 4.8] — every non-obvious rule in `UpdateStatus.vue:171-217` names the constraint it satisfies, including why the Card's own title and `<hr>` are hidden. The feed themes correctly through `--box-bg`/`--border`/`--shadow` in both modes.

## Review Process Notes

### Skill improvements

- When a prior round's report explains that a verification could not run because of a broken or missing environment (an unbuildable toolchain, an absent dependency, a version conflict), treat that explanation as a claim to re-test, not a fact to inherit. Re-check the environment yourself before repeating the excuse or the diagnosis attached to it. A round that inherits a stale environmental verdict skips the verification every later round then also skips, and the original diagnosis is often wrong about the cause even when it is right that something failed.

- When a finding proposes changing a color for contrast, compute the ratio against the background the element actually renders on, which means walking up the ancestor chain to the nearest one that sets a background rather than assuming the page background. A container that tints itself changes the answer, sometimes across the pass/fail line, and a ratio measured against the wrong surface makes a real finding look imprecise and a false one look rigorous.

- When a change places a newly translated string next to a value formatted by the platform rather than the translation layer (a date, a number, a currency, a relative time), check that both read from the same locale source. Localizing the label alone produces a mixed-language line that neither the translation files nor the formatting call reveals on its own, because the defect only exists where the two meet.

- When a round adds a category of file the target did not previously contain, require each reviewer to record a concrete observation for at least one file in that category or state why none is needed. A coverage summary that marks an entire new category "Reviewed, no issues" without comment is indistinguishable from one that never opened the files, and new surface is where unreviewed defects concentrate.

### Repo context updates

- [repo] UPDATE the entry on repo-wide jest failures. The claim that a failing suite signals "a jest/ts-jest major-version skew in `node_modules`" is wrong: the installed jest and ts-jest match `package.json` exactly and the suite runs. The actual cause in a review worktree is a missing `node_modules`, which git worktrees do not inherit. Replace the diagnosis and the "assess statically" advice with: symlink the main checkout's `node_modules` into the worktree (`ln -s /path/to/main/node_modules node_modules`) and run the suite; it works. Reserve the static-assessment fallback for cases where the run still fails after that.

- [repo] UPDATE the entry on `--muted` contrast. It computes ratios against `--body-bg` only, and cites `TelemetryOptIn.vue` as the `--input-label` exemplar, a file that no longer exists. Note that the effective background varies: against the tinted `--box-bg` used by boxed content, `--muted` drops to 1.84:1 in light mode and 3.54:1 in dark, and `--input-label` reaches 4.77:1 and 9.14:1. Point the exemplar at a surviving consumer of `--input-label`.

- [repo] `pkg/rancher-desktop/utils/testUtils/setupVue.ts` installs a global `t: key => key` mock for every Jest test through `config.global.mocks`. A component spec that mounts a template calling `t(...)` therefore needs no per-test translation mock, and its absence is not a defect. Specs that assert on rendered translated text supply their own `t` through `global.mocks` instead.

- [repo] Page-header action components are resolved by filename, not by registration: `TheTitle.vue` dynamically imports `@pkg/components/${componentName}.vue` from the `action` string a page passes to `page/setHeader`. A component referenced only by that string and imported nowhere is wired correctly, so an "unregistered component" finding against one is a false positive.

## Design Observations

### Concerns

**Fetching in main, parsing in the renderer, splits the feed's trust boundary across two processes** *(future)*. `background.ts:810-821` returns raw XML across IPC, and `BlogFeed.vue:21-37` parses it in a window running `nodeIntegration: true, contextIsolation: false` (`window/index.ts:134-135`). The current code handles this correctly — `safeLink` (lines 61-71) rejects non-http(s) schemes before any `href` is bound, all text goes through `{{ }}` interpolation, and no `v-html` touches feed content — but the invariant lives entirely in one component, and the next person to add a field (an author avatar `<img src>`, a category link, a rendered excerpt) inherits a Node-integrated renderer holding remote markup. Parsing in main and returning a typed `{title, link, summary, date}[]` would move the untrusted-string boundary to the IPC edge, make the schema the contract, and let the type signature at `typings/electron-ipc.d.ts:131` carry the guarantee instead of a comment. The tradeoff is that main has no `DOMParser`, so it would need a small XML dependency — which is why the current split is a reasonable call for now.

**Two components independently drive the same IPC handshake** *(in-scope)*. `General.vue:52-56` and `AutoUpdateCheckbox.vue:24-32` both register `settings-update` / `settings-read` / `update-state` listeners and both `send('settings-read')` and `send('update-state')`, so each page load runs the handshake twice and every listener sees both replies. It is harmless — `background.ts:705` uses `event.reply` and `main/update/index.ts:67-68` broadcasts, so both instances converge on the same state — and it is the price of the action-slot component having no props, which the docstring at `AutoUpdateCheckbox.vue:8-11` states deliberately. Worth noting because a third action-slot consumer would multiply it again; a shared composable or a Vuex module for settings would collapse it.

### Strengths

- `safeLink` (`BlogFeed.vue:61-71`) validates by parsing with `URL` and allowlisting `url.protocol`, not by prefix-matching the string — the right mechanism for this check — and the comment names precisely why it matters in this renderer. The spec covers it with an actual `javascript:` payload in the fixture (`BlogFeed.spec.ts:85-90`).
- Every non-obvious CSS decision in `UpdateStatus.vue:171-217` carries a comment explaining the layout constraint it satisfies, including why the Card's own title and `<hr>` are hidden and why `justify-content: flex-start` is needed. This is the kind of styling that is normally impossible to change safely six months later.
- The feed uses `--box-bg` / `--border` / `--shadow` and matches the existing `box-shadow: 0 0 20px var(--shadow)` from `assets/styles/global/_resource.scss:19`, so it themes correctly in both modes without introducing a fixed colour.
