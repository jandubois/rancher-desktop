Executive Summary ¶

The PR adds an experimental language picker to Application → General preferences and moves that page's hard-coded labels into translation keys. The wiring is correct: keys resolve, {appName} auto-injects, the picker reuses the shared locale inventory, application.locale validates, and locked state threads through the fieldset. No Critical or Important issue survives slice-scope review. The findings are minor accessibility and cleanup suggestions, plus locale-registration and further-localization work that later i18n groups already own.

All four reviewers agree there are no correctness or security defects. The substantive material sits in Design Observations, because this PR is one slice of the i18n rollout: localizing other components (UpdateStatus.vue, the telemetry fineprint) is the extraction group's job, translating the new keys is the locale groups' job, and the zh-hans-selectable-but-CLI-rejected mismatch is pre-existing on main — the #10618 review already raised it and deferred it to groups 9/10. Findings that read as "you forgot to localize X" are planned work, not defects here.

Review Process Notes ¶

Repo context updates ¶

  • [repo] Rancher Desktop's i18n feature lands as a stacked series of narrow slices — runtime layer, language picker, string extraction, then one commit per locale. A slice that localizes only its own component or page, or that adds en-us keys without translating them, is following the plan, not omitting work: new keys fall back to English text (not a %key% placeholder) until a later per-locale slice translates them, and unrelated components keep hard-coded strings until the extraction slice converts them — each under its own component-namespaced key, never by reusing another page's key. When reviewing an i18n-slice PR, confirm a localization gap belongs to this slice before flagging it, and prefer a component's own key namespace over a cross-page key.
  • [repo] UPDATE the repo overview: it lists the renderer as "Vue 2", but package.json pins vue at 3.5.x and the code uses Vue 3 constructs (defineComponent, emits, v-model:value). Correct the framework version so reviewers stop applying Vue 2 assumptions.
