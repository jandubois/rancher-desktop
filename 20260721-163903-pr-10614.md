I1. **`optionalDependencies` are excluded, leaving `posix-node` bundled and inert** — `scripts/lib/build-utils.ts:248` [Claude Opus 4.8]

Those are production dependencies (electron-builder ships them), and
`background.ts:123` loads one at runtime via `import('posix-node')`. The
predicate tests `dependencies` only, so `posix-node` gets bundled.

also yields `setpgid is undefined`. It is in scope because this PR rewrites the
deciding predicate.

```diff

+            const runtimeDeps = { ...this.packageMeta.dependencies, ...this.packageMeta.optionalDependencies };

+            if (!packageName || !Object.hasOwn(runtimeDeps, packageName)) {
```

With that change the same probe reports `setpgid is function`.

I2. **Preload inherits `module-import` while emitting CommonJS** — `scripts/lib/build-utils.ts:330` [Claude Opus 4.8, Codex GPT 5.6 Sol, Gemini 3.1 Pro]


## Suggestions

S1. **`in` consults the prototype chain** — `scripts/lib/build-utils.ts:248` [Claude Opus 4.8]

```ts
            if (!packageName || !(packageName in this.packageMeta.dependencies)) {
```

`packageMeta.dependencies` is a plain JSON object, so `in` also matches
`Object.prototype` keys: `'constructor'`, `'toString'`, and `'__proto__'` all
test true and would be externalized as dependencies that do not exist. No such
request occurs today, and the replaced `Object.keys(...)` had no such hole.

Fix: `Object.hasOwn(this.packageMeta.dependencies, packageName)`. It reads as an
own-key membership test and folds into I1's replacement at no cost.

S2. **`externalSpecifier` probes only `.js` and fails open** — `scripts/lib/build-utils.ts:33` [Claude Opus 4.8]

```ts
  } catch {
    return request;
  }
```

The `catch` conflates "the package publishes an `exports` map and resolves the
bare subpath itself" with "this subpath does not resolve at all," while the
docstring at line 23 asserts only the first. The probe is `.js`-only, so a
subpath resolving to `.cjs`, `.mjs`, or a directory `index.js` falls through to
the bare request and fails at runtime, which is the silently-shipped shape this
PR fixes.

Latent today: the consolidator confirmed all 33 emitted specifiers resolve under
ESM import conditions. Note that the probe uses `require.resolve` (require
condition) while the emitted external resolves under `import`; a dual-published
package can map those to different files.

Fix: probe the real extension set and throw when nothing resolves, so the
failure lands at build time. Either narrow the behaviour to match the docstring,
or widen the docstring.

## Review Process Notes

**Skill improvements**

- When a review's changed files are build or bundler configuration, verify
  findings by running the build and inspecting the emitted artifact rather than
  reasoning from the config alone. Bundler semantics depend on the interaction
  of target, output type, and externals in ways that are not legible from the
  diff, and the resulting defects ship silently because the build still
  succeeds. Where a finding claims a package is or is not correctly handled,
  build once and read the artifact — a single build settles claims that would
  otherwise need a clarification round.

- Treat an agent's report of its own verification run as a claim to check, not
  evidence, whenever the same report also states an environment limitation that
  would prevent that run. Reviewers routinely describe a reproduction they
  could not have executed; reconcile against your own run or label it
  unverified before repeating it.

- When a review agent's output describes work it performed on the codebase
  ("we added tests", "I fixed"), check whether it modified its worktree. A
  review agent that writes code has stopped reviewing the change and begun
  reviewing its own edit, and its coverage claims no longer describe the PR.
  Verify with `git status` in the agent's worktree before accepting its
  Coverage Summary.

**Repo context updates**

- `[repo]` The webpack main-process config externalizes packages by testing the
  request's package name against one `package.json` section. `package.json`
  also declares `optionalDependencies` (native or platform-specific packages),
  which electron-builder ships as production dependencies and which app code
  loads at runtime. When reviewing changes to the externals predicate, check
  every runtime manifest section, not just `dependencies` — a native package
  omitted from the predicate is bundled, its binding fails to load, and
  packages that wrap the load in `try`/`catch` degrade to an empty module with
  no error.

- `[repo]` `webpackPreloadConfig` is derived from `webpackConfig` through
  `_.merge`, so any change to the main config's `externals`, `experiments`, or
  `output` is inherited by the preload build, which targets `electron-preload`
  with a CommonJS library type. When reviewing a change to the main webpack
  config, check what it does to the preload build — the two targets disagree on
  module format, and the preload graph is small enough that an incompatibility
  stays latent until someone adds an import.

**I2. `externalSpecifier` fails open: an unresolvable subpath silently becomes a runtime crash — `scripts/lib/build-utils.ts:29-35` (important, gap)**

## Design Observations

### Concerns

**Spelling the extension in the source removes the guessing layer entirely (in-scope).** `externalSpecifier`, `createRequire`, and the resolve-probe exist only because some subpath imports omit `.js`. The repo already writes both styles — `pkg/rancher-desktop/utils/object.js:2-9` and `integrations/manageLinesInFile.ts:3` use `lodash/cloneDeep.js`, `lodash/isEqual.js`, while `backend/lima.ts:14-15` and `utils/resources.ts:3` use `lodash/merge`, `lodash/omit`. `tsconfig.json` sets `moduleResolution: "Bundler"`, so `.js` specifiers type-check today (proven by the existing `.js` imports). Normalising the ~12 extensionless subpath imports to carry `.js` reduces the externals entry to a pure predicate with no filesystem probing, no fail-open branch (I2), and no build-time/runtime resolver-condition mismatch. Cost: the mock keys in `pkg/rancher-desktop/main/update/__tests__/index.spec.ts:63-65` need the same suffix.

**A dependency-list-keyed predicate re-opens whenever the list moves (future).** The main process runs in Node with the full `node_modules` tree present in the asar, so nothing under `node_modules` *needs* bundling. Externalizing by "is this a bare specifier?" rather than "is this key in one specific `package.json` section" removes the whole class: I1 (optional deps), transitive packages pulled in by a bundled dependency, and any future section split. Worth measuring against startup cost and confirming `asarUnpack: '**/*.node'` still covers the natives before adopting.

### Strengths

- Switching from named-import-friendly `modern-module` to namespace-based `module-import` is the safer interop choice for the CJS packages this bundle consumes — a namespace import survives cjs-module-lexer failing to detect a named export, where a named import throws at load.
- The comment at lines 234-243 records both the trap and the two rejected alternatives, which is exactly what stops the next refactor from reintroducing the bug.
