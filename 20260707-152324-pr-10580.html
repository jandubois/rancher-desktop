Executive Summary ¶

The top commit adds the translation data model: per-locale English-source snapshots for drift detection (metadata.go), a comment-preserving yaml.Node document layer (yaml.go), and the meta subcommand. The metadata and drift logic are correct and well-tested. Two latent design flaws stand out: the node layer's dotted-key path model corrupts keys that contain literal dots, and metadata files land where the renderer's locale glob will ingest them.

Only the top commit is new to this PR; the two lower commits come from the stacked base PR (#10107), so findings in scan.go and other base files belong there. Both Important findings are latent — neither is reachable through any command this PR wires up — but both sit in the foundational data model the PR exists to establish. Codex raised both; Claude cleared the same files with only suggestions, and Gemini's two headline findings were hallucinations against code that reads correctly on disk.

S2. stripOverrideMarker strips by substring while commentHasOverride matches exactly Claude¶

commentHasOverride (yaml.go:87) counts a line as a marker only when it equals # @override or starts with # @override (the test pins # @overridden → false). stripOverrideMarker deletes any line containing @override, so a value update drops a translator note like # @overridden spelling — a comment this layer exists to preserve. Latent: only nodeSetLeaf reaches it.

src/go/i18n-report/yaml.go

// overrideMarker is the comment line that protects a hand-tuned translation.
const overrideMarker = "# @override"

// commentHasOverride returns true if a comment string contains @override.
func commentHasOverride(comment string) bool {
	for _, line := range strings.Split(comment, "\n") {
		trimmed := strings.TrimSpace(line)
		if trimmed == overrideMarker || strings.HasPrefix(trimmed, overrideMarker+" ") {
			return true
		}

Fix: strip with the same predicate commentHasOverride uses.

S6. Indirect-key regexes are stricter than the canonical dottedKey Gemini¶

dottedKeyLiteral (scan.go:44) and indirectKeyPattern (scan.go:64) require [a-z][a-zA-Z0-9]* segments — no underscore, lowercase-first — while the dottedKey const allows [a-zA-Z0-9_-]. Real keys break the stricter form: onlyFromVentura_x64, RBAC_ROLE, storage_class_provisioner. A key referenced only indirectly (a string value or ternary) is then missed and reported unused; direct t() calls use dottedKey and are unaffected. This lives in base PR #10107; commit 0dd432ac5 routed other patterns through dottedKey but left these two.

Design Observations ¶

Concerns ¶

  • The path model should match runtime lookup semantics (in-scope) Codex — I2 shows the Go model and the JS runtime already disagree on object-path rules. Carrying []string path segments internally and formatting only at report boundaries, or sharing one escaping convention with the JS get, removes a whole class of bugs around dots, slashes, and quoted keys.

Strengths ¶

  • Atomic metadata writes (in-scope) Claude — writeFileAtomic (repo.go:70) writes a temp file and renames it, cleaning up on every error branch, so an interrupted write cannot truncate the target.
  • Sound drift guard (in-scope) Claude Codex — regenerateMetadata blocks regeneration that would erase outstanding drift markers, while bootstrap and --force proceed. Every state traces correctly.
  • Drift compares decoded values (in-scope) Claude — routing both sides through the same YAML decoder makes drift robust to cosmetic English edits (re-quoting, block-vs-plain scalars). Good choice, though under-documented (S1).
  • Tests lead consumers (in-scope) Claude Codex — the node layer ships with its own tests ahead of merge/remove, keeping each PR in the stack reviewable.

Testing Assessment ¶

Coverage of the new code is strong: nodeSetLeaf insert/update/get, single-line serialization, override placement and detection, the drift guard's block/force/bootstrap states, and metadata round-trips (including a multi-line value). Gaps, ranked by risk:

  1. Keys with literal dots — no node-layer test round-trips a key like secret.types.'kubernetes.io/dockercfg'. Such a test would have caught I2.
  2. Metadata excluded from renderer discovery — no test or fixture asserts generated metadata stays out of the renderer's locale glob. This would have caught I1.
  3. stripOverrideMarker on value change — no test updates an @override leaf with an empty comment and asserts the marker drops while other comment lines survive (S2).
  4. serializeNode multi-line branch (yaml.go:379) and nodeSetLeaf error branches (yaml.go:220, yaml.go:238) are unexercised. I verified the multi-line and long-scalar round-trips by hand; nothing pins them against a yaml.v3 bump.
  5. meta --locale=all — the loop and aggregate-findings path in runMeta are untested; only single-locale regenerateMetadata is.

Documentation Assessment ¶

  • S1 covers the inaccurate compute.go and loadYAMLFlat comments.
  • README.md's meta section documents only --locale=de; it omits --force and --locale=all, both of which the subcommand accepts. One line closes the gap.

Commit Structure ¶

Clean. The top commit is one self-contained concept with an accurate message. The two lower commits belong to base PR #10107 and are out of scope; the diff shrinks to the single top commit once that PR merges.

Acknowledged Limitations ¶

  • The node layer ships without a production consumer. nodeSetLeaf, serializeYAMLNode, loadYAMLDocument, nodeGetLeaf, and siblings are reached only by tests. Intentional per the stack plan (merge/remove/validate/drift follow in later PRs) — not flagged as YAGNI.
  • The metadata header credits merge, not meta. metadata.go:50 writes "Auto-generated by i18n-report merge"; the PR explains that merge updates the file during routine translation while meta bootstraps or regenerates it.
  • Rescan performance. A prior comment noted every subcommand rescans the source tree; the author declined it, citing compiled runs under half a second. The implementation stays consistent with that rationale, so this review does not flag it.
  • nodeSetLeaf leaves valNode.Style unreset on a value update. Documented at yaml.go:230 as safe for the only in-tree serializer; a latent snag only if a future caller marshals these nodes via yaml.Marshal directly.

Review Process Notes ¶

Skill improvements ¶

  • When a PR is stacked on an unmerged base PR, the merge-base diff includes the base PR's commits, so the Changed Files list mixes files the top commit introduces with files inherited from below. Run git show --stat <head> to find which files the top commit actually changes, scope findings to those, and mark any finding in an inherited file as belonging to the base PR's review rather than raising it as net-new. Reviewers that cannot separate the two (for example, one that skips git blame) will concentrate their findings in inherited code and mislabel scope.

Repo context updates ¶

  • [repo] The renderer discovers locales in pkg/rancher-desktop/store/i18n.js via a recursive webpackContext('@pkg/assets/translations', { recursive: true, regExp: /.*/ }), keying each match by filename basename. Any file added anywhere under assets/translations/ — including a subdirectory — becomes a locale entry in state.available and ships in the renderer bundle. Flag any change that writes non-locale files (metadata, fixtures, generated artifacts) into that tree.
  • [repo] Translation keys in en-us.yaml include leaf keys that contain literal dots and slashes — for example kubernetes.io/dockercfg and bootstrap.kubernetes.io/token under secret.types. Any code that flattens nested keys into dotted paths, or splits dotted paths back into segments, must be quote/dot-aware or it corrupts these keys. Verify key round-trips against these, not only simple a.b.c keys.
