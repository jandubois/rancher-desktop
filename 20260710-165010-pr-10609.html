Executive Summary ¶

This PR replaces the manifest's per-dependency checksums map with an assets list, where each artifact carries its own platform, arch, url, and checksum, so the install path selects and verifies an asset without reconstructing URLs. It adds rddepman --regenerate. The refactor is thorough, correct, and well unit-tested; every dependency class was converted and selectors resolve to exactly the manifest's assets. The one notable issue is a dropped commit-SHA validation for the Moby spec.

All three reviewers converged on "approve." No critical issues surfaced. The single Important finding — a validation guard this PR removed — was raised by two reviewers (Codex as important, Claude as a suggestion); verifying against the merge-base confirmed the guard existed before and now does not. The remaining findings are hardening and clarity suggestions. Codex flagged the credential-helper guard as important; Claude independently traced the same path and judged it adequate, so it lands as a suggestion here.

scripts/lib/dependencies.ts
 * version string; `alpineLimaISO` and `mobyOpenAPISpec` track a structured
 * version (see {@link AlpineLimaISOVersion} / {@link MobyOpenAPISpecVersion}),
 * so those two shapes are accepted too.  A bare YAML number (e.g. `1.0`) is
 * rejected so an unquoted version cannot silently lose precision.
 */
function parseVersion(name: string, path: string, raw: unknown): Version {
  if (typeof raw === 'string') {
    return raw;
  }
  if (raw && typeof raw === 'object' && !Array.isArray(raw)) {
    const obj = raw as Record<string, unknown>;

    if (typeof obj.isoVersion === 'string' && typeof obj.alpineVersion === 'string') {
      return { isoVersion: obj.isoVersion, alpineVersion: obj.alpineVersion };
    }
    if (typeof obj.apiVersion === 'string' && typeof obj.commit === 'string') {
      return { apiVersion: obj.apiVersion, commit: obj.commit };
    }
  }

  throw new Error(`Entry ${ name } in ${ path } has invalid version ${ JSON.stringify(raw) }; expected a string or a structured version`);
}

Design Observations ¶

Strengths

  • (in-scope) The AssetSelector / selectAsset / selectAssets abstraction separates "which artifact" from "how to install it," and the exactly-one contract turns a silently-missing asset into a hard error at install time. Claude Codex Gemini
  • (in-scope) Every resolved URL is version- or commit-pinned (GitHub release assets, raw.githubusercontent.com/<commit>, versioned S3/chart paths) — no mutable refs, so upstream drift is caught by checksum rather than swapped in silently. Claude
  • (in-scope) serializeAsset fixes key order so the emitted YAML is deterministic regardless of how the asset object was built; the round-trip and structured-version tests lock this in. Claude
  • (in-scope) The extracted cartesian helper replaces several near-duplicate nested platform/arch loops with one matrix. Gemini

Concerns

  • (future) The migration path is asymmetric: new code tolerates an old checksums entry by parsing it to assets: [], but --regenerate cannot fully migrate an all-old manifest — non-regenerable electron trips the precheck with empty assets and aborts before any dependency is rewritten. Moot post-merge (the committed manifest is already new-format and the tolerance is marked temporary), but relevant if the tool is ever pointed at a stale branch. Claude

Testing Assessment ¶

Library-level coverage is strong and meaningful — the new tests exercise real selection, parse, and serialize logic, not mocks: manifest round-trip, structured versions, the DO-NOT-EDIT header, legacy-schema tolerance, invalid platform/arch/checksum/version rejection, selector ambiguity, and the credential-helper count guard.

Untested surfaces, by risk: regenerateAssets orchestration (the non-regenerable precheck and the skip-then-rewrite loop) has no test, and a regression there silently corrupts the manifest — the precheck logic could be extracted and unit-tested even though the full loop needs network and git; parseArgs unknown-config rejection and --regenerate detection are untested; and the successful DockerProvidedCredHelpers baseName-reconstruction path (the strip of -v<version>.<platform>-<arch>/.exe) is untested, though the count-check throw is covered.

No agent executed the suite: Codex reported that yarn and a Jest binary were unavailable in its worktree copy, so the tests were read but not run.

Documentation Assessment ¶

The manifest header comment and the DependencyAsset / DependencyEntry docstrings are accurate and match the emitted YAML. RawAsset / RawEntry lack docstrings but are internal, which is acceptable.

Two out-of-diff comments still describe the manifest as holding "checksums" — scripts/postinstall.ts:188 ("load desired versions and checksums of dependencies") and scripts/dependencies/global.ts:1 ("whose version and checksums live in dependencies.yaml"). Both now hold versions plus assets (each asset carries a checksum); update the terminology when convenient. S3 covers the one misleading in-diff comment.

Acknowledged Limitations ¶

  • Migration tolerance is temporary — dependencies.ts:224-228 accepts an entry with no assets list so --regenerate can migrate an old checksums-schema manifest; the author flags it for removal once this lands on main, and the committed manifest is already new-format, so install never relies on it.
  • Electron opts out of regeneration — electron.ts:35-37: its assets are pinned to the package.json version, which a regenerate cannot resolve, so regenerable = false and rddepman bumps it instead.
  • Qemu has no Linux/arm64 build — lima.ts:95,115: the download skip and the getAssets combos both omit linux/arm64, and the manifest matches (3 qemu assets). Pre-existing, correctly mirrored.

Review Process Notes ¶

Skill improvements

  • When reviewing a refactor that relocates or restructures validation, enumerate the guards (format checks, required-field assertions, exact-identity lookups) present on the touched code paths at the merge-base and confirm each still fires after the change. A guard that existed before and is absent afterward is a regression even when no test fails and the happy path is unchanged — the check most often disappears when a value that was validated at its point of use becomes a pre-resolved field that later code reads blindly from a manifest or config. (Check whether the dimensions already ask for this before adding.)

Repo context updates

  • [repo] pkg/rancher-desktop/assets/dependencies.yaml is machine-generated by rddepman and marked DO-NOT-EDIT. When a finding's only trigger is a malformed or inconsistent manifest, calibrate severity by whether a manual-edit path is documented: most dependency classes generate their entries correct-by-construction, so treat corruption-only findings as low severity — but a class that documents hand-editing a field (e.g. mobyOpenAPISpec.version.commit, "edit dependencies.yaml manually") makes weak validation of that field a genuine, higher-severity gap.
