## Suggestions

S1. **`openPreferences` re-runs its tail on every reopen and the one-time guard leaks** — `pkg/rancher-desktop/window/preferences.ts:101` [Codex GPT 5.6 Sol, Gemini 3.1 Pro]

```ts
  window.webContents.on('ipc-message', (_event, channel) => {
    if (channel === 'preferences/load') {
      window.show();
    }
  });

  window.on('close', (event) => {
```

`createWindow` returns the open preferences window (`window/index.ts:69`), yet `openPreferences` re-runs this tail on every tray or menu invocation. Round 3's fix put `onLocaleChange` inside the `if (!Shortcuts.isRegistered(window))` guard (line 36), but `Shortcuts` clears that sentinel on the cancellable `close` event (`utils/shortcuts.ts:143`), not `closed`. Cancel a dirty close and the surviving window loses its sentinel, so the next open passes the guard and adds a second listener; Codex reproduced `localeCallbacks=2`. The `ipc-message` and `close` handlers here never had a guard, so they stack on every reopen, and each `close` runs `showMessageBoxSync` (line 114), so a dirty window shows one discard dialog per prior open. Both paths predate this PR and self-heal once the window truly closes.

Fix: clear the shortcuts sentinel on `closed` and move the sibling handlers inside the guard, or early-return when the window already exists (as `window/dashboard.ts:13` does), which covers every listener at once.

```diff
-      window.on('close', () => {
+      window.on('closed', () => {
         delete this.windows[id];
       });
```

## Design Observations

### Concerns

- **The renderer imports the whole `package.json`, and the leaner alternatives were tried and rejected** `(in-scope)` [Claude Opus 4.8, Gemini 3.5 Flash] — `store/i18n.js:3` binds the whole manifest (about 7 KB: 37 dependencies, 70 devDependencies, 36 scripts) to read only `productName` at line 91. Claude proposed a named import; Flash a `DefinePlugin` constant. Neither is right here. A named import (`import { productName }`) breaks jest, whose ESM treats JSON as default-export-only and never sees the named export webpack synthesizes; the author tried it and dropped it. A plain default import without the attribute loads but makes jest emit a JSON-import deprecation warning, which fails the repo's pristine-test-output rule and becomes a hard error in a later Node, so the author landed on the attribute form (`with { type: 'json' }`), the one variant that passes jest, eslint, babel, and webpack, all four verified when the commit landed. Flash's `DefinePlugin` route is ruled out separately. A hardcoded value would not track `productName`, and tracking it is the point, so `appName` becomes "Rancher Desktop 2" automatically on the rancher-desktop-2 merge. The 7 KB is an accepted cost, and nothing sensitive leaks since the repo is public. A future reviewer should not re-suggest either form; a one-line comment on the import would head that off in code.
- **`{appName}` now tracks `productName`, but ~36 corpus strings still spell out "Rancher Desktop"** `(future)` [Claude Opus 4.8] — Commit `105069d8d` makes the renderer's 8 `{appName}` keys resolve to `productName`, and the main-process menu passes `Electron.app.name`, so both become "Rancher Desktop 2" automatically on the rancher-desktop-2 merge. The source text of 36 other keys hard-codes "Rancher Desktop" (`en-us.yaml:63` `tray.tooltip`, `:75` `tray.quitRancherDesktop`, `:115`, `:436`), which will read wrong after that merge. This is the deliberate app-wide pattern (literal source text), not a defect in this slice, so the RD2 merge should plan a corpus sweep rather than this PR fixing one instance.
- **`DiagnosticsBody.vue` builds headers in `computed` where the README prefers `data()`** `(future)` [Claude Opus 4.8] — carried from Round 3 and unchanged; both patterns are blessed, so this is a consistency note, not a finding.

### Strengths

- The CI gate (`i18n-report check --locale=all`, `test.yaml:23`) mechanically guarantees every referenced key exists and none is orphaned; both Codex and Claude ran it green (0 unused, 0 undefined) [Claude, Codex, Gemini 3.5 Flash].

### Acknowledged Limitations

The following limitations have been previously reviewed and accepted as intentional tradeoffs:
- **Relative-Time Tooltip Locale:** Relative timestamps in the Diagnostics page ("Last run") are captured in `data()` and deferred in-code (`pkg/rancher-desktop/components/DiagnosticsBody.vue:18`).
- **Volumes Breadcrumb:** The hardcoded literal `"root"` breadcrumb is a deferred design question (`pkg/rancher-desktop/pages/volumes/files/_name.vue:2`).
- **E2E / Live Switch Tests:** Complex multi-window live locale-switch integration tests remain omitted as low-value compared to the automated unit tests.
- **Startup Errors:** Early-startup errors in `deploymentProfiles.ts` continue to fall back to English by design due to early subsystem loading sequences.
- **UpdateStatus Punctuation:** Semicolon/period hardcoding in `UpdateStatus.vue` is accepted and deferred.
- **Table Headers Refresh:** Re-rendering of table headers captured inside standard `data()` properties is delayed until component remount by design; `DiagnosticsBody.vue` uses `computed` headers which is the blessed pattern.
- **Scanner Blind Spots:** Known and documented scanner blind spots (`showErrorBox`, port-forward errors) are accepted limits.
