## Suggestions

S1. **`AutoUpdateCheckbox` scoped style reaches into `RdCheckbox`'s root class** — `pkg/rancher-desktop/components/AutoUpdateCheckbox.vue:67` [Claude Opus 4.8]

```scss
// The title line sizes itself to the heading; center the checkbox against it.
.rd-checkbox-container {
  display: flex;
  align-items: center;
  height: 100%;
}
```

This scoped rule centers the checkbox by matching `.rd-checkbox-container`, the root element of `RdCheckbox` (`form/RdCheckbox.vue:43`). Vue stamps a parent's scope id onto a child's root, so the rule reaches that class today — but it couples this component's centering to `RdCheckbox`'s internal class name, and a rename there would break the centering with no error. Sixteen component files reach into child internals through an explicit `:deep()` (for example `UpdateStatus.vue:189`), which names the coupling instead of relying on it.

Fix: center a wrapper this component owns, or make the reach explicit with `:deep(.rd-checkbox-container)`.

S2. **Repeated "Read more" links share one accessible name** — `pkg/rancher-desktop/components/BlogFeed.vue:96` [Codex GPT 5.5]

```vue
        <p class="blog-entry-summary">
          {{ entry.summary }} <a
            :href="entry.link"
            class="blog-entry-more"
          >Read more</a>
        </p>
```

Every "Read more" link exposes the same link text to screen-reader link navigation, though each opens a different post. The title link above it (`:89-92`) is unique, so a user tabbing the summary links lands on destinations they cannot tell apart.

Fix: give each link an accessible name that includes the post title.

```diff
  {{ entry.summary }} <a
    :href="entry.link"
+   :aria-label="`Read more: ${ entry.title }`"
    class="blog-entry-more"
  >Read more</a>
```

S3. **Malformed-XML test asserts only that something throws** — `pkg/rancher-desktop/components/__tests__/BlogFeed.spec.ts:93` [Codex GPT 5.5]

```ts
  it('throws on XML it cannot parse', () => {
    expect(() => parse('<rss><channel><item></rss>')).toThrow();
  });
```

`parse` mounts the component before calling `parseFeed`, so a bare `toThrow()` passes for any error — including a mount or setup failure that never reaches the `parsererror` branch (`BlogFeed.vue:24`). Pinning the message ties the test to the parser failure it was added to guard.

```diff
-    expect(() => parse('<rss><channel><item></rss>')).toThrow();
+    expect(() => parse('<rss><channel><item></rss>')).toThrow('Could not parse the blog feed XML');
```

S4. **Empty update-status wrapper adds a flex gap when no update is available** — `pkg/rancher-desktop/components/UpdateStatus.vue:2` [Gemini 3.1 Pro]

```vue
<template>
  <div class="update-status">
    <template v-if="hasUpdate">
```

When neither `hasUpdate` nor `unsupportedUpdateAvailable` holds — the common case — the component still renders an empty `<div class="update-status">`. `General.vue`'s `.general` is a flex column with `gap: 0.625rem`, so the empty box stays a flex item and inserts an extra 10px between the `<hr>` and the blog feed below it. The empty wrapper predates this PR, but the feed now sits directly beneath it, so the gap is newly visible. `BlogFeed.vue` avoids this by putting its `v-if` on its own root (`:77`).

Fix: gate the root element itself.

```diff
-  <div class="update-status">
+  <div v-if="hasUpdate || unsupportedUpdateAvailable" class="update-status">
```

S5. **`firstParagraph` skips the rest of a post when its first paragraph is empty** — `pkg/rancher-desktop/components/BlogFeed.vue:45` [Gemini 3.5 Flash]

```js
      const post = new DOMParser().parseFromString(encoded, 'text/html');
      const summary = new DOMParser().parseFromString(description, 'text/html');
      const text = post.querySelector('p')?.textContent || summary.body.textContent || '';
```

`post.querySelector('p')` takes the first `<p>` in `content:encoded`. If that paragraph is empty (`<p></p><p>real text</p>`), its `textContent` is falsy, so `||` discards the rest of the post and falls back to the `description`. The Rancher feed's posts open with real text, so this is a robustness edge case rather than an observed break.

```diff
-      const text = post.querySelector('p')?.textContent || summary.body.textContent || '';
+      const paragraph = [...post.querySelectorAll('p')].find(p => p.textContent?.trim());
+      const text = paragraph?.textContent || summary.body.textContent || '';
```

S6. **A blog-load failure is invisible to the user** — `pkg/rancher-desktop/components/BlogFeed.vue:16` [Claude Opus 4.8]

```js
    } catch (error) {
      console.error('Failed to load the blog feed:', error);
    }
```

The PR frames the blog as a last-resort channel when auto-update and release notes both fail, yet a fetch or parse failure only writes to `console.error` and hides the section via `v-if="entries.length"` (`:78`); the user sees nothing. The renderer console forwards to the main log, so operators can still diagnose it. This is a deliberate graceful degrade, so the only cost is that a future reader may "fix" the silence into an error banner.

Fix: keep the silent degrade; add a one-line comment at `:16` recording that hiding the section on failure is intentional.

## Design Observations

### Concerns

- **Duplicated IPC wiring between `General.vue` and `AutoUpdateCheckbox.vue`** `(future)` [Claude Opus 4.8] — Both subscribe to `settings-update`/`settings-read`/`update-state` and re-request `settings-read` and `update-state` (`General.vue:52-56`, `AutoUpdateCheckbox.vue:24-33`), so each General visit runs the round-trips twice and keeps two copies of `enabled`. The header `action` slot renders its component with no props (`TheTitle.vue`), which forces the action component to source its own state, as Snapshots and Images already do. No change is warranted here; a props channel on the slot would let the two share one subscription.

### Strengths

- **Untrusted feed content cannot inject** `(in-scope)` [Claude Opus 4.8, Codex GPT 5.6-sol, Gemini 3.5 Flash] — feed text reaches the DOM only through mustache interpolation, `safeLink` rejects non-http(s) schemes before an `:href` binding, and HTML is stripped by parsing into an inert `DOMParser` document rather than `v-html`.
- **Main-process fetch is the right layer** `(in-scope)` [Gemini 3.1 Pro, Codex GPT 5.6-sol] — `Electron.net.fetch` in `background.ts` bypasses renderer CORS and inherits Chromium's proxy configuration, so users behind a corporate proxy still reach the feed.
- **The refactor simplifies `UpdateStatus.vue`** `(in-scope)` [Claude Opus 4.8] — dropping the embedded checkbox and the `updatesEnabled` getter/setter collapses a prop round-trip that had spanned two components.
- **Independent scroll regions** `(in-scope)` [Gemini 3.5 Flash, Codex GPT 5.6-sol] — the update card and the feed each scroll their own content, so neither crowds the other off a short window.

## Review Process Notes

### Skill improvements

- When a reviewer reports concrete execution results — a test pass/fail count, a built binary, a green suite, a live control plane — confirm the review environment could actually produce them before repeating the claim in the consolidated report. A reviewer sometimes states a static count, or a run against a broken or partial toolchain, as if it were a clean pass. Recognise the pattern when one reviewer reports executed results that its siblings say they could not run at all; reconcile by reproducing the run or labelling the claim unverified, never by passing it through.

### Repo context updates

- [repo] A repo-wide jest failure — `TS1378` on top-level `await import`, or "Cannot use import statement outside a module" across many unrelated specs — is almost never a PR defect. It signals a local toolchain problem: a jest/ts-jest major-version skew in `node_modules`, or locked `.claude/worktrees` adding duplicate spec files that collide in the haste map. The repo's standard unit-test pattern is `mockModules` plus a top-level `await import` of the component under test, which needs the ESM ts-jest transform intact. When the suite will not run, assess changed specs statically against that pattern rather than reporting the failure against the PR.

```javascript
    firstParagraph(item) {
      // Prefer the first paragraph of the full post; fall back to the RSS summary.
      // Both may embed HTML, so read parsed text rather than raw markup.
      const encoded = item.getElementsByTagName('content:encoded')[0]?.textContent ?? '';
      const description = item.querySelector('description')?.textContent ?? '';
      const post = new DOMParser().parseFromString(encoded, 'text/html');
      const summary = new DOMParser().parseFromString(description, 'text/html');
      const text = post.querySelector('p')?.textContent || summary.body.textContent || '';

      return text.replace(/\s+/g, ' ').trim();
    },
```

Currently, `post.querySelector('p')` selects the very first paragraph element. If that paragraph is empty (e.g. `<p></p><p>Actual post text...</p>`), its `textContent` is empty, causing the `||` operator to discard the rest of `content:encoded` and fall back to the `description` instead.

Fix: Iterate over the found paragraphs to identify the first paragraph with non-empty text content.
```diff
-     const text = post.querySelector('p')?.textContent || summary.body.textContent || '';
+     const paragraphs = Array.from(post.querySelectorAll('p'));
+     const firstNonEmpty = paragraphs.find(p => p.textContent?.trim());
+     const text = firstNonEmpty?.textContent || summary.body.textContent || '';
```

S2. **Defensive formatting on speed values** — `pkg/rancher-desktop/components/UpdateStatus.vue:112-117` `(suggestion, enhancement)`

      const percent = Math.floor(progress.percent);
