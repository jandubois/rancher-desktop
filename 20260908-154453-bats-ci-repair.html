# The MSI marks a machine-wide install with a registry key and opens the
# firewall for host-switch.exe (build/wix/main.wxs).  Rancher Desktop reads that
# key to decide whether to publish container ports on all interfaces, so without
# it a zip install silently behaves like a per-user one.
configure_admin_install() {
    local app_dir=$1
    local host_switch profile

    host_switch=$(cygpath --windows "$app_dir/resources/resources/win32/internal/host-switch.exe")

    MSYS2_ARG_CONV_EXCL='*' reg.exe add 'HKLM\SOFTWARE\SUSE\RancherDesktop' \
        /v AdminInstall /t REG_SZ /d true /f

    # The MSI opens the private and domain profiles, but not public.  A
    # hosted runner gives the WSL adapter no connection profile at all, so
    # Windows treats its traffic as public and neither shipped rule matches;
    # a published UDP port is then unreachable from the distro the tests run
    # in.  Categorizing the adapter is not an option, because
    # Set-NetConnectionProfile needs a profile that does not exist.  So open
    # public as well, and only here: the installed product keeps the two
    # profiles it ships with.
    for profile in Private Domain Public; do
        MSYS2_ARG_CONV_EXCL='*' netsh.exe advfirewall firewall delete rule \
            name="Rancher Desktop Networking ${profile} Exception" >/dev/null 2>&1 || :
        MSYS2_ARG_CONV_EXCL='*' netsh.exe advfirewall firewall add rule \
            name="Rancher Desktop Networking ${profile} Exception" \
            dir=in action=allow protocol=any profile="${profile}" \
            program="$host_switch"
    done
}

Design Observations ¶

Concerns ¶

  • --scale is opt-in, so the default stays wrong for slow machines (in-scope). Every new wait must remember the flag, and I1 is the first cost of that. Scaling by default with an explicit opt-out for the loops the docstring calls "expected to run out" would make the safe choice automatic; those loops appear to be few. Claude Opus 5
  • Per-file splitting multiplies fixed setup cost on the slowest runners (future). Adding containers to SPLIT_PER_FILE_ON_MAC takes the macOS matrix from 44 jobs to 78 (measured by running get-tests.py at both SHAs). Each new job pays a full artifact download, install and VM boot to run one file, and containers/published-udp-ports.bats skips everything on macOS via skip_on_unix, so two of those jobs only install. Splitting just the files that exceed a time budget, or reusing one instance across a suite, would keep the two-hour cap satisfied for fewer runner minutes. Claude Opus 5
  • NerdctlClient.waitForReady still retries forever (future). The branch adds a log line every ten failures but nothing bounds the loop, so an engine that never becomes ready stalls the start. The new comment says so itself. MobyClient.waitForReady has the same shape. This is pre-existing: the loop is byte-identical at the merge-base. Gemini 3.5 Flash

Strengths ¶

  • The commit messages carry the evidence. Each names the run ID, the measurement, and the alternative tried and rejected — 0b54d3644 on the firewall protocol, 1cc855bc1 on Set-NetConnectionProfile, 6b7116cee on the k3s version, d00838c62 on why the dropped verify-cached-images skip never matched. Reviewing 51 commits was possible because of them. Claude Opus 5
  • The dangling-symlink change is correct and non-obvious. Replacing a dangling lima symlink with an empty file made lima.ts's symlink() fail, and that failure is swallowed, so the placeholder blanked the lima logs for the rest of the run. Removing the symlink instead fixes it. Claude Opus 5
  • summarize.mjs's 'no ok ' → 'not ok ' is a real fix. The old string never matched TAP output, so failures counted as zero, and the earlier startsWith('ok ') arm cannot shadow the corrected one. Claude Opus 5
  • package.yaml's github.event.inputs.sign → inputs.sign. For a workflow_dispatch input declared type: boolean, the former is the string "false", which is truthy; the latter is a real boolean. Claude Opus 5

Review Process Notes ¶

Skill improvements ¶

  • Set the per-agent deadline from measured duration history rather than from prompt length or diff size, and record the measurement where the rule lives. Agent wall-clock does not track input size: an agent that verifies claims by running experiments spends its time per file, and one that answers from the diff finishes in a fraction of it regardless of how large that diff is.
  • When an agent times out twice with no quota or API error, drop it and say so in the report rather than raising the deadline again. A second identical failure with the agent still working means it is not deadline-aware, and a longer budget buys another full wait for the same nothing.
  • Check every agent worktree for files written outside the scratch directory, and read them. A fabricated finding is usually accompanied by the script that produced it, and comparing that script against the file it claims to test settles the finding faster than re-reading the code.
  • When a reviewer's finding rests on a language, schema, or platform default, settle it from the implementing source rather than from the reviewer's assertion or your own recollection. Vendored toolchains pin a specific version whose behaviour is readable, and a default that applies only under a sibling condition is the common shape of this error.

Repo context updates ¶

  • [repo] Jest run from the repo root collects specs from any worktree under .claude/worktrees/, so a stray worktree adds its whole suite to the run and its e2e specs fail under Jest. Pass --testPathIgnorePatterns '/node_modules/' '/pkg/rancher-desktop/sudo-prompt/' '/[.]claude/worktrees/' when a run reports failures in paths outside the main tree; overriding the flag drops the config's own sudo-prompt exclusion, which must be restated. A worktree marked locked belongs to a running session and must not be removed.
  • [repo] bats/Makefile's lint target runs from bats/, so its find scripts covers only bats/scripts. Shell added under .github/workflows/ is not linted by any target, and make lint passing says nothing about it.
  • [repo] On Windows the BATS suite runs inside the WSL distribution, not Git Bash: bats.yaml sets BATS_COMMAND to wsl.exe --distribution <distro> --exec. A helper that branches on using_windows_exe is choosing between the host's view and the distro's namespace, not between two shells.
  • [repo] The BATS CI lane installs from the zip on Windows by default, and the zip install recreates the product's firewall rules under the MSI's own names. A test that asserts on rules named Rancher Desktop Networking* is reading the test harness's rules, not the product's, unless INSTALL_MODE=installer.
