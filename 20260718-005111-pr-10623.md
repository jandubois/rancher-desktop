## Suggestions

S1. **Disclaimer text fails WCAG AA contrast** — `pkg/rancher-desktop/components/Preferences/ApplicationGeneral.vue:133` [Codex GPT 5.6 Sol]

```scss
  .locale-disclaimer {
    margin-top: 0.5rem;
    font-size: 0.85rem;
    color: var(--muted);
  }
```

The disclaimer renders `--muted` at 0.85rem (normal text) on `--body-bg`. In the light theme `--muted` resolves to `#B6B6C2` on `#FFFFFF` (2.01:1); in the dark theme to `#6C6C76` on `#1B1C21` (3.27:1). Both fall below the 4.5:1 AA threshold for normal text. The nearest sibling — the telemetry fineprint at `TelemetryOptIn.vue:45` — styles the same kind of text with `--input-label`, which passes (5.2:1 light, 8.5:1 dark).

`--muted` text is a systemic pattern (seven components use it), so this is a consistency fix rather than a defect this PR introduced, and the disclaimer only shows for experimental non-English locales. The fix is cheap and matches the sibling.

Fix: match `TelemetryOptIn.vue`'s fineprint.

```diff
-    color: var(--muted);
+    color: var(--input-label);
```

S2. **Disclaimer wraps inside the 20rem picker column** — `pkg/rancher-desktop/components/Preferences/ApplicationGeneral.vue:72` [Claude Opus 4.8]

```vue
      <p
        v-if="showLocaleDisclaimer"
        class="locale-disclaimer"
      >
        {{ t('application.locale.disclaimer') }}
      </p>
```

The disclaimer `<p>` sits inside the `<rd-fieldset class="width-xs">` (line 53), whose `.width-xs` pins the fieldset to exactly 20rem (lines 125-128). `.width-xs` exists to size the `<select>`, not the prose beneath it, so the three-sentence disclaimer wraps into a ~320px column — roughly four short lines. This is a net-new styling consequence of nesting the disclaimer inside the sized fieldset; it is cosmetic, not a defect.

Fix: give the disclaimer its own width, or move it below the fieldset.

```diff
   .locale-disclaimer {
     margin-top: 0.5rem;
+    max-width: 32rem;
     font-size: 0.85rem;
```

S3. **`.width-xs` block duplicated verbatim** — `pkg/rancher-desktop/components/Preferences/ApplicationGeneral.vue:125` [Claude Opus 4.8]

```scss
  .width-xs {
    max-width: 20rem;

  }
```

This block is byte-identical to `BodyKubernetes.vue:221`. Both are Preferences body components that size a control column. `BodyKubernetes.vue` already carries its own local copy, so the picker follows the existing convention — consistent and correct as written. Consolidate only if the team wants one source of truth. Low priority.

## Review Process Notes

### Skill improvements

- When a finding flags a new use of a shared design token or utility class (a color variable, a spacing token, a layout helper) as a defect, grep the codebase for that token's other usages before rating severity. A new instance of an established, app-wide pattern is a consistency issue scoped to the PR — rate it a Suggestion — even when the underlying pattern is imperfect, such as a low-contrast color used throughout. If the systemic pattern itself warrants attention, raise it separately as a design observation rather than inflating the single instance to Important. This keeps a genuine defect signal (e.g. a real WCAG failure) while attributing severity to what the PR actually introduced.

### Repo context updates

- [repo] Rancher Desktop styles secondary and help text with the `--muted` CSS variable in roughly seven components (`ContainerInspect`, `ContainerStats`, `ImagesScanResults`, `pages/extensions/installed`, `ContainerInfo`, `pages/volumes/files/_name`, `Preferences/ApplicationGeneral`). `--muted` resolves to `#B6B6C2` on the light `--body-bg` (`#FFFFFF`), which is 2.0:1 — below WCAG AA — and to `#6C6C76` on dark (`#1B1C21`), which is 3.3:1. A new element using `--muted` for small text follows the existing convention rather than introducing an isolated defect; rate it a consistency Suggestion. The `--input-label` token, used for preferences fineprint (e.g. `TelemetryOptIn.vue`), passes AA (5.2:1 light, 8.5:1 dark) and is the better choice for new help text.

### Design Observations

#### Strengths

- **Clean Attribute Fall-Through**: By utilizing `v-bind="$attrs"` on the native `<select>` inside `<rd-select>`, the `aria-label` and `data-test` attributes correctly fall through to the input control, maintaining excellent accessibility and testability without redundant props.
- **Idiomatic Value Synchronization**: The event binding `@change="onChange('application.locale', $event.target.value)"` uses standard native bubbling, seamlessly integrating the custom `<rd-select>` wrapper with the underlying Vuex preference-updating action.
- **Consistent Layout Restraints**: Adding the `.width-xs` (20rem) constraints to the fieldset keeps the layout aligned with the established preferences style defined in `BodyKubernetes.vue`.

### Acknowledged Limitations

- **SFC Testing Gap**: No component-level tests exist for the language picker. This was explicitly declined in Round 1 as `ApplicationGeneral.vue` does not have an existing unit spec, and the schema validators are already extensively tested.
- **README / CLI Examples**: The `adminAccess` wording in documentation files retains English literals, which is accepted as a deferred chore for the final localization sweep.
- **`zh-hans` in CLI**: The Chinese locale is selectable in the UI picker but rejected by the `rdctl` command-api schema enum. This is a pre-existing limitation on `main` and is scheduled to be resolved in future i18n locale group tasks.
- **Inline i18n Hardcoding**: Hardcoded strings like "Check for updates automatically" in `UpdateStatus.vue` or fine-print paragraphs in `TelemetryOptIn.vue` are intentional and scheduled to be extracted in subsequent localized string slices.
