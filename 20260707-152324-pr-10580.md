## Important Issues

I1. **Metadata files land in the renderer's locale-discovery tree** — `metadata.go:17` [Codex GPT 5.5]

```go
func metadataPath(root, locale string) string {
	return filepath.Join(root, translationsDir, "meta", locale+".yaml")
}
```

Metadata is written under `pkg/rancher-desktop/assets/translations/meta/`. The renderer builds its locale list from a recursive glob of that tree — `store/i18n.js:8`, `webpackContext('@pkg/assets/translations', { recursive: true, regExp: /.*/ })` — and maps each match to its basename (`store/i18n.js:16`). Once `meta/de.yaml` exists, webpack bundles it and `state.available` gains a duplicate `de`; the tool-only metadata YAML ships in the renderer bundle and couples runtime locale discovery to tool state. Latent today: `meta/` does not yet exist and is not gitignored, so this manifests the first time `meta` runs before a build.

Fix: write metadata outside the translations tree (e.g. `assets/translation-meta/`), or narrow the glob to root-level locale files.

I2. **Node path model corrupts YAML keys containing literal dots** — `yaml.go:207` [Codex GPT 5.5]

```go
parts := strings.Split(dottedKey, ".")
```

`flattenNodeWithComments` joins nested keys with `.` (`yaml.go:66`); `nodeSetLeaf` and `nodeGetLeaf` split back on `.` (`yaml.go:207`, `yaml.go:292`). Locale files hold active leaf keys that themselves contain dots — `'kubernetes.io/dockercfg'` and `'bootstrap.kubernetes.io/token'` under `secret.types` (`en-us.yaml:3122`, `en-us.yaml:3127`). I reproduced the round-trip: writing the flattened key `secret.types.kubernetes.io/dockercfg` back through `nodeSetLeaf` builds `kubernetes:` → `io/dockercfg:` nested mappings instead of the original leaf, silently restructuring the file.

Latent: no command in this PR calls `nodeSetLeaf` (grep confirms only tests reach it), but `merge` and `remove` — later PRs — route every write through it.

Fix: carry `[]string` path segments internally, or use a quote-aware split/join matching the JS `get` semantics.

## Suggestions

S1. **"raw scalar text / source bytes" comment misstates a decoded comparison** — `compute.go:9` [Claude Opus 4.8]

`loadYAMLFlat` returns the YAML-*decoded* scalar, not raw bytes: `k: "Hello"` and `k: Hello` both yield `Hello`, and `k: "a\tb"` yields a real tab. Comparing decoded values is the right call — re-quoting English never falsely triggers drift — but the comment claims byte preservation, the opposite. The same wording predates this commit in `loadYAMLFlat`'s own doc (`yaml.go:16`).

Fix: state that both sides decode through the same YAML decoder, so drift compares decoded values; drop the "raw bytes" framing in both places.

S2. **`stripOverrideMarker` strips by substring while `commentHasOverride` matches exactly** — `yaml.go:276` [Claude Opus 4.8]

`commentHasOverride` (`yaml.go:87`) counts a line as a marker only when it equals `# @override` or starts with `# @override ` (the test pins `# @overridden` → false). `stripOverrideMarker` deletes any line *containing* `@override`, so a value update drops a translator note like `# @overridden spelling` — a comment this layer exists to preserve. Latent: only `nodeSetLeaf` reaches it.

Fix: strip with the same predicate `commentHasOverride` uses.

S3. **Redundant sort when building metadata entries** — `metadata.go:66` [Gemini 3.1 Pro, Claude Opus 4.8]

`entries` is a map, so the `sortedKeys(localeKeys)` iteration order is discarded, and `serializeMetadata` marshals via `yaml.Marshal`, which sorts keys itself (`TestMetadataDeterministic` confirms determinism). The sort over ~2,300 keys changes nothing in the output.

Fix: iterate `for key := range localeKeys`.

S4. **New `sourceLocale` const not used at the en-us call sites** — `metadata.go:86` [Claude Opus 4.8]

This commit adds `const sourceLocale = "en-us"` (`repo.go:17`) and uses it in `translationLocales`, yet `generateMetadata` and `regenerateMetadata` (`report_meta.go`) still hardcode `"en-us.yaml"`. The source locale now has two spellings in one commit.

Fix: use `translationsPath(root, sourceLocale+".yaml")` at these sites.

S5. **Per-line scan misses multi-line dynamic template literals** — `scan.go:242` [Gemini 3.1 Pro]

`extractDynamicPatterns` runs per line, and `dynamicKeyLiteral` needs both backticks on one line, so a template literal split across lines is missed and its keys then read as unused. Regular multi-line `t()` calls already match whole-file content (`scan.go:245`); dynamic literals do not. This lives in `scan.go` — base PR #10107 — and is low-impact, since multi-line dynamic literals are rare.

Fix: match `dynamicKeyLiteral` against the whole file, as `multilineKeyPattern` does.

S6. **Indirect-key regexes are stricter than the canonical `dottedKey`** — `scan.go:44` [Gemini 3.1 Pro]

`dottedKeyLiteral` (`scan.go:44`) and `indirectKeyPattern` (`scan.go:64`) require `[a-z][a-zA-Z0-9]*` segments — no underscore, lowercase-first — while the `dottedKey` const allows `[a-zA-Z0-9_-]`. Real keys break the stricter form: `onlyFromVentura_x64`, `RBAC_ROLE`, `storage_class_provisioner`. A key referenced only indirectly (a string value or ternary) is then missed and reported unused; direct `t()` calls use `dottedKey` and are unaffected. This lives in base PR #10107; commit `0dd432ac5` routed other patterns through `dottedKey` but left these two.

Fix: build both regexes from the `dottedKey` const.

## Design Observations

### Concerns

- **The path model should match runtime lookup semantics (in-scope)** [Codex GPT 5.5] — I2 shows the Go model and the JS runtime already disagree on object-path rules. Carrying `[]string` path segments internally and formatting only at report boundaries, or sharing one escaping convention with the JS `get`, removes a whole class of bugs around dots, slashes, and quoted keys.

### Strengths

- **Atomic metadata writes (in-scope)** [Claude Opus 4.8] — `writeFileAtomic` (`repo.go:70`) writes a temp file and renames it, cleaning up on every error branch, so an interrupted write cannot truncate the target.
- **Sound drift guard (in-scope)** [Claude Opus 4.8, Codex GPT 5.5] — `regenerateMetadata` blocks regeneration that would erase outstanding drift markers, while bootstrap and `--force` proceed. Every state traces correctly.
- **Drift compares decoded values (in-scope)** [Claude Opus 4.8] — routing both sides through the same YAML decoder makes drift robust to cosmetic English edits (re-quoting, block-vs-plain scalars). Good choice, though under-documented (S1).
- **Tests lead consumers (in-scope)** [Claude Opus 4.8, Codex GPT 5.5] — the node layer ships with its own tests ahead of `merge`/`remove`, keeping each PR in the stack reviewable.

## Review Process Notes

### Skill improvements

- When a PR is stacked on an unmerged base PR, the merge-base diff includes the base PR's commits, so the Changed Files list mixes files the top commit introduces with files inherited from below. Run `git show --stat <head>` to find which files the top commit actually changes, scope findings to those, and mark any finding in an inherited file as belonging to the base PR's review rather than raising it as net-new. Reviewers that cannot separate the two (for example, one that skips `git blame`) will concentrate their findings in inherited code and mislabel scope.

### Repo context updates

- [repo] The renderer discovers locales in `pkg/rancher-desktop/store/i18n.js` via a recursive `webpackContext('@pkg/assets/translations', { recursive: true, regExp: /.*/ })`, keying each match by filename basename. Any file added anywhere under `assets/translations/` — including a subdirectory — becomes a locale entry in `state.available` and ships in the renderer bundle. Flag any change that writes non-locale files (metadata, fixtures, generated artifacts) into that tree.
- [repo] Translation keys in `en-us.yaml` include leaf keys that contain literal dots and slashes — for example `kubernetes.io/dockercfg` and `bootstrap.kubernetes.io/token` under `secret.types`. Any code that flattens nested keys into dotted paths, or splits dotted paths back into segments, must be quote/dot-aware or it corrupts these keys. Verify key round-trips against these, not only simple `a.b.c` keys.

### Executive Summary

This PR introduces the translation data model, including a snapshot layer for English source text to detect drift and a `yaml.Node` layer to safely rewrite locale files while preserving comments. The most critical finding is a string-splitting bug using the literal letter `"n"` instead of `"\n"`, which breaks the parsing of `override` marker comments.

### Findings

#### Critical Issues

C1. **`strings.Split` splits by `"n"` instead of `"\n"`** — `src/go/i18n-report/yaml.go`

```go
func commentHasOverride(comment string) bool {
	for _, line := range strings.Split(comment, "n") {
		trimmed := strings.TrimSpace(line)
```

The `strings.Split` call in `commentHasOverride` and `stripOverrideMarker` splits the comment string using the literal letter `"n"` instead of the newline character `"\n"`. This corrupts comment text, drops the remainder of any string after the first "n", and causes valid override markers containing "n" (like `# @reason normal\n# @override`) to be silently ignored.

Fix: Change `"n"` to `"\n"` in both `commentHasOverride` and `stripOverrideMarker`.

```diff
-	for _, line := range strings.Split(comment, "n") {
+	for _, line := range strings.Split(comment, "\n") {
```
(critical, regression)

#### Important Issues

I1. **Global find-and-replace artifacts in docstrings and tests** — `src/go/i18n-report/yaml.go`

```go
// stripOverrideMarker removes @pkg/rancher-desktop/mixins/vue-select-overrides.js lines from a comment, keeping any
```

A global find-and-replace inadvertently replaced `@override` with `@pkg/rancher-desktop/mixins/vue-select-overrides.js` in the docstrings for `nodeHasOverride`, `validateOverridePlacement`, `checkOverridePlacement`, and `stripOverrideMarker`. The same find-and-replace mishap likely caused the `\n` to `n` replacement in `src/go/i18n-report/yaml_test.go`, resulting in the nonsensical test case `{"# @overriden# @reason something", true}`.

Fix: Revert `@pkg/rancher-desktop/mixins/vue-select-overrides.js` back to `@override` in all `yaml.go` docstrings, and fix the `yaml_test.go` test cases to correctly use `\n`.
(important, regression)

I2. **Dynamic template literal regex misses multiline strings** — `src/go/i18n-report/scan.go`

```go
	// Dynamic template literal patterns.
	result.dynamics = append(result.dynamics, extractDynamicPatterns(line, ref)...)
```

The `extractDynamicPatterns` call operates on individual lines from `strings.Split(content, "\n")`. Because `dynamicKeyLiteral` requires both the opening and closing backticks to be present in the target string, it silently misses multiline template literals (e.g., `` t(`prefix.${\nvar\n}`) ``). This causes false positives in the `unused` report and incomplete tracking in the `dynamic` report.

Fix: Match `dynamicKeyLiteral` against the full `content` rather than per-line, similar to how `multilineKeyPattern` is processed.
(important, gap)

I3. **Inconsistent key regexes drop valid keys containing underscores** — `src/go/i18n-report/scan.go`

```go
	dottedKeyLiteral = regexp.MustCompile(`['"]([a-z][a-zA-Z0-9]*(?:\.[a-z][a-zA-Z0-9]*)+)['"]`)
```

The canonical `dottedKey` constant permits underscores and uppercase characters (`[a-zA-Z0-9_]+`). However, `dottedKeyLiteral` and `indirectKeyPattern` strictly enforce lowercase-started alphanumeric segments (`[a-z][a-zA-Z0-9]*`). This discrepancy causes the scanner to silently miss indirect references and ternary properties for valid keys like `my_key.value`, resulting in false positives for `unused` keys.

Fix: Redefine `dottedKeyLiteral` and `indirectKeyPattern` using the `dottedKey` constant to ensure consistent key matching across all patterns.
(important, gap)

S1. **Redundant map key sorting** — `src/go/i18n-report/metadata.go`
