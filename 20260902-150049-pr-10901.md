## Suggestions

S1. **A failed `docker image inspect` re-imports an image that is present, with nothing in the log** — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:103` [Codex GPT 5.6 Sol]

```sh
    if [ "$(docker image inspect --format '{{.Descriptor.Digest}}' "$name" 2>/dev/null || true)" != "$digest" ]; then
```

`2>/dev/null || true` maps every inspect failure to the empty string, so the image joins `wanted`. If the failure clears before line 124, the script re-imports a tag already pointing at the same target, `ensureDanglingImage` fires, and the record is permanent.

The outcome is capped at merge-base behaviour for that one image, and a persistent failure produces the same record on every start, which the merge-base did anyway. The window is small. `cri-dockerd` declares `need docker` and k3s declares `need cri-dockerd`, so dockerd is up before `start_pre` runs, and the loop takes about 150 ms per start. What remains is the missing diagnostic. The run prints `loading 1 of 8` and looks correct.

```sh repro
# Synthetic OCI archive built from the real k3s v1.36.4 index.json (8 manifests),
# plus a stub docker: inspect returns the archive digest for every image except
# $ERR_IMAGE, which fails the way an unreachable daemon does. All 8 are present.
NAMES=names ERR_IMAGE=            CAPTURE=capA.tar PATH=$PWD/bin:$PATH sh docker-load-airgap-images fixture.tar
NAMES=names ERR_IMAGE=docker.io/rancher/mirrored-pause:3.10.2 \
                                 CAPTURE=capB.tar PATH=$PWD/bin:$PATH sh docker-load-airgap-images fixture.tar
tar -xOf capB.tar ./index.json | python3 -c 'import json,sys; print([m["annotations"]["io.containerd.image.name"] for m in json.load(sys.stdin)["manifests"]])'
```

```text repro-output
# A: no inspect fails
airgap images: all 8 already present, nothing to load     <- docker load never runs, capA.tar absent
# B: one inspect fails, that image is present
airgap images: loading 1 of 8
['docker.io/rancher/mirrored-pause:3.10.2']               <- the present tag is re-imported
```

Fix: send inspect's stderr to the k3s log instead of `/dev/null`. Codex proposed keying on Docker's `No such image` text and exiting 1 otherwise; an upstream rewording would then leave k3s unable to start.

S3. **The removal loop depends on exactly one airgap image having no container** — `bats/tests/k8s/airgap-image-load.bats:91-97` [Claude Opus 5]

```bash
    for image in "${lines[@]}"; do
        # Most of these images back a running pod, and those cannot be removed.
        if ctrctl rmi "$image" >/dev/null 2>&1; then
```

`$lines` is every image in the store, and `docker rmi` refuses any image a container references, running or stopped. On the live VM seven of the eight airgap images are referenced; only `mirrored-library-busybox` is free, so the test turns on one image that no k3s workload happens to use. A k3s release that deploys it, or drops it from the archive, makes the loop fall through to `fail`. The message names the fixture clearly, so the cost here is maintenance, not a broken test. Gemini 3.1 Pro flagged the same loop, claiming `docker rmi` refuses every airgap image without `--force`; the listing below refutes that.

```text repro-output

101b4afd7673 rancher/mirrored-library-busybox   # 1 of 8 unreferenced -> rmi succeeds without --force
```

Fix: restrict the candidates to the archive's own namespace, so a fixture change fails where it happens: `[[ ${image} == rancher/* ]] || continue`.

S4. **The probe matches `index.json` more strictly than the loader does** — `bats/tests/k8s/airgap-image-load.bats:28` [Claude Opus 5]

```bash
        printf "%s\n" "$members" | grep -c "^index.json$" || true
```

The loader delegates the match to `tar -xf - -C "$WORK" index.json` (line 32), which also accepts a `./index.json` member; the anchored literal here does not. An archive packed with `tar -cf - -C dir .` has the prefix, and the suite would then skip with a message claiming the archive has no index while the loader filters it happily. The k3s archives use bare names. v1.36.4 lists `blobs/`, `index.json`, `manifest.json` and `oci-layout`, so this is latent.

Fix: accept both spellings, `grep -c "^\(\./\)\?index\.json$"`.

S5. **"no index.json in the archive" is printed for every archive-read failure** — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:32-33` [Claude Opus 5]

```sh
decompress | tar -xf - -C "$WORK" index.json 2>/dev/null || true
[ -f "$WORK/index.json" ] || load_everything "no index.json in the archive, loading all images"
```

A missing `zstd`, a truncated archive, and a full filesystem all reach the same line as the intended "this is a docker-save archive", and all four log the same sentence into `k3s.log` before the run hits the same fault again inside `docker load`. Falling back is right; naming the cause wrongly is not, and it is the message a bug report will quote.

Fix: drop `2>/dev/null` so tar's own diagnosis reaches the log, or test tar's status separately and log `cannot read the archive` for it.

S6. **The skip message asserts the classic image store for any non-`overlayfs` driver** — `bats/tests/k8s/airgap-image-load.bats:13-16` [Claude Opus 5]

```bash
    run -0 --separate-stderr ctrctl info --format '{{.Driver}}'
    if [[ ${output} != "overlayfs" ]]; then
        skip "the classic image store (${output}) loads every image"
    fi
```

Under the containerd store `Driver` reports the snapshotter name, so `native` or `btrfs` would skip with a message asserting something false about the configuration. `settings.ts` exposes `mobyStorageDriver` as `'classic' | 'snapshotter' | 'auto'`, so the store is knowable without inferring it from the driver.

Fix: word the skip around what was observed, `skip "image store driver ${output} loads every image"`.

## Design Observations

### Concerns

- **The partial path is the only one nothing verifies automatically** `(in-scope)` [Claude Opus 5, Codex GPT 5.6 Sol]. Round 2 adds the test that covers it, and S2 is why it does not run by default. The awk program remains reachable only through a full VM start; a fixture-driven check (an `index.json`, a stub `docker` on `PATH`, and an assertion that the filtered output parses) runs in milliseconds and is what both the consolidator and two agents built by hand to review this PR.
- **Records from earlier sessions outlive the fix** `(future)` [Claude Opus 5, Codex GPT 5.6 Sol, Consolidator]. Raised in Round 1, and both agents raised it again, Claude at Important. The change stops creating records and removes none, so an upgrading user keeps the warnings for the images their pods inspect. Claude proposed `docker image rm "moby-dangling@$digest"`; that does not work. On the live VM `docker image inspect 'moby-dangling@sha256:d986…'` answers `No such image`, because the CLI normalises a bare name to `docker.io/library/…` and the record's literal name is not a valid reference. `docker images -a` and `--filter dangling=true` do not list them either. Any cleanup would have to go through containerd's `moby` namespace, which is a larger change than this PR. Release notes saying the fix is preventive would cost nothing.
- **The dangling warning is emitted on inspect, not on load** `(in-scope)` [Consolidator]. On the live VM all 60 warnings fall in a 50-second window right after the k3s start, none in the 14.5 hours since, and neither `docker images` nor `docker image inspect` produces one. So `assert_no_dangling_records` depends on a workload having inspected the affected image. It holds for the seven images pods use, which is where the regression would appear; a record on an image nothing runs would go unseen. Given that no CLI lists these records at all, asserting on the log is the only check available.

### Strengths

- **Every failure to understand the archive degrades to the merge-base behaviour** `(in-scope)` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]. Format probe, all-present, all-missing, partial: the consolidator ran all four against a synthetic archive built from the real index, and the two common cases behave as documented.
- **Coupling `assert_no_dangling_records` to `skip_unless_loader_can_filter` is the right contract** `(in-scope)` [Claude Opus 5]. On an archive the loader cannot filter, dangling records are expected, so a zero assertion would be false.
- **Counting matches is a stronger assertion than `refute_output`** `(in-scope)` [Claude Opus 5, Consolidator]. Verified both ways in the VM: `grep -c … || true` on a missing file exits 0 with empty stdout, so `assert_output '0'` fails; `rdctl shell sudo sh -c "exit 7"` collapses to `Error: exit status 7` on stderr and status 1.
- **The digest comparison is exact against a real store** `(in-scope)` [Consolidator]. All eight archive digests match `docker image inspect --format '{{.Descriptor.Digest}}'` on the running moby daemon, so a restart with everything present reaches `wanted == 0`.

## Review Process Notes

### Skill improvements

- When a finding's severity turns on a resource limit (memory, disk, a quota), measure it on the target platform before rating it. A path that "could exhaust" a filesystem is a Suggestion or nothing when the filesystem has two orders of magnitude of headroom, and the measurement is usually one command. State the measured figure in the finding so the next round inherits a number.
- When a finding proposes matching a third-party tool's human-readable error text to classify a failure, weigh the new failure mode against the old one. Text matching turns a rare silent degradation into a hard failure the day upstream rewords the message, and in start-up paths that trades a cosmetic defect for an unbootable service.

### Repo context updates

- [repo] Both guest images are built from Alpine 3.24.1 and ship busybox 1.37.0, whose `ash` supports `set -o pipefail`; `pkg/rancher-desktop/assets/scripts/install-k3s` and `install-containerd-shims` are `#!/bin/sh` scripts that already rely on it in production. Both guests also install GNU tar and zstd as apk packages (the WSL distro's `build.sh` adds them explicitly), so a guest script may use GNU tar behaviour such as reading a `.tar.zst` directly. Nothing under `pkg/rancher-desktop/assets/scripts/` is shellchecked by CI, so SC3040 on `pipefail` is not a lint break.
- [repo] The docker CLI cannot see the `moby-dangling@<digest>` records. `docker images -a`, `docker images --filter dangling=true`, and `docker image inspect 'moby-dangling@sha256:…'` all fail to show or resolve them, because the CLI normalises a bare name to `docker.io/library/…`. Any finding that proposes removing one through the docker CLI is wrong; the only observable trace is dockerd's "still dangling" warning, which is emitted when a workload inspects the image, not when it is loaded.
- [repo] `bats/tests/helpers/commands.bash` defines `rdctl()` to pipe through `no_cr` on Windows only, so on Windows the function returns `tr`'s status and `run -0` asserts nothing about the remote command. A bats assertion that must fail on a remote error needs to check the output on Windows, not the status.
- [repo] `.github/workflows/bats.yaml` is `workflow_dispatch` only and defaults `KUBERNETES_VERSION` to 1.22.7, which `get-tests.py` assigns to every moby matrix entry; `bats/tests/helpers/defaults.bash` defaults local runs to 1.32.7. k3s airgap archives switched from the docker-save layout to the OCI layout across maintained branches in one release train, so v1.22.7+k3s1 has `<id>/layer.tar` and v1.32.7+k3s1 has `blobs/` and `index.json`. A test that depends on the archive format gets no coverage from a default dispatch.

### Important Issues

**I1. The partial-load path materialises the whole archive under `mktemp -d`, and a failure there now aborts k3s `start_pre`** — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:120-124` *(important, regression)*

```sh
mkdir -p "$WORK/archive"
decompress | tar -xf - -C "$WORK/archive"
awk -v mode=filter -f "$WORK/index.awk" "$WORK/wanted" "$WORK/archive/index.json" >"$WORK/index.filtered"
mv "$WORK/index.filtered" "$WORK/archive/index.json"
tar -cf - -C "$WORK/archive" . | docker load
```

At the merge-base, `service-k3s.initd:46` streamed the archive straight into `docker load` with no temporary copy. The partial path now writes an uncompressed copy of the entire airgap archive into `$WORK` (line 13, `mktemp -d`, i.e. `/tmp`), then repacks it. Under `set -o errexit` (line 10) a failed extraction aborts the script, `start_pre` returns non-zero, and k3s does not start — a strictly worse outcome than the load failure the merge-base produced.

The condition that selects this path is often the condition that makes it fail: kubelet's image GC evicts unused images under disk pressure, leaving `0 < wanted < total` on a host already short of space.

## Design Observations

### Concerns

**Filtering and repacking the archive may be more machinery than the goal needs** *(in-scope)*

The script currently carries a hand-rolled JSON splitter (`split_manifests`/`restore`, lines 51-64), a two-mode awk program, a full extract, and a repack — all to avoid one re-tag per already-present image. Its own comment at lines 116-118 concedes that "Docker ingests every blob either way", so the filtering buys no I/O; it buys only the absence of the dangling record.

An alternative keeps the valuable fast path and drops the rest: parse `index.json` in `list` mode only, exit early when every image is present (the common case and the 0.29s win the PR reports), and otherwise `docker load` the archive whole and then remove the `moby-dangling@<digest>` records for the digests that were already present. That deletes `split_manifests`, `restore`, `filter` mode, the `mkdir`/extract/`mv`/repack block, the temp-space exposure in I1, and — as a side effect — closes I3 for existing installs. It also removes the awk fragility the author deliberately deferred in Round 1, since `list` mode never has to reconstruct valid JSON. It rests on the same unverified premise as I3's fix (that the dangling ref is removable), so it is worth one probe before committing to it.

### Strengths

- Layering the guard as *format probe → all-present → all-missing → partial* means every failure to understand the archive degrades to the merge-base behaviour rather than to a broken load. I confirmed all four paths against a synthetic archive.
- Making `assert_no_dangling_records` call `skip_unless_loader_can_filter` is the right coupling: on an archive the loader cannot filter, dangling records are expected, so asserting zero would be wrong rather than merely unverified.
- Counting grep matches instead of asserting on empty output (lines 46-49) is a genuinely better assertion than the `refute_output` it replaced, for the reason the comment gives.

### Executive Summary

PR #10901 successfully implements a fast path to skip loading pre-existing airgap images, resolving annoying dangling-image warnings. However, the newly introduced BATS test suite has two major robustness regressions that will cause false-positive test failures when the log files or airgap archives are missing. Furthermore, the decompression script extracts the entire archive into `/tmp` (which mounts to RAM-backed `tmpfs` in Alpine Linux), introducing a risk of RAM exhaustion.

---

### Findings

#### Critical Issues

None.

#### Important Issues

##### I1. Test fails if `/var/log/docker.log` is absent on non-Windows hosts — `bats/tests/k8s/airgap-image-load.bats:48-49` (important, regression)

```bash
        run -0 --separate-stderr rdsudo sh -c "grep -c 'still dangling' /var/log/docker.log || true"
        assert_output '0'
```

If `/var/log/docker.log` does not exist (e.g., prior to any `dockerd` output or after log rotation), `grep -c` fails, printing an error to stderr and producing an empty stdout. The `|| true` coaxes the subshell's exit status to `0`, but the empty stdout causes the subsequent `assert_output '0'` assertion to fail.

Fix: Handle the missing file gracefully by ensuring that `0` is always printed:

```diff
-        run -0 --separate-stderr rdsudo sh -c "grep -c 'still dangling' /var/log/docker.log || true"
+        run -0 --separate-stderr rdsudo sh -c "[ -f /var/log/docker.log ] && grep -c 'still dangling' /var/log/docker.log || echo 0"
```

##### I2. Test crashes instead of skipping if no airgap archive is found — `bats/tests/k8s/airgap-image-load.bats:21-31` (important, regression)

```bash
        for archive in /var/lib/rancher/k3s/agent/images/k3s-airgap-images-*.tar.zst \
            /var/lib/rancher/k3s/agent/images/k3s-airgap-images-*.tar; do
            if [ -f "$archive" ]; then break; fi
        done
        members=$(tar -tf "$archive")
```

If no archive matches the glob (e.g., under a different Kubernetes version or configuration), `archive` retains the literal glob string. The `tar -tf` command then fails. Because `set -o errexit` is set in the probe, the subshell exits with a non-zero status. The wrapping `run -0` then fails, causing the test suite to crash instead of skipping gracefully.

Fix: Check that the file actually exists before running `tar`:

```diff
     local probe='
         set -o errexit
+        found=""
         for archive in /var/lib/rancher/k3s/agent/images/k3s-airgap-images-*.tar.zst \
             /var/lib/rancher/k3s/agent/images/k3s-airgap-images-*.tar; do
-            if [ -f "$archive" ]; then break; fi
+            if [ -f "$archive" ]; then
+                found="$archive"
+                break
+            fi
         done
-        members=$(tar -tf "$archive")
+        if [ -z "$found" ]; then
+            echo "0"
+            exit 0
+        fi
+        members=$(tar -tf "$found")
         printf "%s\n" "$members" | grep -c "^index.json$" || true
     '
```

##### I3. Full archive extraction in `/tmp` risks RAM/tmpfs exhaustion — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:121` (important, gap)

```sh
decompress | tar -xf - -C "$WORK/archive"
```

The script extracts the entire decompressed airgap images tarball (often >1 GB in uncompressed size) into `$WORK/archive`. Since `$WORK` is created by a bare `mktemp -d`, it resides in `/tmp`. In Alpine Linux (the guest VM), `/tmp` is mounted on a `tmpfs` (RAM-backed), limited to half of the guest's physical memory. Extracting a massive image archive on `tmpfs` can easily cause ENOSPC ("No space left on device") or exhaust guest memory.

Fix: Use `/var/tmp` for the temporary directory instead, which resides on the VM's persistent, disk-backed filesystem:

```diff
-WORK="$(mktemp -d)"
+WORK="$(mktemp -d -p /var/tmp)"
```

#### Suggestions

##### S1. Missing argument check triggers `nounset` crash — `pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:12` (suggestion, enhancement)

```sh
set -o errexit -o nounset -o pipefail

TARBALL="$1"
```

If the script is executed manually or as part of other scripting without arguments, the reference to `$1` triggers a `nounset` (unbound variable) error under `set -o nounset` on line 10, causing the shell to terminate immediately without a helpful diagnostic.

Fix: Use a safe default expansion and check for missing arguments explicitly:

```diff
-TARBALL="$1"
+TARBALL="${1:-}"
+if [ -z "$TARBALL" ]; then
+    echo "Error: Missing path to k3s airgap images archive" >&2
+    exit 1
+fi
```

### Design Observations

#### Concerns

- **Heuristic JSON parsing (in-scope)**: The awk fast-path parser relies on string splits and regex matches on an unstructured representation of `index.json`. If an OCI index contains key-reordering or spaces (which are standard and valid in JSON), the script could fail to extract all image digests, resulting in some images being silently skipped from the load process. This is currently mediated by the `total == 0` fallback to `load_everything`, but a partial match of some keys might skip others without trigger. Hardening this parser to validate structural integrity (e.g. key-counts match) would protect against silent image load gaps.

#### Strengths

- **Clever re-tagging prevention**: Minimizing the payload written to `docker load` via filtered `index.json` manifests is a brilliant way to prevent `moby` from generating redundant dangling image records while avoiding complex client-side cleanup pipelines.

### Testing Assessment

#### Untested Scenarios

1. **Host-level file absent check**: No unit or integration test checks what happens if the WSL Host log folder does not contain `docker.log` on Windows (addressed in **I1**).
2. **Missing airgap archive check**: The suite does not assert behavior when there are no k3s airgap files inside `/var/lib/rancher/k3s/agent/images/` (addressed in **I2**).

---

### Acknowledged Limitations

- **Heuristic `index.json` Parsing**: The parser relies on strict formatting rules of the JSON (e.g. `mediaType` positioning) that are not guaranteed by the JSON specification (`pkg/rancher-desktop/assets/scripts/docker-load-airgap-images:53-58`). The author declined adding a complex validator, as no producer in use emits non-matching layouts, and parser hardening is deferred.
- **Classic Store Fallback Assertion**: Behavior of the classic-store `.Descriptor.Digest` fallback is asserted by comments rather than active tests because setting it up requires a dedicated test environment with a classic store configuration.
- **BATS Format Skip Comment**: The BATS test comment does not specify the archive-format precondition since the helper's own skip message already clearly reports it.
